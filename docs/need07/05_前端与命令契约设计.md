# 05 前端与命令契约设计

## 1. 命令清单（`lib.rs generate_handler!` 增量）

| 命令 | 参数（camelCase） | 返回 | 说明 |
|---|---|---|---|
| `db_reveal_in_explorer`（改签名） | `{ path: string }` + `AppHandle` | `()` | 重写见 `03`-§3；前端调用不变 |
| `iq_open_output_dir`（新增） | `{}` | `string`（解析后的绝对目录，展示用） | 空配置走新/老默认决策 + 保活 + 打开 |
| `iq_get_resolved_output_dir`（新增） | `{}` | `string` | 只解析不打开，供设置页 placeholder/验收 |
| `path_get_bases`（新增，探针） | `{}` | `{ exeDir, exeData, activeData, docDir: string\|null, base: 'exe'\|'appdata', writable: boolean }` | 调试+验收；字段一律 camelCase（pitfalls/01） |
| `path_migrate_status`（新增，探针） | `{}` | `{ version: string, washed: number, deduped: number }` | 可选；读 `app_settings` 版本键 |

- Rust DTO 一律 `#[serde(rename_all="camelCase")]`（沿用 `queue.rs:107` 惯例）。
- `db_reveal_in_explorer` 加 `AppHandle` 后，前端 `invoke('db_reveal_in_explorer', { path })` 不变（Tauri 不序列化 AppHandle）。

- `DbManagerDrawer.vue:97,108`、删除确认 `row.path`（§42）、`LibraryDialog` 落盘回显：展示层统一过 `displayPath`（后端已洗，前端再兜底一次，防旧缓存）。

## 3. 三视图改造

**`ImageQueuePanel.vue:45 onOpenOutput`（根治异常2）：**

```ts
async function onOpenOutput() {
  if (!iq.config.outputDir.trim()) {
    const dir = await invoke<string>('iq_open_output_dir')  // 后端解析+保活+打开
    push(`已打开 ${dir}`, 'success', 1500)  //dir 已经是 display 形态
  } else {
    await dbRevealInExplorer(iq.config.outputDir.trim())
  }
}
// 删除 '<data_dir>/output/images' 占位符；设置页 placeholder 改调 iq_get_resolved_output_dir
```

**`ImageQueueSettings.vue`：** 输出目录输入框 placeholder 显示 `resolved || 'Documents/Prompt Modular Factory/images'`；若老默认保留，hint 显示"旧默认位置（已保留）：<display>"（调 `iq_get_resolved_output_dir` 判断）。

**`DbManagerDrawer.vue` + `LibraryDialog.vue`：** 路径展示过 `displayPath`；`handleRepair` 的 `window.prompt` 输入校验：空/`<>`占位符直接拒绝并提示；`onOpenDir` 失败才回退 `plugin-opener openPath`（现状已有，保持）。

## 4. 缓存兼容

- `localStorage` 中旧 `outputDir/displayPath` 若含 `\\?\` 或 `<data_dir>`：`viewToConfig`/`toLocalCache`（`imageQueueApi.ts:84,119`）加载时过一次 `stripVerbatim` + 占位符清洗（`startsWith('<')` → 置空）。
- `dbRegistry` store 不缓存 path 比较结果，每次以 `fetchActiveInfo` 为准。
