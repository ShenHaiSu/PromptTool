# 04 注册表与存量数据迁移设计（无感核心）

## 1. 范围：只洗字符串，不搬文件

- 对象：`Default.db` 中 `db_registry.path` 全行 + `app_settings(foreground_path)`。
- 不碰：业务 `.db` 文件本体、`output/images` 图片、`image_queue.json`（`outputDir` 绝对值只洗前缀；`""` 保持空，走新默认决策）。
- 版本键：`app_settings('path_schema_version') = '2'`（无键视为 v1，需迁移；v2 跳过，幂等）。

## 2. 迁移算法（`migrate_path_schema_v2(default_db)`，启动时一次）

```
1. 备份：copy Default.db → Default.db.bak-<unix_ts>（失败则中止迁移、原库照常启动）
2. 读全量：SELECT id, path FROM db_registry；SELECT v FROM app_settings WHERE k='foreground_path'
3. 逐行 wash(p) = strip_verbatim(canonical_stripped_if_exists_else_lexical(p))
   - wash 后盘符大写；norm_key 用于判重
4. 去重（关键：\\?\ 与普通路径是同一文件）：
   - 按 norm_key 分组；每组保留 last_opened_at 最大者（无则保留 id 最小者）
   - 被合并行的 dim/module/favorite 计数取最大者 refresh； últim 删除多余行（DELETE）
   - 更新保留行 path = wash 值
5. foreground_path：wash；若 wash 后无对应 registry 行且文件存在 → 自动补注册（alias = 文件 stem，去重后缀 -1）；若文件不存在 → 置 status='missing'，不清空（保留用户手动补路径机会）
6. refresh_missing_status() 重算 available/missing；写 path_schema_version='2'
7. 打日志：[pmf] path-migrate v1→v2 washed=N deduped=M fg=<display>
```

- 全程单事务（`BEGIN IMMEDIATE`），任一步失败 `ROLLBACK` + 用 `.bak` 恢复提示。
- 可重入：已 v2 直接返回 `Ok(0,0)`。

## 3. 读写双防（迁移后不再脏）

- 写：`db_create_business/db_switch_active/db_repair_path` 入口统一过 `canonical_stripped`（脱壳），入库前用 `norm_key` 预查 `SELECT id FROM db_registry WHERE ...`（NOCASE 不足以判 `\\?\`，必须应用层查）。
- 读：`db_get_active_info/db_list_registry` 返回前对 `path` 再 `strip_verbatim` 一次（防手工改库/旧备份恢复带前缀）。
- `wasForeground` 比较（`business.rs:651`）改 `norm_key(a)==norm_key(b)`。

## 4. 回滚

- 自动回滚：迁移异常 → 删除新写、保留 `.bak`，启动沿用旧库 + `eprintln` 明示 bak 路径。
- 手工回滚：关闭程序 → 删 `Default.db` → 重命名最近 `.bak-<ts>` 回 `Default.db` → 重启。
- 回滚演练为 P1 必测项（见 `06`）。

## 5. 与 02 的衔接

- 老默认输出有文件 → 不搬：`resolve_image_dir("")` 判断 `legacy_has_files = data/output/images 非空`，此时即使 v2 也返回老默认（`04` 不删老目录）。
- `Program Files` 回退到 `appdata` 的新用户：`Default.db` 在新位置新建，旧 `exe/data/Default.db` 若存在且新位置无 → 走既有 `migrate_legacy_db`（backup API）整库搬一次（文件级），再跑本 §2 的字符串洗。
