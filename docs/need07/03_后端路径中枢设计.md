## 3. `reveal` 重写（根治异常2 + 隐患B/C）

```rust
#[tauri::command]
pub fn db_reveal_in_explorer(app: AppHandle, path: String) -> Result<(), String> {
  let input = path.trim();
  if (input.is_empty()) { return Err("路径不能为空".into()) }
  // 1. 占位符拦截："<data_dir>" / "<...>" 一律视为"未解析"，转 resolve（而不是直接 explorer）
  // 2. strip_verbatim → 若相对则拼 active data_dir
  // 3. ensure_dir 保活（目录不存在则创建；是文件则保活其 parent）
  // 4. Windows：文件 → .arg("/select,").arg(file)（两个参数！）；
  //             目录 → .arg(dir)；spawn 前打 display_path 日志
  // 5. spawn 失败 → 回退 tauri_plugin_opener::open_path（需 AppHandle，这就是签名加 app 的原因）
}
#[tauri::command]
pub fn iq_open_output_dir(app: AppHandle) -> Result<String, String> {
  let dir = resolve_image_dir(app, "")?;   // 空 = 走新/老默认决策
  ensure_dir(&dir)?; reveal(&app, &dir)?; Ok(display_path(&dir))
}
#[tauri::command]
pub fn iq_get_resolved_output_dir(app: AppHandle) -> Result<String, String>
```

- `db_reveal_in_explorer` 签名加 `app: AppHandle`（前端调用不变，`invoke` 按 camelCase 传 `path` 即可；见 pitfalls/01）。
- macOS/Linux 分支保持 `open/xdg-open`，但同样先 `ensure`。
- 相对路径/占位符**永远不再透传给 explorer**（Code Review 必查）。

## 4. 日志规范

- 所有路径日志用 `display_path`（无 `\\?\`）；`resolve_data_dir` 在 setup 打一行：
  `[pmf] data_dir active=<...> base=exe|appdata writable=true`。
- `GetDiskFreeSpaceExW` 失败沿用"放行+日志"，但日志带脱壳路径。
