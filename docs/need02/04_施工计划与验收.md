## 3. 手工验收步骤

| 步骤 | 操作 | 期望 |
|------|------|------|
| 3.1 | 打开 `📚 词库`，观察导出区 | 显示"输出文件夹"只读框（默认 `…/data/output`）与"选择文件夹"按钮 |
| 3.2 | 不选目录，直接点"导出词库 JSON" | Toast `已导出至 …/data/output/pm…json`，文件存在于 `exe/data/output/`，内容为合法 `pmf-library` JSON |
| 3.3 | 点"选择文件夹"，选一个可写目录（如 `D:\tmp\pmf-out`），再点导出 | 落盘至自选目录，文件名 `pmf-library-YYYYMMDD-HHmmss.json`，结果区显示完整路径与"打开文件夹" |
| 3.4 | 关闭重开词库弹窗 | 輸出文件夾記憶為 `D:\tmp\pmf-out`（`localStorage` 生效） |
| 3.5 | 点"打开文件夹" | 系统文件管理器打开至落盘目录（或选中文件） |
| 3.6 | 在目录选择器中点"取消" | 目录保持不变，无 Toast |
| 3.7 | 故意选一个不可写目录（如 `C:\Windows\System32` 的子目录，或通过后端 mock 返回不可写错误） | Toast `error` 提示目录不可写，并自动通过浏览器下载完成导出（`warning` Toast 说明已降级） |
| 3.8 | 同秒内连续点两次导出 | 生成两个文件（秒级相同则后者带 `-1` 后缀），无覆盖 |
| 3.9 | 切换深色模式 | 输入框、提示文案、结果区可辨，无文字不可见 |

## 5. 风险与回退

| 风险 | 缓解 |
|------|------|
| exe 所在目录不可写导致默认 `data/output` 创建失败 | 捕获 `create_dir_all / atomic_write` 错误，Toast + Blob 降级，引导用户自选可写目录 |
| Dialog 插件权限缺失导致 `open()` 被拒 | `capabilities` 显式加 `dialog:allow-open`；前端对 `open` 的异常 `try/catch` 并 Toast 提示 |
| 长路径/特殊字符目录 | 依赖 OS 报错透出，前端不预校验；路径展示用 `truncate + title` |
| 旧版本前端调用新命令（命令不存在） | `invoke` 抛错，前端捕获后回落 Blob 下载，不阻断导出 |

**回退：** 本需求仅新增插件、2–3 个命令与弹窗内的目录选择/落盘分支；`capabilities` 与 `invoke_handler` 的新增项可单独注释隐藏，回退后导出自动走 Blob 下载，不影响存量导入/拼装/建库链路。
