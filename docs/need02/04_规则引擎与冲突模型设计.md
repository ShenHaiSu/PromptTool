# 04 — 规则引擎与冲突模型设计

> 本文档定五类规则的精确语义、求值算法、自动修复策略与 legacy 迁移表。`src/engine/*` 必须为纯函数（禁 `invoke`、禁 `localStorage`）。

---

## 1. 输入输出

```ts
// src/engine/ruleTypes.ts
export interface EngineRule extends Rule {
  /** 内存补齐：关键词模式（仅三条转正种子规则有值，见 §6） */
  sourceKeyword?: string | null
  targetKeywords?: string[]
  /** limit 专属：同维度段数上限，默认 1（单选维）/ 2（多选维），可配 */
  limitCount?: number
  /** isolated 专属：命中源时需清空的目标维度键列表 */
  isolatedTargets?: string[]
}

export interface EvaluateInput {
  segments: IRSegment[]
  rules: EngineRule[]
  /** 锁定下标集合：用户在编辑器/画布锁定的段，自动修复永不移除 */
  lockedIndexes?: Set<number>
  /** 维度排序映射（DB sort_order 优先，缺省走 legacy DIM_ORDER） */
  dimOrderMap?: Record<string, number>
}

export function evaluateRules(input: EvaluateInput): Finding[]
export function buildAutoFixPreview(segments: IRSegment[], finding: Finding): IRSegment[]
export function summarizeFindings(findings: Finding[]): { errors: number; warnings: number; fixable: number }
```

- 求值**不删段、不排序**，只产出 `findings`；删段由调用方经 `fix` 显式应用（决策 K4）。
- `lockedIndexes` 由调用方传入（画布 `SelectedItem.locked` / 编辑器段锁），引擎内只读。

---

## 2. 命中判定（三档，优先级从高到低）

对每条 rule，按以下三档之一判定“源命中集合 S / 目标命中集合 T”（下标数组）：

### 2.1 条目级（最优先）

`sourceModuleId（或 targetModuleId）非空` → `seg.sourceModuleId === 该值` 即命中。用于新规则（如“某顶帽子与某头盔互斥”）。

### 2.2 维度级

`sourceDimensionId 非空 且 sourceModuleId 为空` → `seg.dimensionKey === 维度 key` 即命中（需经 `dimensionId → key` 映射，调用方传入 `dimIdToKey: Record<string,string>`；快照段只有 `dimensionKey`，故引擎内部以 `dimensionKey` 比对，映射由 `evaluateRules` 调用前在 `ruleEngine` 内完成——`EngineRule` 额外携带 `sourceDimKey/targetDimKey` 派生字段）。

### 2.3 关键词级（兼容 R02/R03，转正专用）

`sourceKeyword / targetKeywords 非空` → `seg.text.toLowerCase().includes(kw)` 即命中。仅三条种子规则使用，新建规则 UI 默认不暴露关键词输入（高级折叠项可选）。

## 3. 五类语义与修复策略

### 3.1 `mutex`（互斥，二存一）

- 触发：`S 非空 且 T 非空`。
- `message` 模板渲染：`{source}`=源维度中文名或条目名，`{target}` 同理。
- 自动修复：默认保留 S、移除 T 中**未锁定**项；若 T 全锁定而 S 有未锁定，则反向保留 T、移除 S 未锁定项；若两侧全锁定 → `fix: null`（只能手动解锁后处理），`message` 追加“（双方均已锁定，请先解锁）”。
- 对应 legacy R01：`source=维度 outfit`，`target=维度 top/bottom`（一条规则表达“目标维度组”：`targetDimensionId` 存 `top`，`targetKeywords` 扩展或第二条规则覆盖 `bottom`——见 §6 迁移表采用**两条规则**表达 R01，保证单规则单目标、可独立开关）。

### 3.2 `requires`（依赖：有源必须有目标）

- 触发：`S 非空 且 T 为空`。
- 无一键修复（`fix: null`），`message` 为“已选{source}，建议补选{target}”，`severity: warning`。
- 首版无 `requires` 种子规则，引擎先实现语义 + 单测，用户可新建（如“pose 要求 background”这类工作流约束）。

### 3.3 `excludes`（排除：源排除目标关键词组）

- 触发：`S 非空 且 T（关键词组任一命中）非空`。语义同 `mutex`，区别在于目标侧天然是“一对多关键词”（R03 的 `beach/sunset/street/rooftop`）。
- 自动修复同 `mutex`（保留源关键词侧，即保留 `studio`，移除户外侧未锁定项）。
- 对应 legacy R03。

### 3.4 `limit`（同维度上限）

- 触发：某维度段数 `> limitCount`（默认单选维 1、多选维 2，规则可配）。
- 无一键修复（`fix: null`），`message` 为“{维度}最多选 N 项，当前 M 项，请删减”，`involvedIndexes` 为该维度全部段下标。
- 首版以后端不校验、前端提示实现；随机引擎采样数已天然收敛（`0..min(2,len)`），此规则主要约束**手动多选**场景。

### 3.5 `isolated`（独占）

- 触发：`S 非空 且除 S 外还有其他段`（或 `isolatedTargets` 指定维度有段）。
- 自动修复：移除非 S 侧未锁定项；若有锁定外段 → `fix: null` + 追加解锁提示。
- `severity: error`（唯一 error 级，编辑器内红色强调 + 应用前二次确认）。
- 首版无种子规则，预留（如“某特殊风格独占”）。

---

## 4. 锁定与优先级铁律

1. 自动修复**永不移除锁定段**（`lockedIndexes` 内的下标）。
2. 两侧均有未锁定项时，默认保留**源侧**（`mutex/excludes`），理由：源为规则书写者认定的主项（如 outfit 优先于 top）。
3. `fix.removeIndexes` 必须按**降序**排列（调用方 `splice` 删段时从后往前，避免下标漂移）。
4. `fix.keepIndexes` 仅用于展示，不参与应用。

---

## 5. 排序与随机引擎的衔接

- `assemble` 内部继续调用求值：`assemble(selected, config, rules?)` 新增可选第三参；若传入 `rules` 则用 `ruleEngine.evaluateRules`（段快照 + 锁定集合由 `SelectedItem.locked` 映射），否则回退 legacy `applyRules`（保证老调用方不破）。
- `random.ts` 的 `filterPoolByAnchor`（H5）标记 `@deprecated`，保留函数体但不再新增关键词；新关键词约束一律走规则表。`partialRandomAssembly` 的 `forbiddenDims`（outfit↔top/bottom）保留（属于采样剪枝非语义冲突，性能考量）。
- 排序：`sortByOrder` 新增可选 `dimOrderMap`（见 03 §5），`assemble` 优先透传 DB `sort_order` 映射。

## 6. Legacy 迁移表（R01/R02/R03 转正为种子数据）

`migration.rs` `seed_rules_if_empty` 只在空表时执行，已有 3 条种子的库**不受影响**；新装库按以下五条写入（R01 拆二）：

| id | name | type | source | target | message |
|----|------|------|--------|--------|---------|
| `rule_01a` | 套装互斥·上装 | `mutex` | 维度 `outfit` | 维度 `top` | `已选全身套装，上装将自动忽略` |
| `rule_01b` | 套装互斥·下装 | `mutex` | 维度 `outfit` | 维度 `bottom` | `已选全身套装，下装将自动忽略` |
| `rule_02` | 鞋袜与赤脚互斥 | `mutex` | 关键词 `barefoot`（维度 `shoes` 内） | 维度 `shoes` 非 barefoot | `赤脚与鞋袜不可共存`（+ 引擎按锁定侧文案细化） |
| `rule_03` | 室内外背景互斥 | `excludes` | 关键词 `studio`（维度 `background` 内） | 关键词组 `beach/sunset/street/rooftop` | `室内背景与户外背景冲突，已保留棚拍` |
| — | （兼容）旧 `rule_01/02/03` | — | — | — | 老库保留，前端 `ruleEngine` 对旧 id 做同名语义兼容（`LEGACY_RULE_ALIAS` 映射到新求值路径），`rules.ts` 转调保证行为一致 |

`rules.ts` 转调方案：

```ts
// src/engine/rules.ts（改后）
/** @deprecated 用 ruleEngine.evaluateRules 替代；保留以兼容既有单测与调用方 */
export function applyRules(selected: SelectedItem[]): [SelectedItem[], string[]] {
  const segments = selected.map(toSegmentSnapshot)
  const findings = evaluateRules({ segments, rules: LEGACY_DEFAULT_RULES, lockedIndexes: lockedSet(selected) })
  return [applyFixesToSelected(selected, findings), findings.map(f => f.message)]
}
```

`LEGACY_DEFAULT_RULES` 为上述五条的内存常量（与种子数据同语义），保证无后端时单测仍过。

## 7. 复杂度与性能

- 求值复杂度 `O(R×S)`（R=启用规则数，S=段数），R 常 < 50、S 常 < 20，直接双循环，无需索引。
- 编辑器内每次击键不求值：`text` 输入用 300ms debounce 后重算；权重 stepper / 删段 / 排序即时重算（S 小，无压力）。
- 批量生成后 findings 计算为同步调用（同上量级），不得 `await`，不得阻塞虚拟列表渲染（见 06 §5）。
