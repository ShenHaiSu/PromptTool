# Need02 · 技术方案与接口契约 — 词库导出落盘与文件夹自选

> **路径：** `docs/need02/03_技术方案与接口契约.md`
> **版本：** v1.0 — 2026-08-29
> **前置：** `01_诊断与缺口分析.md` · `02_功能设计.md`
> **分支：** `tauri`

---

## 1. 总体选型

- **落盘仍走 Rust 原子写：** 复用 `src-tauri/src/commands/db.rs: atomic_write`（临时文件 + `rename`），避免前端 `fs` 直写带来的半截文件风险；与现有 `db_export_library(path)` 同链路。
- **目录选择走 Tauri Dialog 插件：** 新增 `tauri-plugin-dialog`，前端通过 `open({ directory: true })` 拉起 **Windows 原生文件夹选择器**，返回绝对目录字符串（`string | null`，`null` 表示取消）。
- **默认目录由 Rust 计算：** `migration::data_dir_for(app).join("output")`，与 `Default.db / PromptDataBase.db` 的选址同源，首次落盘前 `create_dir_all` 幂等创建。
- **"打开文件夹"走 Opener 插件：** 复用已有的 `tauri-plugin-opener`，前端 `openPath(dir)` 或 Rust 侧 `opener::open_path` 调起系统文件管理器。
- **invoke 键名：** 严格 **camelCase**（`dir/path/filename`），遵循 `docs/pitfalls/01-invoke-arg-case.md`。

## 3. 前端 — `src/lib/db.ts` 新增封装

```ts
// src/lib/db.ts 新增段

/** 默认导出目录（exe/data/output 的绝对路径，由 Rust 计算） */
export async function dbGetDefaultExportDir(): Promise<string> {
  return invoke<string>('db_get_default_export_dir')
}

export type ExportToDirResult = {
  /** 落盘后的绝对文件路径，如 E:\...\data\output\pmf-library-20260829-153022.json */
  path: string
  /** 同步返回的 JSON 文本（与落盘内容一致，便于降级或预览） */
  json: string
  /** 文件名（不含目录） */
  filename: string
}

/**
 * 将当前词库导出并落盘到指定目录（目录不存在则自动创建）。
 * 文件名由后端按 pmf-library-YYYYMMDD-HHmmss.json 模板生成，遇同名自动加后缀。
 */
export async function dbExportLibraryToDir(dir: string): Promise<ExportToDirResult> {
  return invoke<ExportToDirResult>('db_export_library_to_dir', { dir })
}

/** 在系统文件管理器中打开/选中路径（文件夹或文件均可） */
export async function dbRevealInExplorer(path: string): Promise<void> {
  await invoke('db_reveal_in_explorer', { path })
}
```

**既有兼容：** `dbExportLibrary(path?: string)` 保留不变，作为 Blob 降级的兜底与存量用例的回归锚点。

**目录选择（前端直调插件，不经 Rust）：**

```ts
import { open } from '@tauri-apps/plugin-dialog'

async function pickDir(): Promise<string | null> {
  const dir = await open({
    directory: true,
    multiple: false,
    title: '选择导出文件夹',
  })
  // Tauri dialog: string | string[] | null；directory:true 时为 string | null
  return typeof dir === 'string' ? dir : null
}
```

**"打开文件夹"（二选一）：**

- 方案 A（推荐，前端直调）：`import { openPath } from '@tauri-apps/plugin-opener'; await openPath(dirOrFile)`
- 方案 B（经 Rust）：`await dbRevealInExplorer(dirOrFile)`（内部 `opener::open_path`）

### 3.1 localStorage 约定

- **Key：** `pmf:exportDir`
- **值：** 绝对目录字符串（Windows 形如 `E:\...\data\output` 或用户自选的任意可写目录）
- **读写：** 进入 `LibraryDialog` 时 `getItem`；用户确认选择后 `setItem`；`removeItem` 不暴露，清空即回落默认。

## 4. 后端 — Rust 契约

### 4.1 目录与文件名

```rust
// 伪签名，实际位于 src-tauri/src/commands/export.rs

/// 默认导出目录 = data_dir_for(app).join("output")
pub fn default_export_dir_for(app: &AppHandle) -> Result<PathBuf, String>

/// 生成文件名 pmf-library-YYYYMMDD-HHmmss.json，遇冲突追加 -1/-2
fn unique_filename_in(dir: &Path, stem: &str) -> PathBuf

/// 归一目录（去空白、父目录 canonicalize、剔除 ./../ 词法）
fn normalize_export_dir(input: &str, app: &AppHandle) -> Result<PathBuf, String>
```

- **默认目录解析：** 直接调用 `migration::data_dir_for(app)? .join("output")`，不二次拼接 `data`，避免 `data/data/output` 的历史坑（见 `business::normalize_business_path` 的兼容逻辑）。
- **文件名模板：** `pmf-library-{YYYY}{MM}{DD}-{HH}{mm}{ss}.json`，本地时间（`chrono::Local::now()`）格式化；若同名已存在则尝试 `pmf-library-…-1.json` 递增，最多 100 次（极端同秒高频导出）。
- **目录归一：** 参考 `business::normalize_business_path` 的父目录 `canonicalize` 策略；对不存在的目录则做词法归一（`lexical_normalize`），末尾不强制 `canonicalize`（避免首次创建前就要求存在）。

### 4.2 Tauri Commands

```rust
#[tauri::command]
pub fn db_get_default_export_dir(app: AppHandle) -> Result<String, String> {
    Ok(default_export_dir_for(&app)?.to_string_lossy().to_string())
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct ExportToDirResult {
    pub path: String,
    pub json: String,
    pub filename: String,
}

#[tauri::command]
pub fn db_export_library_to_dir(app: AppHandle, dir: String) -> Result<ExportToDirResult, String>

#[tauri::command]
pub fn db_reveal_in_explorer(app: AppHandle, path: String) -> Result<(), String>
```

### 4.3 `db_export_library_to_dir` 流程

```
1. dir = normalize_export_dir(&dir, &app)?   // 空串则回落 default_export_dir_for
2. std::fs::create_dir_all(&dir)?            // 幂等；失败返回可读错误
3. Writable 校验：尝试在 dir 下创建并删除临时探针文件（可选，或直接依赖 atomic_write 的错误）
4. payload = export_library(&open_conn(&app)?)? // 复用 db.rs 的 is_deleted=0 过滤
5. json = serde_json::to_string_pretty(&payload)?
6. filename = unique_filename_in(&dir, "pmf-library-YYYYMMDD-HHmmss")
7. full_path = dir.join(filename)
8. atomic_write(full_path.to_string_lossy(), json.as_bytes())? // 复用 db.rs::atomic_write
9. Ok(ExportToDirResult { path: full_path, json, filename })
```

- **错误分类（字符串透出，前端据此分支）：**
  - `目录不存在且无法创建: {dir}: {os_err}` → 提示重选
  - `目录不可写: {dir}: {os_err}` → 触发 Blob 降级
  - `当前无激活的提示词数据库…`（来自 `open_conn`）→ 提示先选库
  - `导出失败: {serde_err}` → 罕见，直接 Toast

- **原子性：** `atomic_write` 已保证"临时文件 + rename"，落盘不会产生半截 JSON。
- **权限：** 仅写 `dir` 下的新文件，不触及其他目录；不提供任意路径的读能力。

## 6. 前端 `LibraryDialog.vue` 改动要点

- **状态：** `exportDir: ref<string>('')`（生效目录）、`exporting: ref(false)`、`lastExportPath: ref<string | null>(null)`、`defaultDir: ref<string>('')`
- **挂载：** `onMounted` 中并行执行：
  1) `localStorage.getItem('pmf:exportDir')` 回填；
  2) `dbGetDefaultExportDir()` 获取默认绝对路径用于占位/回落展示（失败则用 `…/data/output` 文案占位）。
- **选择：** `onPickDir()` 中 `const dir = await open({ directory: true })`，非空则 `exportDir = dir; localStorage.setItem(...)`，`null` 则不改。
- **导出：**
  ```ts
  const targetDir = exportDir.value.trim() || defaultDir.value
  try {
    const { path, filename } = await dbExportLibraryToDir(targetDir)
    lastExportPath.value = path
    push(`已导出至 ${path}`, 'success')
  } catch (err) {
    // 尝试 Blob 降级
    try {
      const json = await dbExportLibrary() // path=null
      // Blob + <a download> 复用现有 LibraryDialog 的下载逻辑
      push(`已通过浏览器下载导出（落盘失败，已自动降级）: ${String(err)}`, 'warning')
    } catch (e2) {
      push(`导出失败: ${String(err)} / 降级亦失败: ${String(e2)}`, 'error')
    }
  }
  ```
- **打开文件夹：** `await openPath(lastExportPath.value)` 或 `await dbRevealInExplorer(lastExportPath.value)`，按钮 `data-testid="library-export-open-dir"`。

## 7. 关键边界与校验

| 校验点 | 规则 |
|--------|------|
| 空目录入参 | 空串视同"使用默认目录"（`default_export_dir_for`） |
| 相对路径 | 若用户通过其他入口传入相对路径，则按 `data_dir_for` 的相对拼接规则归一（参考 `business.rs` 的 `data/` 前缀剥离） |
| 非法字符 | 依赖 OS 与 `create_dir_all` 的错误透出，不在前端预校验 |
| 并发导出 | 文件名含秒级时间戳 + 冲突递增，已可应对同秒二次点击；`exporting` 互斥避免并发 |
| 长路径 | Windows `MAX_PATH` 由 OS 报错透出，前端不截断路径 |

## 9. 备选与舍弃

- **前端 `fs` 直写：** 需 `tauri-plugin-fs` 且要在 JS 侧拼路径与处理并发/半截文件，不如复用 Rust `atomic_write`。
- **文件选择器而非目录选择器：** 题述明确为"文件夹"，`open({ directory:true })` 是唯一符合项；`save` 对话框虽可指定文件名但不符合"选文件夹"的交互。
- **把默认目录做成可配置设置页：** 首版用 `localStorage` 记忆已满足"下次沿用"，设置页可后置。

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| `C:\Program Files` 下 exe 不可写 | 捕获 `create_dir_all / atomic_write` 错误，Toast + Blob 降级，并引导用户自选可写目录 |
| Dialog 插件权限未配导致 `open()` 被拒 | `capabilities` 显式加 `dialog:allow-open`，并在前端对 `open` 的异常做 try/catch 提示 |
| 旧版本前端调用新命令失败 | 命令不存在时 `invoke` 抛错，前端捕获后回落 Blob 下载，不阻断导出 |
