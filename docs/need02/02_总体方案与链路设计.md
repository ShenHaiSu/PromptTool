# 02 — 总体方案与链路设计

> 本文档定分层、定链路、定关键决策。实现与本文冲突时，以 `03_IR中间表示与数据契约.md` 为准。

---

## 1. 设计目标

1. **规则可配**：`rules` 表从“种子摆设”变为唯一真源；R01/R02/R03 转正为种子数据，引擎只读表、不读代码分支。
2. **冲突可见**：任何 IR（画布 / 批量卡 / 历史方案 / 模板）都能算出结构化 `findings`，而非只有整串后的警告文案。
3. **IR 可改**：`IrConflictEditorDialog` 内可改字、改权重、删段、排序、忽略/修复冲突，所见即所得预览 `finalPrompt`。
4. **安全可退**：所有写库乐观更新 + 失败回滚；破坏性操作 `window.confirm`；规则删除为软删除；编辑器有关闭前脏检查。

非目标见 `00 §五`，不再重复。

## 2. 分层架构

```
┌─ 视图层 ─────────────────────────────────────────────┐
│ IrConflictEditorDialog.vue（主框：段表/冲突/预览）      │
│ RuleListPanel.vue + RuleEditDialog.vue（规则管理）      │
│ PromptPreviewDialog（+“打开冲突编辑器”入口按钮）        │
│ DimensionPanel（已选设置区 +“冲突 N”入口徽标，可选）     │
└──────────────────┬───────────────────────────────────┘
                   │ props 受控 + emit（open/update:open/applied）
┌─ 组合式/状态层 ──▼───────────────────────────────────┐
│ src/stores/rules.ts（规则列表/刷新/乐观更新）            │
│ src/stores/assembly.ts（复用：setSelected/reassemble）  │
│ src/lib/irEdit.ts（纯函数：段增删改排 + 重算 preview）   │
└──────────────────┬───────────────────────────────────┘
                   │
┌─ 领域层（纯前端，无 IO）▼─────────────────────────────┐
│ src/engine/ruleTypes.ts（Rule/Finding/AutoFix 类型）    │
│ src/engine/ruleEngine.ts（evaluateRules + autoFix）    │
│ src/engine/assembly.ts（复用 assemble，输入改为 IR v2） │
│ src/engine/adapters.ts（复用，不改签名）               │
└──────────────────┬───────────────────────────────────┘
                   │
┌─ 传输层 ─────────▼───────────────────────────────────┐
│ src/lib/db.ts（新增 dbListRules/dbCreateRule/         │
│  dbUpdateRule/dbDeleteRule/dbToggleRule，camelCase）  │
└──────────────────┬───────────────────────────────────┘
                   │ Tauri invoke
┌─ 存储层 ─────────▼───────────────────────────────────┐
│ src-tauri/src/commands/rules.rs（CRUD + 校验 + 软删）  │
│ resources/schema.sql（不改表结构；仅新增种子对账）      │
└──────────────────────────────────────────────────────┘
```

**分层铁律**：

- `src/engine/*` 禁止 `import { invoke }`，禁止读 `localStorage`，必须为纯函数（可单测、无 Tauri 宿主也可跑）。
- `src/stores/rules.ts` 是规则唯一的内存真源；组件不直调 `invoke` 改规则，必须经 store（保证乐观更新 + 回滚 + 事件统一）。
- 写库成功后必须 `emit(LIBRARY_CHANGED, {source, op})`，由 `App.handleLibraryChanged → library.scheduleFetch()` 统一刷新（沿用 need01 链路）。

## 3. 核心链路

### 3.1 Happy Path：从预览打开编辑器并修复冲突

```
用户点击「预览」→ PromptPreviewDialog（新增“冲突编辑”按钮，badge 显示 findings 计数）
 → IrConflictEditorDialog.open(ir快照, config快照)
 → 左区段表渲染 segments（每段：维度色条 + dimensionKey chip + text + weight stepper + 锁定/删除）
 → ruleEngine.evaluateRules(segments, rules) → findings 写入右区
 → 用户点击某 finding 的「自动修复」→ 预览 autoFix 删减方案（diff 高亮被删段）
 → 用户「应用修复」→ irEdit.applyFix → 重算 findings + finalPrompt → 脏标记
 → 用户「应用到画布」→ assembly.setSelected(回映射 SelectedItem) → 关闭 → Toast
```

### 3.2 规则管理链路

```
RuleListPanel（入口：编辑器右区“管理规则”或 DimensionPanel 设置区）
 → dbListRules → 列表（名称/type/涉及维度/启用开关/编辑/删除）
 → RuleEditDialog（表单见 05 §4.3，维度/条目下拉来自 library store）
 → rules.store 乐观更新 → invoke → 失败回滚 + Toast → 成功 LIBRARY_CHANGED（op=rule-changed）
 → 所有打开的 IR 视图重算 findings（订阅 store 即可）
```

### 3.3 批量卡链路（只读 findings + 一键进入编辑器）

```
BatchCard 新增 props findings（由 BatchFactory 在生成后调用 evaluateRules 计算，
  不阻塞生成主链路）→ 警告行沿用 amber 样式展示首条 message
 → 「编辑」按钮 → IrConflictEditorDialog.open(card.ir) → 应用后可「回填到画布」或「更新本卡」（见 05 §6）
```

## 4. 关键决策

| 编号 | 决策 | 理由 |
|------|------|------|
| K1 | **引擎只读 `rules` 表**，`rules.ts` 硬编码标记 `@deprecated` 并转调 `ruleEngine`，保留导出别名 `applyRules` 做兼容 | 现有单测 `rules.test.ts`、`assembly.test.ts`、`BatchFactory.favorite.test.ts` 均 `import { applyRules }`，直接删除会大面积破测试；转调保证行为一致 + 种子数据对齐（见 04 §6 迁移表） |
| K2 | IR v2 **加字段不改旧字段**：`PromptIR{segments, warnings}` 原样保留，新增 `findings: Finding[]`、`version: 2`（见 03） | 老快照可直接读；`hash()` 口径不变，去重语义稳定 |
| K3 | 规则求值输入为 **IR segments（快照）而非 SelectedItem（引用）** | 批量卡/历史快照只有 `text + sourceModuleId`，无模块引用；统一快照输入保证四处（画布/批量/历史/模板）同一算法 |
| K4 | 自动修复是**建议而非自动执行**：引擎产出 `fix{removeIds[], keepIds[], reason}`，必须用户点击才应用 | 避免静默删用户已选；锁定项永不被自动移除（见 04 §4） |
| K5 | 规则条目级定位用 **`sourceModuleId` 优先、`contentEn` 关键词 fallback** | R02/R03 现状是关键词匹配（`barefoot/studio`），种子数据转正时保留关键词模式（见 04 §2.3），新规则推荐用明确 `source/target_module_id` |
| K6 | 不新增 `rules` 表列；`message` 为模板串，支持 `{source}{target}` 占位 | 零迁移、零数据丢失；`limit/isolated` 首版以后端校验 + 前端提示实现，不做复杂计数器 UI（见 04 §3） |
| K7 | 编辑器为**受控对话框**（`v-model:open`），内部维护 `draft` 副本，关闭时脏检查 | 避免直接改 store 导致预览与画布闪烁；`applied` 后由调用方决定是否写回画布 |

## 5. 状态机

### 5.1 编辑器主状态

```
closed → open(draft=clone(ir), findings=evaluate(draft))
  → editing（段改动 → 重算 findings+preview → dirty=true）
  → fixing（previewFix 非空 → 确认/取消）
  → applying（写回画布/存方案中，按钮 disabled + Toast）
  → closed（ applied | 取消（dirty 则 confirm） ）
```

### 5.2 规则启用开关

```
enabled ──toggle──→ disabled（求值时跳过，findings 即时减少，无需重载）
  删除 → 软删除（is_deleted=1，列表默认隐藏，提供“显示已删除/恢复”）
```
