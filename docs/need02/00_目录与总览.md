# Need02 — IR 冲突编辑器 · 目录与总览

> **需求**：当前 `rules` 表有表无路、冲突逻辑硬编码在 `src/engine/rules.ts` 三段 `if` 中，前端无规则管理、无 IR 分段编辑能力。`PromptPreviewDialog` 仅只读展示 IR JSON，`BatchCard` 仅展示整串 + 维度徽标。本需求补齐 **IR 为一等公民的冲突配置与编辑器闭环**：规则可配、冲突可见、IR 可改、修复可一键应用。
>
> **核心隐喻**：片段（`modules` 行）已经是一等公民（见前序核验结论）；本需求让**冲突规则**也成为一等公民，让 **PromptIR** 从“拼完即扔的中间变量”升级为“可视、可改、可校验的工作台对象”。

- **输出路径**：`docs/need02/`（本目录）
- **版本**：v1.0 — 2026-09-07
- **状态**：方案设计，待评审后施工
- **上游引用**：`docs/need01/00-07`（翻译链路与对话框范式）、`docs/Tauri-develop/03_数据模型与存储迁移.md`（存储基线）、`docs/pitfalls/01-invoke-arg-case.md`（invoke 大小写铁律）

## 二、术语

| 术语 | 含义 |
|------|------|
| **片段 / Module** | `modules` 表的一行，`contentEn` 为拼入 Prompt 的英文原文，`displayName` 为中文显示名，通过 `dimension_id` 外键归属维度 |
| **维度 / Dimension** | `dimensions` 表的一行，`key` 为机器键（如 `outfit`），`nameCn` 为中文名 |
| **IR / PromptIR** | `src/engine/models.ts:192-215` 的 `{segments: IRSegment[], warnings: string[]}`；本需求升级为 IR v2，增加结构化 `findings`（见 03） |
| **Segment / IRSegment** | `{dimensionKey, text, weight, sourceModuleId}`，`text` 为 `contentEn` 快照，`weight` 为已合并 `weightOverride` 后的生效权重 |
| **规则 / Rule** | `rules` 表的一行，`type ∈ mutex/requires/excludes/limit/isolated`，描述维度/条目间的约束（见 04） |
| **Finding / 冲突发现** | 规则引擎对当前 IR 求值后产出的结构化结论 `{ruleId, type, severity, message, involvedModuleIds, fix}`，区别于 legacy 的纯字符串 `warnings` |
| **IR 冲突编辑器** | 本需求新增的工作台对话框 `IrConflictEditorDialog.vue`：左段表 + 右冲突 + 底预览三区，IR 可改、冲突可见、修复可点（见 05/06） |
| **自动修复 / AutoFix** | 引擎按规则类型与锁定优先级生成的确定性删减/保留方案，用户一键应用（非静默自动执行） |

## 五、基线与非目标

- **基线复用**：`DimensionPanel` 三段式面板、`PromptPreviewDialog` 居中对话框范式、`Teleport z-[70] + calcMenuPos/calcPopoverPos` 浮层、`useToast` 反馈、`data-testid` 体系、`library.scheduleFetch + LIBRARY_CHANGED` 刷新链、`export.ts` CSV 导出（详见 01）。
- **非目标**：不做 LLM 自动修冲突、不做跨库规则市场、不改 `contentEn` 分词语义、不引入新的软删除语义、不碰 `need01` 翻译链路、不做规则版本分支（单版本 + `is_enabled` 开关）。
- **破坏性约束**：`dimensions.key`、`modules.id`、`assemblies` 快照语义不变；IR v2 对老 `prompt_ir` JSON 前向兼容（无 `findings` 字段的老快照可直接读，见 03 §7）。
