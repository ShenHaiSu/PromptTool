## 需求原文

1. 左侧提示词分类（维度）面板，默认状态改为折叠，不要默认展开；
2. 合理设计一套用户在前端手动添加提示词片段（词条/模块）以及创建提示词分类（维度）的交互入口、完整的交互逻辑和交互界面。

## 设计约束（两需求通用）

- **向后兼容**：新增 Rust 命令沿用 `open_conn` + `Result<_, String>` 模式，DTO 保持 `camelCase`（`#[serde(rename_all = "camelCase")]`），invoke 参数键名与 Rust 形参 camelCase 形式一致。
- **软删除**：维度和词条均使用 `is_deleted` 字段软删除，不物理删除，保证历史数据引用完整性。
- **幂等**：创建操作可重复执行（维度 key 唯一校验），不产生重复数据。
- **级联安全**：删除维度前检查是否存在未删除的词条，有则拒绝并提示用户先清理词条。
- **UI 一致性**：弹窗组件复用现有 `SaveDialog` 的 `v-model:open` 模式（props `open` + emit `update:open`），视觉风格与 `SaveDialog` / `LibraryDialog` 保持一致。
