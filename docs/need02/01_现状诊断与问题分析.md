# 01 — 现状诊断与问题分析

> 目标：用文件证据说明“为什么必须做 need02”。结论先行：**规则有表无路、执行硬编码、IR 只读、编辑器整体缺失**，且配置与执行脱节。

---

## 1. 数据结构现状（成立的部分）

- `src-tauri/resources/schema.sql:13-25` — `dimensions` 独立表（`id` 主键 + `key` 业务键 + `sort_order/is_multi_select/is_enabled`）。
- `src-tauri/resources/schema.sql:31-46` — `modules` 独立表，每行独立 `id`，`dimension_id TEXT NOT NULL ... FOREIGN KEY (dimension_id) REFERENCES dimensions(id)`，`content_en` 为拼入 Prompt 的英文片段。
- `src/engine/models.ts:12-38` — 前端同构 `Dimension` / `Module{dimensionId, contentEn, displayName, weight, ...}`，`IRSegment{dimensionKey, text, weight, sourceModuleId}` 经 `sourceModuleId` 回指 `Module.id`。
- 实测 `data/pmf.db`：`dimensions` 14 行（`body/face/top/bottom/outfit/shoes/accessories/pose/props/background/camera/gender/ethnicity/height`，仅 `accessories` 为 `is_multi_select=1`）、`modules` 356 行、`rules` 3 行。

**结论**：说法 1（片段一等公民 + 外键 + 维度独立表）成立，无需重构存储模型。

## 2. 随机与拼装现状（半成立的部分）

### 2.1 随机单位是片段 — 成立

`src/engine/random.ts:37-98` `randomAssembly`：逐维度取 `modulesByDim[dim.key]` 池 → 过滤 `isEnabled/isNsfw` → 锁定保留 → 按 `weight` 做 `weightedSample(pool, n)`（单选 `n=1`，多选 `n ∈ 0..min(2,len)`）。`partialRandomAssembly`（L100-180）同理补缺口维度。随机单位确为片段。

### 2.2 拼装保留片段结构 — 成立

`src/engine/assembly.ts:9-28` `assemble`：`applyRules → sortByOrder → map→IRSegment → adaptToModel`，`PromptIR{segments, warnings}` 完整保留每段来源；`src/engine/adapters.ts:8-14` 才按 `separator`（默认 `', '`）`join` 为 `finalPrompt`（SD 权重 `>1` 包 `(t:w)`、`<1` 包 `[t]`，MJ 用 `::`，Flux 丢权重）。

### 2.3 展示“每片段拼接 + 视觉分隔” — 不准确

| 位置 | 实际行为 | 文件证据 |
|------|----------|----------|
| 画布已选区 | 每片段独立卡片，按 `dimColor` 左边框 4px + 圆点 + `dimensionKey` chip | `DimensionPanel.vue:834-852` |
| 批量结果卡 | 单个 `<p>` 显示拼接后整串；视觉分隔仅是下方 `dimKeys` 徽标行 | `BatchCard.vue:116-136` |
| 预览弹窗 | 整串 + `X 字符 · Y 段` 计数；IR 仅折叠只读 JSON | `PromptPreviewDialog.vue:136-160` |

**缺口**：批量与预览处用户看不到“哪一段来自哪个维度、权重多少、能否单独改”，IR 的结构化信息在展示层丢失。

### 2.4 复制写整串 — 成立

`BatchCard.vue:26-43`、`PromptPreviewDialog.vue:65-84`、`App.vue:46-59` 均为 `navigator.clipboard.writeText(finalPrompt)` + `textarea/execCommand` 降级；批量全复制为多条 `finalPrompt` 换行 `join`（`BatchFactory.vue:93-105`）。

## 3. 规则现状（不成立的部分，need02 主战场）

### 3.1 存储有雏形，零消费

- `schema.sql:131-145` — `rules(id, name, type[mutex|requires|excludes|limit|isolated], source_dimension_id/module_id, target_dimension_id/module_id, message, is_enabled)`，索引 `idx_rules_source/target_dim`。
- `migration.rs:361-380`（另有 402-433 重复 seeding）— 3 条种子：`rule_01 mutex dim_05→dim_03`（套装互斥）、`rule_02 mutex dim_06(mod_shoes_15)→dim_06`（鞋袜赤脚）、`rule_03 excludes dim_10(mod_bg_01)→dim_10`（室内外）。**注意**：`mod_bg_01` 与实际 `mod_background_XX` 命名疑似对不上，need02 施工时需先对账（见 07 T0）。
- `db.rs:1146-1157 RuleDto` 仅用于词库导出（L1295-1321）/导入（L1701-1784）；**无 `db_list/create/update/delete_rule` 命令**，前端无 store、无对话框、无列表。

### 3.2 执行硬编码，且双重实施

| 编号 | 位置 | 行为 |
|------|------|------|
| R01 | `rules.ts:13-23` | 有 `outfit` 则剔除未锁定 `top/bottom` |
| R02 | `rules.ts:26-50` | `shoes` 内 `contentEn.includes('barefoot')` 互斥，锁定侧优先 |
| R03 | `rules.ts:52-66` | `background` 内 `studio` vs `beach/sunset/street/rooftop`，保留 `studio` |
| H5 | `random.ts:182-204 filterPoolByAnchor` | 用同样关键词做池前过滤，与 `applyRules` 双重实施 |
| H6 | `PromptPreviewDialog.vue:33-41` | badge 按首条 warning 含 `套装/裸足/室内` 关键字分类，脆弱的字符串匹配 |

后果：新增一条互斥（如“帽子与头盔”）需要改三处代码 + 发版；用户无法自行配置；`rules` 表改了也不生效。

### 3.3 warnings 链路丢信息

- `batch.ts:29,55` 把 `ir.warnings` 复制一份到 `BatchCardModel.warnings`（双写）。
- `db_save_assembly_from_ir` 的 `IrDto.warnings` 标 `allow(dead_code)`（`db.rs:599-604`）直接丢弃，落盘快照无警告。

## 5. 根因一句话

`rules` 表是按“一等公民”设计的（独立表 + 类型枚举 + 双向外键 + 索引），但**引擎从未读取它**，前端从未管理它；IR 是按“结构化中间表示”设计的（`segments + warnings + hash`），但**展示层只消费 `finalPrompt` 整串**。need02 即把这两条断链接上。
