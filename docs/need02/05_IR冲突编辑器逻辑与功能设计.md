# 05 — IR 冲突编辑器逻辑与功能设计

> 本文档是 need02 的核心施工图：`IrConflictEditorDialog` 的逻辑状态、六大功能、`RuleListPanel/RuleEditDialog` 的形态、`stores/rules` 与 `lib/irEdit` 的函数签名。UX 落地细节见 06。

## 1. 组件总览与 props/emit 契约

```vue
<!-- src/components/IrConflictEditorDialog.vue -->
<script setup lang="ts">
const props = defineProps<{
  open: boolean
  /** 进入时快照（调用方传入 assembly.ir / card.ir / 历史方案解析结果） */
  ir: PromptIR | null
  /** 进入时配置快照（separator/权重括号/profile/排序） */
  config: AssemblyConfig
  /** 规则列表（由调用方从 rules store 传入，或编辑器内部 useRulesStore 自取——推荐后者，props 仅 ir/config） */
  title?: string   // 默认 “IR 冲突编辑器”
}>()
const emit = defineEmits<{
  (e: 'update:open', v: boolean): void
  (e: 'applied', payload: { ir: PromptIR; finalPrompt: string }): void
  (e: 'close'): void
}>()
defineExpose({ refresh: () => void })
</script>
```

- 受控形态（沿用 `PromptPreviewDialog` 范式）：`open` 由父控，内部 `draft: Ref<IRSegment[]>` 为深拷贝，`dirty` 脏标记，关闭时脏检查（`window.confirm('改动未应用，确定关闭？')`）。
- 规则来源：内部 `const rulesStore = useRulesStore()` + `onMounted/fetchAll`，`findings = computed(() => evaluateRules({segments: draft, rules: enabledRules, lockedIndexes}))`，规则变更自动重算（订阅即得，无需事件）。
- `data-testid` 前缀 `ir-editor-*`（清单见 06 §6）。

## 2. 左区：段表（Segment Table）——IR 可改

### 2.1 行结构

每行 = 一个 `draft[i]`，复用 `selected-card` 视觉（左边框 4px `dimColor` + 圆点 + `dimensionKey` chip，见 06 §2）：

```
[≡ drag] [●dim] dimensionKey chip | text(单行截断, title=全文) | w stepper | 🔒/🔓 | ✕
         └─ 展开行（点击 text 展开）：text Input 全文 + sourceModuleId 缩略 + 维度中文名
```

- 排序：`VueDraggable`（复用 `DimensionPanel` 参数：`animation=150 ghost-class=opacity-40 handle=.drag-handle`），`@end` 后重算 findings。
- 新增段：工具行“+ 添加空段”按钮，插入 `{dimensionKey:'', text:'', weight:1, sourceModuleId:''}` 并聚焦其 text 输入（用于手动补写 prompt 片）。
- 空 text 段：行标黄 + `title='文本为空，该段不会拼入预览'`，拼装时自动跳过（`adaptToModel` 前 `filter(text.trim())`，见 §3.5）。

### 2.2 改字（text）

- 行内点击 text → 展开 `Input`（`h-7 text-xs font-mono`），300ms debounce 写回 `draft[i].text` → 重算 findings + preview。
- 守卫：`text` 允许任意英文；若含 CJK（`/[\u4e00-\u9fa5]/`）→ 行下 amber 提示“检测到中文，拼入的 Prompt 通常为英文，请确认”，不拦截（只提示）。
- 改字后 `sourceModuleId` 保留（表示“源自该模块的改写”），回写画布时按 `sourceModuleId` 尽量关联回库模块（见 §6.1）。

### 2.3 改权重（weight）

- 复用已选卡 `w stepper`：`−/＋` 步进 0.1 + 点击弹 `weight-slider(0.5-2.0 step0.1)+weight-input` 浮窗（抄 `DimensionPanel.vue:926-947` 结构与 `clampWeight`，`=1` 显示 `w1.0`）。
- 写回 `draft[i].weight`（注意：draft 内存即生效权重，无 `weightOverride` 概念；回写画布时再拆分为 `weightOverride = w!==1 ? w : null`）。
- 额外能力：`title='双击同步为词条默认权重'`？否——改为显式行菜单项“写回词条默认权重”（需 `sourceModuleId` 非空 + 二次确认 + `dbUpdateModule`，见 §5）。

### 2.4 删段与锁定

- `✕` 删除：即时删除 + Toast（`info '已移除一段，可继续编辑'`，无 confirm——编辑器内可撤销见 §7，且关闭不应用即全弃）。
- `🔒` 锁定：锁定段不参与自动修复移除（`lockedIndexes`），行加 `ring-1 ring-primary` 态；锁定态在回写画布时映射为 `SelectedItem.locked=true`。

### 2.5 预览重算

```
draft 变更 → findings = evaluateRules(...) → warnings = findings.map(message)去重
→ previewSegments = draft.filter(text.trim()) → finalPrompt = adaptToModel({segments: preview}, profile, config)
```

`hash()` 显示于底栏（`8 位短 hash`，用于肉眼确认两次改动是否等价）。

## 3. `src/lib/irEdit.ts`（纯函数，单测覆盖）

```ts
export function cloneSegments(segs: IRSegment[]): IRSegment[]
export function updateSegmentText(segs: IRSegment[], index: number, text: string): IRSegment[]
export function updateSegmentWeight(segs: IRSegment[], index: number, weight: number): IRSegment[]  // clamp 0.5-2.0 + round 0.1
export function removeSegment(segs: IRSegment[], index: number): IRSegment[]
export function moveSegment(segs: IRSegment[], from: number, to: number): IRSegment[]
export function appendEmptySegment(segs: IRSegment[]): IRSegment[]
export function applyFindingFix(segs: IRSegment[], fix: FindingFix): IRSegment[]  // removeIndexes 降序 splice
export function buildPreview(segs: IRSegment[], profile: string, config: AssemblyConfig): string   // 过滤空 text 后 adaptToModel
export function toSelectedItems(segs: IRSegment[], opts: { lockedIndexes: Set<number> }): SelectedItem[]
// toSelectedItems：module 字段尽量回填 {id: sourceModuleId, dimensionKey, contentEn: text, displayName: text.slice(0,24), weight}
//   dimensionId 回填需查 library（按 dimensionKey→id），查不到置 ''（快照语义，见 01 D9，允许但需标注）
export function shortHash(ir: PromptIR): string  // ir.hash().slice(0, 8)
```

全部不可变更新（返回新数组），供编辑器 `draft.value = updateSegmentText(...)` 直接用。

## 4. 右区：冲突列表 + 规则管理

### 4.1 冲突列表（Findings List）

- 头部：`Badge（✓ 无冲突 / ⚠ N 冲突 / ⛔ N 错误）` + “管理规则”按钮 + “全部忽略”文字按钮（将所有 `warning` 置 `ignored`，`error` 不可批量忽略）。
- 行结构：`[severity 色点] ruleName + message（两行截断，title=全文） + involvedIndexes 段号 chips（如 #1 #3） + 操作区`。
- 行操作（按 `fix` 是否为空）：
  - 有 fix：`「自动修复」`（主按钮，`size=sm h-6 text-xs`）→ 进入 `fixing` 预览态（见 §4.5）；`「忽略」`（ghost）。
  - 无 fix（`requires/limit`）：`「定位」`（滚动左区到首个 involved 段并高亮 `ring` 1.2s）+ `「忽略」`。
- 点击段号 chip → 同定位高亮。
- 忽略态行 `opacity-60 + “已忽略” Badge`，可“取消忽略”。

### 4.2 `RuleListPanel.vue`（内嵌于右区下半或独立 Tab，二选一）

推荐：右区采用 `Tabs（value=findings/rules）` 复用 `HistoryPanel` 的 `Tabs` 模式（见调研结论 §1）。`rules` 页：

```
工具行：[搜索 Input][+ 新建规则 Button][仅看启用 checkbox]
列表行：[type Badge][name + message 一行截断][涉及维度 chips][启用 Switch(原生 checkbox accent-primary)][✎][✕]
```

- `type Badge` 色：`mutex=amber`、`requires=blue`、`excludes=orange`、`limit=slate`、`isolated=red`（语义色，见 06 §2）。
- 删除 → `window.confirm('删除规则将影响后续冲突判定，确定？')` → 软删除。
- 行 `data-testid=rule-row-{id}`，开关 `rule-toggle-{id}`。

### 4.3 `RuleEditDialog.vue`（表单）

```ts
props: { open, mode: 'create'|'edit', initialRule?: Rule | null }
emit: confirm(payload: RuleUpsertPayload)
```

字段（按序）：

1. `名称 Input*`（`rule-name`，必填，≤50 字）。
2. `类型 select*`（`rule-type`，五类，下方联动说明文案：选中 `mutex` 显示“源与目标二存一，默认保留源”）。
3. `源维度 select`（`rule-source-dim`，选项来自 `library.dimensions`，可空）+ `源条目 select`（`rule-source-module`，随源维度联动过滤，可空=该维度全部）+ 高级折叠 `源关键词 Input`（转正兼容，默认收起）。
4. `目标维度/条目/关键词` 同上（`limit` 类型时隐藏目标组，显示 `上限数量 number(1-10)`；`requires` 显示提示“目标缺失时仅提示补选，无一键修复”）。
5. `提示消息 Input*`（`rule-message`，必填，支持 `{source}{target}` 占位，旁附示例）。
6. `启用 checkbox`（默认勾选）。
7. 底部：`取消 / 保存（Ctrl+Enter）`，校验失败行下红字（`名称/消息必填`、`mutex/excludes 需至少一侧定位`）。

### 4.5 修复预览态（fixing）

点击某行「自动修复」→ 该行展开 `fix preview` 子块：

```
将移除： [#2 上装 chip] [#3 下装 chip]    将保留： [#1 全身套装 chip]
[确认应用] [取消]
```

- 确认 → `draft = applyFindingFix(draft, fix)` → 重算 → Toast `success '已应用修复'` → 该 finding 消失（`dirty=true`）。
- `isolated` 的确认按钮为 `destructive` + 文案“仍要应用（将清空 N 段）”。

## 5. 词条/维度轻编辑（E4/E5 收敛，不开新框）

- 段展开行内增加两项（需 `sourceModuleId` 非空，否则置灰 + `title` 说明）：
  - `isEnabled 开关`（调用既有 `dbUpdateModule`/`dbUpdateDimension`，沿用 `library` store 方法，乐观更新）。
  - `写回词条默认权重`（`dbUpdateModule(weight=draft段weight)`，二次确认）。
- 换维（错维迁移）本期不做（涉及 `dimension_id` 外键变更 + 去重键冲突面大），编辑器内以 amber 提示“如需换维请前往维度面板删除重建”。

## 6. 三出口（Extra Actions）

底栏右侧（见 06 §3），按序：

1. `应用到画布`（主按钮）：`assembly.setSelected(toSelectedItems(draft))` → 若画布非空先 `confirm('覆盖当前画布？')` → `emit('applied')` → 关闭 → Toast。
2. `另存方案`：复用 `SaveDialog`（`title` 默认 `finalPrompt` 前 30 字），走 `dbSaveAssemblyFromIr(JSON.stringify(draftIr含findings), finalPrompt, config)`。
3. `复制全文 / 导出 CSV`：复用 `BatchCard/PromptPreviewDialog` 双路径复制 + `exportSingleCsv`。

## 7. 草稿与撤销

- 撤销：编辑器内维护 `undoStack: IRSegment[][]`（上限 30，每次删段/应用修复/排序前压栈），工具行 `↩ 撤销` 按钮 + `Ctrl+Z`（对话框内）。重做不做。
- 草稿持久化：可选（默认不做）。若实现，键 `pmf:irEditor:draft` 存 `{segments, savedAt}`，打开时若存在未应用草稿则 `confirm('恢复上次未应用的编辑？')`。**首版建议不做**，以控制范围（07 T3 标注为可选）。

## 8. 空态与边界

| 场景 | 行为 |
|------|------|
| `ir=null` 或 `segments=[]` | 段表空态（复用 `batch-empty` 样式）+ 可“+ 添加空段”手动写；冲突区显示“暂无可判定的 IR” |
| 规则未加载/加载失败 | 冲突区 warning 条“规则加载失败，仅预览：{e}” + 重试按钮；段编辑不受影响 |
| 全段锁定 + 冲突需删锁定段 | fix 为 null，message 追加解锁提示；提供“全部解锁”快捷 |
| 超长 IR（>50 段） | 段表虚拟化（复用 `BatchFactory` 的 `@tanstack/vue-virtual` 参数，见 06 §5），首版若段数常 < 20 可先不做，以 07 验收实测为准 |
