## 1. 设计目标与非目标

**目标：**

- 在现有"导出词库 JSON"的基础上，增加**输出文件夹自选**（Windows 原生目录选择器）与**默认落盘到 `exe/data/output/`** 的闭环；
- 用户无感时"一键导出即落盘到默认目录"，有诉求时"自选目录后下次沿用"；
- 导出始终产出标准 `pmf-library` JSON，不改变其 `format / formatVersion / counts / dimensions / modules / rules / tags` 结构。

**非目标：**

- 不改 `pmf-library` 的导入侧逻辑；
- 不做文件名自定义、格式切换、增量导出等扩展；
- 首版不做导出历史列表（可后置）。

## 2. 交互设计

### 2.1 入口

- **主入口：** 右下角 `StatusBar` 的 `📚 词库`（`data-testid="library-toggle"`）→ `LibraryDialog` 弹窗内的导出区。
- **改动范围：** 仅 `LibraryDialog` 的导出区（`data-testid="library-export-section"`）重塑；`StatusBar` 与其他入口不动。

### 2.2 导出区布局（`LibraryDialog` 内）

```
导出（标准 JSON，可跨实例导入）

  输出文件夹： [  E:\…\data\output  ]  [选择文件夹]      ← 只读输入框 + 按钮
              提示：默认 data/output；已选目录将自动记忆

  文件名： pmf-library-20260829-153022.json（只读预览，导出瞬间生成）

  [导出词库 JSON]                  ← 主按钮；文案保持不变，disabled=exporting
  导出后：已落盘至 E:\…\data\output\pmf-library-….json  [打开文件夹]
```

- **选择文件夹按钮：** `data-testid="library-export-pick-dir"`，触发 Windows 原生目录选择器。
- **输出文件夹输入框：** `data-testid="library-export-dir"`，只读展示当前生效目录；未自选时显示默认 `…/data/output` 的可读缩写，hover 显示全路径。
- **主导出按钮：** `data-testid="library-export-btn"` 保持不变（兼容既有用例），点击后按当前生效目录落盘。
- **"打开文件夹"链接：** `data-testid="library-export-open-dir"`，导出成功后出现，点击调用系统文件管理器打开所在目录（`opener`）。

### 2.3 交互时序

1. 弹窗打开 → 读取 `localStorage.getItem('pmf:exportDir')`，若有则回填；否则展示默认目录（前端计算或后端 `db_get_default_export_dir` 返回的绝对路径）。
2. 点击"选择文件夹" → 调 `open({ directory: true })` 拉起 Windows 目录选择器 → 用户确认则回填输入框并 `localStorage.setItem('pmf:exportDir', dir)`，取消则保持原值。
3. 点击"导出词库 JSON" → `exporting=true` → `await dbExportLibraryToDir(dir)`（或 `dbExportLibrary(path)` 落盘）→ 成功则 Toast + 展示"已落盘至 … + 打开文件夹"；失败则按 §4 降级。

### 2.4 状态与反馈

| 状态 | 文案/表现 |
|------|-----------|
| 未自选、展示默认 | 输入框灰字"默认：…/data/output"，按钮"选择文件夹"常态 |
| 已自选 | 输入框显示绝对路径，hover 全路径；按钮仍可重选 |
| 导出中 | 主按钮 `disabled` + 文案"导出中…"，选择按钮 `disabled` |
| 导出成功（落盘） | Toast `已导出至 {path}`（`success`）；结果区"已落盘至 … [打开文件夹]" |
| 导出成功（Blob 降级） | Toast `已通过浏览器下载导出（落盘失败，已自动降级）`（`warning`）+ 错误原因 |
| 用户取消目录选择 | 无 Toast，保持原目录 |
| 目录不可写/原子写失败 | Toast `导出失败: {err}`（`error`）+ 自动 Blob 降级 |

### 2.5 边界与空态

- 首次安装且 `data/output` 尚不存在：首次导出时由后端 `create_dir_all` 自动创建。
- `localStorage` 被清空：回落默认 `data/output`。
- 长路径展示：输入框 `truncate` + `title` 全路径，必要时在结果区换行展示。

## 3. 路径与命名规则

### 3.1 默认目录

- **定义：** `exe 所在目录 / data / output`，即 `migration::data_dir_for(app) + "output"`。
- **解析：** 复用 `migration::data_dir_for`（`std::env::current_exe().parent() / "data"`），再 `join("output")`。
- **创建：** 后端在落盘前 `std::fs::create_dir_all(&dir)`（幂等），与 `init_db` 的建库逻辑一致。

### 3.2 生效目录优先级

```
用户自选目录（localStorage pmf:exportDir，且经后端校验可写）
  > 默认目录（exe/data/output）
```

- 自选目录若后续被删除/不可写：后端在导出时报可读错误，前端捕获后 Toast 提示并提供"重选文件夹"与"使用默认目录"两条出路。

### 3.3 文件命名

- **模板：** `pmf-library-YYYYMMDD-HHmmss.json`（与 `LibraryDialog` 现有 `a.download` 命名一致），时间取**导出瞬间**本地时间，`padStart(2,'0')`。
- **生成方：** 首选**后端**生成（避免前端/后端时间不一致），或前后端任一但保持模板一致；本设计约定由**后端**在落盘时生成文件名并回传完整路径，前端据此展示与"打开文件夹"。

### 3.4 路径归一与安全

- 自选目录与最终文件路径均做归一：去首尾空白、Windows 下 `canonicalize` 父目录以还原真实大小写（复用 `business::normalize_business_path` 的父目录归一思路），并剔除 `.`/`..` 词法。
- 禁止将文件名注入目录选择（目录选择器仅返回目录，不含文件名）；最终文件路径为 `dir.join(filename)`。

## 4. 异常与降级

| 场景 | 处理 |
|------|------|
| 用户在目录选择器中点"取消" | `open()` 返回 `null`，不改目录，无提示 |
| 自选目录不存在 | 后端 `create_dir_all` 尝试创建；创建失败则报错 |
| 目录不可写（如 `C:\Program Files`） | `atomic_write` 失败 → 前端捕获 → Toast `error` + 自动 **Blob 下载降级**（用后端返回或前端重拉的 JSON 文本走 `<a download>`） |
| 磁盘空间不足 | 同"目录不可写"的降级路径 |
| 文件名冲突（同秒二次导出） | 后缀加 `-1` / `-2` 递增，或在秒级后追加毫秒；首版可在文件名中加入毫秒 `SSS` 以降低冲突率 |
| 后端未升级/插件缺失 | 选择按钮置灰并 tooltip"当前版本不支持文件夹选择，已使用默认目录"（可选） |

## 5. 持久化

- **Key：** `localStorage` → `pmf:exportDir`（字符串，绝对路径）。
- **写入时机：** 用户通过目录选择器确认后立即写入；导出成功不重复写。
- **读取时机：** `LibraryDialog` 挂载时读取；若为空则请求后端 `db_get_default_export_dir` 获取默认绝对路径用于展示。
- **清除：** 浏览器"清除站点数据"会清掉，届时回落默认；不提供专门的"清除记忆"按钮，重新选一次即覆盖。

---

## 6. 与现有能力的协同

- 导出内容与 `LibraryDialog` 现有 `Blob 下载` 同源（`export_library` 的 `dimensions/modules/rules/tags` 过滤 `is_deleted=0`），仅落盘位置变化；
- 不影响 `LibraryDialog` 的导入区（`skip/overwrite` + `<input type=file>`）；
- "打开文件夹"复用 `tauri-plugin-opener` 的 `open(path)` / `reveal` 能力（如可用），否则退化为仅展示路径。
