# Need02 · 诊断与缺口分析 — 词库导出落盘与文件夹自选

> **分支：** `tauri`

## 1. 需求复述

> 在前端右下角词库入口（`StatusBar` → `LibraryDialog`）的"导出 JSON"按钮旁，增加**输出路径选择**能力：
>
> - 用户可通过 **Windows 原生文件夹选择器**自选一个目标文件夹；
> - 若用户未自选，则**默认落盘到 exe 所在目录下的 `data/output/`**；
> - 导出产物为 `pmf-library-*.json` 的标准词库 JSON（与现有 `pmf-library` 格式一致）。

---

## 2. 现有导出链路盘点

### 2.1 入口与 UI

- **入口：** `App.vue:293` → `StatusBar.vue:46-54`（右下角 `📚 词库` 按钮 `data-testid="library-toggle"`）→ `LibraryDialog.vue`
- **形态：** `LibraryDialog.vue:93-98` 的导出区仅有一个按钮 `data-testid="library-export-btn"`，文案"导出词库 JSON"，点击触发 `onExport()`

### 2.2 前端实现（`LibraryDialog.vue:24-46`）

```ts
const json = await dbExportLibrary() // path=null
const blob = new Blob([json], { type: 'application/json' })
const url = URL.createObjectURL(blob)
// <a download="pmf-library-YYYYMMDD-HHmmss.json"> 自动下载（浏览器下载目录）
```

- **特点：** 纯前端 `Blob + <a download>`，不经过 Rust 落盘。文件名在前端用 `Date` 拼装。
- **优缺点：** 无需文件系统权限；但产物进的是**浏览器/系统下载目录**，而非 exe 旁的 `data/`。无法让用户自选落盘目录，也无法满足"默认到 `data/output/`"的诉求。

### 2.3 后端能力（`src-tauri/src/commands/db.rs:1826-1836`）

```rust
#[tauri::command]
pub fn db_export_library(app: AppHandle, path: Option<String>) -> Result<String, String> {
    let payload = export_library(&conn)?;
    let json = serde_json::to_string_pretty(&payload)?;
    if let Some(p) = path.filter(|s| !s.trim().is_empty()) {
        atomic_write(&p, json.as_bytes())?; // 已支持原子写盘
    }
    Ok(json)
}
```

- **已具备：** `path: Option<String>` — 为空则仅返回 JSON 文本；非空则**原子写盘**后再返回 JSON。`atomic_write` 为"写临时文件再 rename"（见 `db.rs:1208-1215`），可避免半截文件。
- **未被前端使用：** `src/lib/db.ts:424-426` 的 `dbExportLibrary(path?)` 已声明可选 `path` 参数，但 `LibraryDialog` 始终以 `path=null` 调用。
- **配套的 `data_dir_for`：** `migration.rs:90-106` 通过 `std::env::current_exe().parent() / "data"` 解析 exe 旁的 `data/`，Windows/macOS/Linux 均可靠（刻意不用 `app.path().executable_dir()` 以规避其在 Windows 上恒为 `Err` 的问题）。

### 2.4 能力/配置缺口

| 项 | 现状 | 缺口 |
|----|------|------|
| 文件夹选择器 | 未集成 `@tauri-apps/plugin-dialog`；`Cargo.toml` 无 `tauri-plugin-dialog`；`capabilities/default.json` 仅有 `core:default` + `opener:default` | 无法弹出 Windows 原生目录选择对话框 |
| 默认输出目录 `data/output` | `migration::data_dir_for` 能算出 `data/`，但没有 `data/output/` 的创建与解析逻辑 | 首次导出若目录不存在会写失败 |
| 前端路径 UI | `LibraryDialog` 无路径展示、选择、记忆、错误态 | 无法让用户感知/选择落盘位置 |
| 落盘后反馈 | 仅 Toast "词库已导出为 JSON"，无路径、无"打开所在文件夹" | 用户找不到文件 |
| 持久化 | 无对用户自选目录的记忆 | 每次都要重选 |

### 2.5 结论判定

| 能力 | 是否存在 | 是否覆盖本题 |
|------|----------|--------------|
| 导出词库 JSON（Blob 下载） | ✅ 已有（`LibraryDialog` + `db_export_library` path=null） | ⚠️ 功能可用，但不满足"自选文件夹 + 默认 data/output 落盘" |
| 后端原子写盘 | ✅ 已有（`atomic_write`） | ⚠️ 已具备但未被前端调用 |
| **Windows 文件夹选择器** | **❌ 缺失** | **本次新增** |
| **默认目录 `exe/data/output/` 的解析与自动创建** | **❌ 缺失** | **本次新增** |
| **导出区"路径选择 + 落盘"闭环** | **❌ 缺失** | **本次新增** |

> **诊断结论：后端已具备"给定路径即落盘"的能力，前端缺少"让用户选到路径、并把路径传给后端"的完整链路；同时缺默认目录的约定与目录选择器的插件集成。**

## 3. 约束与复用

- **存储约束：** 导出读取的是已过滤 `is_deleted=0` 的 `dimensions / modules / rules / tags`（`db.rs: export_library`），与现有导入/校验口径一致。
- **路径基座复用：** 复用 `migration::data_dir_for` 解析 `exe/data`，再在其下拼 `output`，与 `Default.db / PromptDataBase.db` 的选址同源。
- **原子写复用：** 直接复用 `db.rs: atomic_write`，不在 JS 侧做 `fs.writeFile`。
- **invoke 键名约束：** Tauri v2 默认 camelCase（`pitfalls/01-invoke-arg-case.md`），新增参数 `dir`/`path` 等需用 camelCase。
- **权限模型：** Tauri v2 的 `capabilities/default.json` 按窗口授权，需为 `dialog` / `opener` / `path` 等显式加权限。
