# 03 — IR 中间表示与数据契约

> 本文档为对码的唯一口径。所有 `invoke` 键为 **camelCase**（见 `docs/pitfalls/01-invoke-arg-case.md`），DTO 为 `serde(rename_all="camelCase")`，错误以 `Result<T, String>` 透出为 `String`。实现与本文冲突时以本文为准。

---

## 1. IR v2 定义（TypeScript，唯一口径）

`src/engine/models.ts` 在保留现有字段的前提下增补（**不改旧字段名、不改 `hash()` 口径**）：

```ts
// ---- 既有（保持不动） ----
export interface IRSegment {
  dimensionKey: string
  text: string
  weight: number
  sourceModuleId: string
}

// ---- 新增：结构化冲突发现 ----
export type RuleType = 'mutex' | 'requires' | 'excludes' | 'limit' | 'isolated'
export type FindingSeverity = 'error' | 'warning'

export interface FindingFix {
  /** 建议移除的 segment 下标（指向 draft.segments 索引，应用时需按快照解析） */
  removeIndexes: number[]
  /** 保留的 segment 下标（用于展示“将保留…”，可为空） */
  keepIndexes: number[]
  /** 人话解释，如 “将移除上装/下装，保留全身套装” */
  reason: string
}

export interface Finding {
  ruleId: string
  ruleName: string
  type: RuleType
  severity: FindingSeverity
  message: string
  /** 涉及的 segment 下标 */
  involvedIndexes: number[]
  /** 涉及的模块 id（快照可得即填，否则为空数组） */
  involvedModuleIds: string[]
  /** 为空表示该冲突无一键修复，只能手动改/忽略 */
  fix: FindingFix | null
  /** 用户手动忽略后由编辑器填入，引擎不消费 */
  ignored?: boolean
}

export class PromptIR {
  segments: IRSegment[]
  warnings: string[]          // legacy：保留，由 findings 映射生成，保证老 UI 不破
  findings: Finding[]         // 新增：结构化结论，默认 []
  version: 2                  // 新增：快照版本，老快照缺省视为 1
  constructor(segments = [], warnings = [], findings = [], version = 2) { ... }
  hash(): string              // 口径不变：md5("dim:text:w(1dp)" join "|")，不含 findings
  toJSON() { return { segments, warnings, findings, version } }
}
```

**字段语义铁律**：

- `text` 恒为 `contentEn` 快照（英文原文），中文只出现在 `displayName`，编辑器内改 `text` 即改英文（见 05 §2.2 守卫）。
- `weight` 恒为生效权重（已合并 `weightOverride`），`hash()` 取 1 位小数。
- `warnings` 为 `findings.map(f => f.message)` 的去重投影，供老 UI（`BatchCard` 警告行、`PreviewDialog` badge）零改动消费；新 UI 优先读 `findings`。
- `ignored` 只存在于编辑器内存 `draft`，**不落盘**（落盘即代表接受当前段表，无需记忽略）。

## 2. Rule DTO（前后端同构）

```ts
export interface Rule {
  id: string
  name: string
  type: RuleType
  sourceDimensionId: string | null   // 维度级：维度 id（Dimension.id，如 dim_05）
  sourceModuleId: string | null      // 条目级：模块 id（Module.id），为空表示该维度全部
  sourceKeyword: string | null       // 关键词模式：contentEn 含此串即命中（转正 R02/R03 用）
  targetDimensionId: string | null
  targetModuleId: string | null
  targetKeyword: string | null
  /** 人话模板，支持 {source} {target} 占位，如 “已选{source}，{target}将自动忽略” */
  message: string
  isEnabled: boolean
}
```

Rust 侧（`src-tauri/src/commands/rules.rs`，`schema.sql` 不新增列，`sourceKeyword/targetKeyword` 复用既有 `message` 以外的**内存派生**——见 §5 说明）：

> 注意：`schema.sql` 的 `rules` 表**没有 keyword 列**。首版不做迁移，关键词模式以前端 `ruleEngine` 的内置转正规则 + `source_module_id/target_module_id` 为空即“维度全部”的语义实现；`RuleDto.sourceKeyword/targetKeyword` 为**可选回填字段**（后端置 `None`，前端对三条种子规则在内存中补齐，见 04 §6）。若后续需要持久化关键词，再以迁移补列（本期明确不做）。

## 3. 五类规则语义速览（详见 04）

| type | 含义 | 触发条件 | 默认 severity |
|------|------|----------|---------------|
| `mutex` | 源与目标互斥，二存一 | 两侧均命中 | `warning`（可修复） |
| `requires` | 源要求目标必须存在 | 命中源但缺目标 | `warning`（无一键修复，提示补选） |
| `excludes` | 源排除目标关键词组 | 同 mutex，但目标侧为关键词组 | `warning`（可修复） |
| `limit` | 同维度段数上限 | 该维度段数超限 | `warning`（无一键修复，提示删减） |
| `isolated` | 源独占：出现即清其他指定维度 | 命中源且有其他段 | `error`（可修复，谨慎文案） |

## 4. 快照落盘格式（`assemblies.prompt_ir`）

```jsonc
{
  "segments": [
    { "dimensionKey": "outfit", "text": "red slip dress", "weight": 1.0, "sourceModuleId": "mod_outfit_03" }
  ],
  "warnings": ["已选全身套装，上装/下装将自动忽略"],
  "findings": [
    {
      "ruleId": "rule_01", "ruleName": "套装互斥", "type": "mutex",
      "severity": "warning", "message": "已选全身套装，上装/下装将自动忽略",
      "involvedIndexes": [0, 1], "involvedModuleIds": ["mod_outfit_03", "mod_top_01"],
      "fix": { "removeIndexes": [1], "keepIndexes": [0], "reason": "将移除上装，保留全身套装" }
    }
  ],
  "version": 2
}
```

- `db_save_assembly / db_save_assembly_from_ir` **不改签名**，仅要求调用方传入的 `ir_json` 可含 `findings/version`；后端**原样存储**（`TEXT` 字段，无需解析）。
- 读取时（`db_get_assembly` 等）后端原样返回；前端 `parsePromptIr(json)` 做容错解析（见 §7）。

## 5. 排序口径收敛（D2 缺口）

- 新增 `orderRef: 'dbSortOrder' | 'legacyDimOrder'`（引擎内部常量，前端 `assembly.config` 暂不暴露，由 `ruleEngine/assembly` 自动选择）。
- 求值与拼装排序：优先按 `library.dimensions[].sortOrder`（DB 真源）；若 dimensions 未加载（如批量快照上下文），fallback 到 legacy `DIM_ORDER`（`assembly.ts:30-45` 原样保留）。
- `sortByOrder(items, mode)` 签名不变，内部增加可选第三参 `dimOrderMap?: Record<string, number>`，默认 `undefined` 即走 legacy，保证老单测不破。

## 6. Rust 命令契约（新增文件 `src-tauri/src/commands/rules.rs`）

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct RuleDto {
    pub id: String,
    pub name: String,
    pub r#type: String,                    // mutex|requires|excludes|limit|isolated
    pub sourceDimensionId: Option<String>,
    pub sourceModuleId: Option<String>,
    pub targetDimensionId: Option<String>,
    pub targetModuleId: Option<String>,
    pub message: String,
    pub isEnabled: bool,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct RuleUpsertPayload {
    pub name: String,
    pub r#type: String,
    pub sourceDimensionId: Option<String>,
    pub sourceModuleId: Option<String>,
    pub targetDimensionId: Option<String>,
    pub targetModuleId: Option<String>,
    pub message: String,
    pub isEnabled: bool,
}
```

命令签名（`invoke` 键全 camelCase）：

```rust
#[tauri::command]
pub fn db_list_rules(app: AppHandle, includeDisabled: bool) -> Result<Vec<RuleDto>, String>

#[tauri::command]
pub fn db_create_rule(app: AppHandle, payload: RuleUpsertPayload) -> Result<RuleDto, String>

#[tauri::command]
pub fn db_update_rule(app: AppHandle, id: String, payload: RuleUpsertPayload) -> Result<RuleDto, String>

#[tauri::command]
pub fn db_delete_rule(app: AppHandle, id: String) -> Result<(), String>  // 软删除 is_deleted=1

#[tauri::command]
pub fn db_toggle_rule(app: AppHandle, id: String, isEnabled: bool) -> Result<RuleDto, String>
```

校验与错误前缀（对外透出 `String`，前端做文案映射）：

| 前缀/文案 | 场景 |
|-----------|------|
| `规则名称不能为空` | `name.trim()` 空 |
| `规则类型非法` | `type` 不在五类枚举 |
| `规则消息不能为空` | `message.trim()` 空 |
| `源维度不存在或已删除` | `source_dimension_id` 指向缺失/软删维度 |
| `目标维度不存在或已删除` | 同上 |
| `源条目不属于源维度` | `source_module_id.dimension_id ≠ source_dimension_id` |
| `目标条目不属于目标维度` | 同上 |
| `规则不存在或已删除` | `id` 缺失/软删 |
| 事务 | 写操作 `BEGIN IMMEDIATE`，`updated_at = chrono::Utc::now().timestamp()`，异常 `ROLLBACK` |

`lib.rs` 注册：`commands::rules::{db_list_rules, db_create_rule, db_update_rule, db_delete_rule, db_toggle_rule}`；`mod.rs` 加 `pub mod rules;`。

## 7. 前端封装（`src/lib/db.ts` 增补）

```ts
export type RuleDto = { id: string; name: string; type: RuleType; sourceDimensionId: string | null; sourceModuleId: string | null; targetDimensionId: string | null; targetModuleId: string | null; message: string; isEnabled: boolean }
export type RuleUpsertPayload = Omit<RuleDto, 'id'>

export async function dbListRules(includeDisabled = true): Promise<RuleDto[]>
export async function dbCreateRule(payload: RuleUpsertPayload): Promise<RuleDto>
export async function dbUpdateRule(id: string, payload: RuleUpsertPayload): Promise<RuleDto>
export async function dbDeleteRule(id: string): Promise<void>
export async function dbToggleRule(id: string, isEnabled: boolean): Promise<RuleDto>
```

注意 `invoke` 实参形态（防 `pitfalls/01` 重演）：

```ts
invoke('db_update_rule', { id, payload })        // id 与 payload 平铺，非嵌套
invoke('db_toggle_rule', { id, isEnabled })      // 同上
invoke('db_list_rules', { includeDisabled })
```

`parsePromptIr`（新增，`src/lib/irEdit.ts` 或 `src/engine/irCodec.ts` 二选一，推荐后者并由前者复用）：

```ts
export function parsePromptIr(json: string): PromptIR
// - JSON.parse 失败 → 返回空 IR（segments=[]，warnings=['快照解析失败，已置空']）
// - 缺 findings/version → 补 [] / 1（前向兼容老快照）
// - segments 项缺字段 → 丢弃该项并计 warnings（不抛错）
```
