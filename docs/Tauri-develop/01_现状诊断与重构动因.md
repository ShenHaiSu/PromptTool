## 二、性能瓶颈根因（量化）

### 2.1 拖拽卡顿的 4 层根因

| 层 | 机制 | 量化表现 |
|----|------|----------|
| **Tcl 单线程** | 所有几何计算、`<Configure>` 回调、Canvas 重绘串行 | `resize` 每像素触发回调，1600→1200 拖拽触发 ~400 次重排 |
| **递归 pack** | `Paned 30:38:32` + 3×`ScrollableFrame` + 50×`BatchCard(tk.Frame)` 全树 `pack` 重算 `O(n)` | 50 Card 时单次 `_render` ~35ms，拖拽 400次 = 14s CPU |
| **CPU 软渲染** | Tk 无 GPU 图层合成，无脏矩形优化 | `Canvas.create_window` 嵌 Frame 是官方性能黑洞 |
| **Python 胶水** | `wraplength` 自适应、`bind(<Configure>)`、`_render_chips` 全在 Python 层 | `assembly_canvas.py:284` 流式布局每帧 Python 循环 |

### 2.2 实测数据（V2.0, 1600x1080, 50 Card）

| 场景 | 帧率 | CPU | 体感 |
|------|------|-----|------|
| 静态展示 | — | 1% | 正常 |
| 拖拽 sash (左右栏) | **12-15 fps** | 单核 85-100% | **明显卡顿、鼠标跟手延迟 200ms** |
| 拖拽窗口边框 resize | **10-13 fps** | 单核 90% | **布局闪烁、Card 重排掉帧** |
| 批量生成 500条 | 首屏 400ms + 滚动卡顿 | — | `bind_all <MouseWheel>` 劫持，多滚动区互抢 |

> **结论：** 瓶颈在 `tkinter/Tcl/Tk` 引擎本身，上层优化（防抖/节流/减少 Card）最多从 15fps 提到 25fps，无法到 60fps。必须更换渲染引擎。

### 2.3 用户旅程痛点（量化）

| 旅程 | 现状摩擦 | 影响 |
|------|----------|------|
| 选材 | Treeview 列宽 290px，长中文名截断；搜索实时但无虚拟化 | 中 |
| 拼装 | Chips 拖拽 ghost 用 `Toplevel(overrideredirect)` 模拟，无动画 | 高 |
| 预览 | TopBar 已优化为 88px 常驻，但 `Label wraplength` 绑定仍 Python 计算 | 中 |
| 批量 | `ScrollableFrame + Canvas` 分页 50，无虚拟化，500条滚动掉帧 | **高** |
| 视觉 | sv-ttk 已引入，但 Tk 无法做圆角/阴影，仍有 `highlightbackground` 矩形边框 | 中 |

## 三、为什么必须彻底重构（而非修补）

| 方案 | 成本 | 效果 | 决策 |
|------|------|------|------|
| A. tkinter 内优化（防抖+虚拟化+Canvas 优化） | 1-2 天 | 15→25fps，仍卡 | ❌ 治标不治本 |
| B. 换 ttkbootstrap/CustomTkinter | 0.5 天 | 视觉微提升，性能不变 | ❌ 同引擎 |
| C. **Tauri+Vue 重写** | 10 人天 | **60fps + 8MB + 现代交互** | ✅ 根治 |
| D. PySide6(Qt) | 7 天 | 60fps 但包 40MB + 视觉 80分 | 备选 |

**决策依据：** 项目已进入 V2.0 交付期，后续演进（虚拟化到 10k、跨维度拖拽、动画）均需 GPU 合成，tkinter 无法承载。现在重构成本最低（engine 层纯逻辑易翻译），越晚越贵。

## 四、重构收益预期

| 维度 | 收益 |
|------|------|
| 性能 | 拖拽 15→60fps，500条虚拟化首屏 400ms→80ms |
| 体积 | 30MB(Python) → 8-15MB(Tauri) |
| 体验 | 原生 60fps 动画、圆角阴影、明暗无闪烁、虚拟化 |
| 维护 | Vue SFC 单文件组件 + TS 类型约束 vs tkinter 命令式 |
| 生态 | Tailwind/shadcn-vue/dnd-kit/TanStack Virtual 现成 |

---

## 五、风险与非目标

- **非目标（本方案不做）：** 云同步/多用户/服务端 API；MJ/Flux 负面提示词（留 P0-03）；10k 虚拟化首期仍 500 上限。
- **风险：** Tauri 需 Rust 工具链（`cargo`），首次编译慢（~2min），后续增量 <10s；团队需适应 Vue 3 Composition API（1-2 天）。
