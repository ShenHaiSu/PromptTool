## 二、术语

| 术语 | 含义 |
|------|------|
| **维度 / Dimension** | `dimensions` 表的一行，`key` 为机器键（存活行唯一），`nameCn` 为中文名 |
| **片段 / Module** | `modules` 表的一行，`dimension_id` 外键归属维度，`contentEn` 为英文原文 |
| **归档维度** | 迁移时由原维度改名而来，`key = 原key + 随机后缀`，承接全部存量片段 |
| **新生空白维度** | 迁移时原位重建的维度，复用原 `key / nameCn / sortOrder / isMultiSelect`，`modules = 0` |
| **清空** | 删除维度内全部存量 `modules`（软删 `is_deleted=1`），维度本身保留 |
| **迁移** | 原子地“归档老维度 + 重建空白维度”，模块行零搬运（只改维度行，见 05） |
| **`LIBRARY_CHANGED`** | `src/lib/libraryEvents.ts` 的库变更事件，`library.fetchAll()/scheduleFetch()` 刷新唯一真相源 |

## 三、方案一句话

维度头右键菜单由 4 项扩为 **7 项两组**（功能组：翻译 / 生成 / 启用禁用 / 清空 / 迁移；复制组：复制键名 / 复制中文名），去掉生成项 Emoji；开关复用既有 `onToggleDimension`，清空走“确认→逐条软删→已选联动移除”，迁移走**新 Rust 事务命令 `db_migrate_dimension`**（老维度改名归档 + 原 key 原位重建），全程经 `LIBRARY_CHANGED` 刷新并以 `data-testid="dim-ctx-*"` 可测。

## 五、基线与非目标

- **基线复用**：`DimensionPanel.vue:572-635,903-933` 的菜单骨架、`need05Position.calcMenuPos`、`library`真相源、`dbUpdateDimension/dbSoftDeleteModule/dbCreateDimension`、`DimensionTranslateDialog/DimensionGenerateDialog` 三步壳。
- **非目标**：不做维度删除、不做跨维度单条移动、不做应用内直连 LLM、不改 `contentEn` 语义、不碰 `assembly/template/rules` 表结构；迁移不保留“原维度 id”（原位重建必然换 id，调用方按 key 消费，见 05 §7）。
- **破坏性约束**：`dimensions.key` 存活行唯一（`src-tauri/src/commands/db.rs:421-430` 强校验）；`db_soft_delete_dimension` 要求维度先清空（`db.rs:501-515`），本需求的清空与迁移均与该约束对齐。
