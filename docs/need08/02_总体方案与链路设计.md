# 02 — 总体方案与链路设计

> 结论先行：菜单从 4 项扩为 **7 项、两组一线**；前 3 项保持 need01/need03 语义（翻译 / 生成去 Emoji / 开关），中段为高危组（清空 / 迁移），末段为复制组；开关/清空走既有前端命令复用，迁移走**新 Rust 事务命令**；触发、定位、关闭、刷新四机制沿用既有骨架，只调参数不换架构。

---

## 1. 菜单新结构（定稿）

```
┌ dim-context-menu ────────────────┐
│ ① 批量翻译（中文描述）            │  空维度 disabled
│ ② 片段批量生成                    │  去 ✨，恒可用
│ ③ 禁用维度 / 启用维度（动态）      │  恒可用，复用 onToggleDimension ★新增
│ ───────────── 分隔线 1 ────────── │
│ ④ 清空维度内容…                   │  空维度 disabled，危险色 ★新增
│ ⑤ 迁移维度…                       │  空维度 disabled（空迁无意义） ★新增
│ ───────────── 分隔线 2 ────────── │
│ ⑥ 复制维度键名                    │  恒可用
│ ⑦ 复制维度中文名                  │  恒可用
└──────────────────────────────────┘
```

- `…` 后缀约定：凡打开二次确认/对话框的项加省略号（清空、迁移），与翻译/生成（直接开对话框但为既有项，保持原样不追补）区分；复制项无省略号（直接完成）。
- 分组语义：上组“生产力”（翻译/生成/开关）→ 中组“危险运维”（清空/迁移）→ 下组“复制”。两条分隔线均为 `div.my-1.border-t`，与现状同构。
- 排序理由：翻译/生成不动（保护肌肉记忆与既有测试最小 diff）；开关紧跟生成（高频，首屏可见）；清空/迁移收拢为危险组，避免与复制组混淆。

testid 定稿（`{key}` 为维度 `key`，与现状一致）：

| 项 | testid |
|----|--------|
| 翻译 | `dim-ctx-translate-{key}`（不变） |
| 生成 | `dim-ctx-generate-{key}`（不变，文本去 ✨） |
| 开关 | `dim-ctx-toggle-{key}` |
| 清空 | `dim-ctx-clear-{key}` |
| 迁移 | `dim-ctx-migrate-{key}` |
| 复制键名 | `dim-ctx-copy-key-{key}`（不变） |
| 复制中文名 | `dim-ctx-copy-name-{key}`（不变） |

## 2. 四项诉求的链路

### 2.1 去 Emoji（纯前端文本）

```
右键 → 菜单渲染"片段批量生成"（无✨）→ 其余不动
```

- 改动点仅 `DimensionPanel.vue:928` 一行文本；`MENU_H_EST` 不因此变（见 03 §3 统一调）。

### 2.2 开关（前端复用，无新接口）

```
右键 → 点击"禁用维度/启用维度" → closeContextMenu()
  → onToggleDimension(dim)（既有 214-230：乐观更新 + dbUpdateDimension + emit LIBRARY_CHANGED + toast）
```

- 动态文案：`dim.isEnabled ? '禁用维度' : '启用维度'`；`title` 同步为 `禁用后不参与可控随机` / `启用后恢复参与可控随机`。
- 与 `Ctrl+Click` 双轨：两者调同一函数，注释 `替代原右键菜单` 更新为 `与右键菜单双轨`。

### 2.3 清空（前端编排，多步 invoke，无新 Rust 命令）

```
右键 → 点击"清空维度内容…" → closeContextMenu() → 二次确认框（N + 维度名 + 已选联动数）
  → 乐观快照（modulesByDim + selectedItems）→ 逐条 dbSoftDeleteModule
  → 成功：assembly.removeModule(被清空且已选) + emit LIBRARY_CHANGED + fetchAll + toast
  → 任一步失败：回滚快照 + error toast（详见 04 §3-§4）
```

- 为何不用新 Rust 命令：`db_soft_delete_module` 已是单条原子操作，前端循环 `N` 次在 `N≤500` 量级可接受；且清空语义 = “批量单删”，与逐条删共用同一审计口径。若日后 `N` 常态上千，再下沉为 `db_clear_dimension`（预留，见 06 §5）。

### 2.4 迁移（新 Rust 事务命令，关键路径）

```
右键 → 点击"迁移维度…" → closeContextMenu() → DimensionMigrateDialog（归档key预览 + 影响面）
  → 确认 → invoke db_migrate_dimension({dimensionId}) → 返回 {archive, fresh, moved}
  → assembly.removeModule(属于原维度的已选项) → emit LIBRARY_CHANGED + fetchAll
  → 展开新生维度 + toast（含归档key）
  → 失败：整事务回滚（Rust 侧 ROLLBACK），前端无局部状态需回滚（详见 05）
```

- 为何必须新命令：`db_update_dimension` 不更新 `key` 列（`db.rs:481-495` 的 UPDATE 列表无 `key`），且无事务；前端拼凑“改名+重建”有 key 唯一竞态窗口。详见 05。

## 3. 状态机

```
closed
 ─(右键维度头 @contextmenu.prevent)→ menuOpen{key,pos,dim}
   ├─(选 翻译/生成)→ dialogOpen{translate|generate}（既有 need01/need03，不变）
   ├─(选 开关)→ togglePending → closed（toast + 乐观更新）
   ├─(选 清空…)→ confirmOpen{dim,N,selectedK} ─确认→ clearing{progress} ─成功→ closed
   │                                        └取消/失败→ closed（失败带回滚）
   └─(选 迁移…)→ migrateDialogOpen{dim,archiveKeyPreview,N} ─确认→ migrating ─成功→ closed
                                                            └取消/失败→ closed
 ─(Esc/外部点击/scroll/resize)→ closed（既有 605-635 监听组复用）
```

- 菜单打开时再次右键：关闭旧菜单并在新坐标重开（既有行为，保持）。
- 清空/迁移的确认层与菜单互斥：打开确认即 `closeContextMenu()`，避免双浮层叠加（`z-[70]` 冲突）。

| 交互 | 行为 | 备注 |

| 搜索过滤隐藏维度 | 不可触发 | 不变 |

## 5. 数据流与刷新（统一口径）

- 真相源仍是 `library.dimensions / modulesByDim`（`stores/library.ts:34-53 fetchAll`）；所有写操作后 `emit(LIBRARY_CHANGED, {source:'dimension-panel', op})`，`op` 新增 `toggle-dimension（复用既有 enable/disable-dimension）/ clear-dimension / migrate-dimension`。
- 小库（`total≤200`）`scheduleFetch` 立即同步，大库防抖 10s；清空/迁移后调用 `fetchAll()` 强刷（ bypass 防抖），因涉及维度行增减，防抖视图会错位。
- `panelStore` 展开态：迁移后 `setExpanded(原key, true)`（新生维度沿用原 key，天然保持展开）；清空后保持展开（空态文案“该维度暂无可显示条目”已存在）。
