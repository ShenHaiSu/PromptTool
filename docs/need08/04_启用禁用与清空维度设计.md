# 04 — 启用禁用与清空维度设计

> 结论先行：开关=零新代码（薄包装复用 `onToggleDimension`）；清空=“确认框 + 快照 + 循环软删 + 已选联动 + 失败回滚”，确认层用专用小 Dialog（不用 `window.confirm`），进度可感知，空维度禁用。

---

## 1. 启用/禁用（开关项）

### 1.1 复用链（`DimensionPanel.vue:214-230` 原样）

```ts
async function onToggleDimension(dim: Dimension): Promise<void> {
  const nextEnabled = !dim.isEnabled
  // 乐观更新 library.dimensions[idx] → dbUpdateDimension → emit(LIBRARY_CHANGED, enable/disable-dimension) → toast
  // 失败回滚 prev
}
```

菜单只加薄包装（见 03 §4 `onToggleFromMenu`），要点：

- 文案/可用性见 03 §2；`contextMenu.dim` 可能滞后（菜单打开后维度在别处被切换），点击时以 `library.dimensions` 最新实体为准：

```ts
function onToggleFromMenu(): void {
  const cur = contextMenu.value; if (!cur) return
  const fresh = library.dimensions.find((d) => d.id === cur.dim.id) ?? cur.dim
  closeContextMenu()
  void onToggleDimension(fresh)
}
```

- `op` 复用既有 `enable-dimension / disable-dimension`，不新增事件类型；`Ctrl+Click` 手势保留，注释由“替代原右键菜单”改为“与右键菜单开关项双轨”。
- 维度头 `title` 补丁：`Ctrl+点击可禁用 · 右键更多` → `Ctrl+点击或右键菜单可启用/禁用`（一行动词统一）。

### 1.2 边界

| 场景 | 行为 |
|------|------|
| 禁用含已选项的维度 | 只翻 `isEnabled`，不移出已选（与现状一致；随机链路按 `isEnabled` 过滤，见 `engine/random.ts`） |
| 连续快速点击 | `onToggleDimension` 无防抖，以最后一次为准；乐观更新保证最终一致 |
| 后端失败 | 回滚 `library.dimensions[idx]` + `error` toast（既有逻辑已覆盖） |

## 2. 清空：产品语义（定稿）

- **定义**：删除该维度下全部存量 `modules`（`is_deleted=1` 软删），维度本身（`id/key/name/sortOrder/isEnabled/isMultiSelect`）原样保留。
- **空维度**：菜单项 `disabled` + `title="该维度暂无词条"`（与翻译项同构），杜绝空确认框。
- **非空维度**：点击后打开**专用确认小 Dialog**（非 `window.confirm`，因需展示数量与已选联动数，且 `window.confirm` 在测试/E2E 中难断言）。

确认框内容（定稿）：

```
标题：清空维度「{nameCn} / {key}」？
正文：该维度现有 N 条片段，清空后不可恢复。
     其中 K 条正在“已选”中，将一并移出已选（拼装 IR 同步更新）。
     [x] 我已确认要删除全部 N 条（checkbox，不勾选则确认按钮 disabled）
操作：[取消] [确认清空（N 条）]（destructive，clearing 时 disabled + 文案"清空中… i/N"）
```

- 为何加 checkbox：`N≥1` 即高危，单按钮确认误触率高；checkbox 将“阅读→勾选→确认”三步强制串行，成本低廉且可测（`data-testid="clear-confirm-check / clear-confirm-btn"`）。
- 为何展示 K：让用户预知拼装联动，避免“清空后画布少了一段”的困惑。

## 3. 清空：执行链（前端编排）

前置快照（用于回滚与联动）：

```ts
type ClearSnapshot = {
  dimId: string
  modules: Module[]            // modulesByDim[dimId] 的浅拷贝
  selectedIds: string[]        // 将被联动移除的已选项 id（交集）
  groupedKey: string           // modulesByDim 中的实际 key（dim.id 或 dim.key，复用 onToggleModule:238 的判定）
}
```

步骤（`doClearDimension(dim)`）：

1. `snapshot()`：取 `list = modulesByDim[dim.id] ?? []`；若 `length===0` 直接关闭（防御性，菜单已禁用但数据可能并发变更）。
2. `clearing=true`，逐条 `await dbSoftDeleteModule(m.id)`，每完成一条更新进度 `i/N`（`N>20` 时才有感知，小维度一闪而过属正常）。
3. 每成功一条，同步从 `library.modulesByDim[groupedKey]` 移除该条（乐观递减，避免最后一次性闪变）；**不逐条 `emit`**，全部完成后统一一次。
4. 完成后：`for (id of snapshot.selectedIds) assembly.removeModule(id)`（复用 `assembly.removeModule`，与 `onToggleModule:234-236 / onDisableSelected:280` 同构）；`emit(LIBRARY_CHANGED, {op:'clear-dimension'})`；`await library.fetchAll()` 强刷；`push('已清空维度「X」，删除 N 条' + (K?`，移出已选 K 条`:''), 'success')`。
5. 关闭确认框，`clearing=false`。

已选联动判定：`selectedIds = assembly.selectedItems.filter(it => it.module.dimensionId===dim.id || snapshot.modules.some(m=>m.id===it.module.id)).map(...)`（双条件是防御 `dimensionId` 快照滞后，见 `onDisableSelected:273-279` 取 fresh 的先例）。

## 4. 清空：失败与回滚

- **单条失败**（`dbSoftDeleteModule` 抛错）：立即停止后续条（避免半清空后继续扩大），用快照恢复 `library.modulesByDim[groupedKey] = snapshot.modules` 并 `library.modulesByDim = {...}` 触发响应式；已移出的已选项**不自动恢复**（因失败时尚未执行第 4 步联动，顺序保证）；`push('清空中断：已删除 i 条，剩余已恢复显示，请重试…', 'error')` + `emit(LIBRARY_CHANGED, {op:'clear-dimension-failed'})` 触发一次 `fetchAll` 以与后端对齐（后端已删 `i` 条是事实，前端快照回滚仅为避免显示错乱，`fetchAll` 后以后端为准并如实 toast）。
  - 诚实性原则：不谎称“已回滚”， toast 必须说明“已删除 i 条”，用户可重试清空剩余。
- **fetchAll 失败**：保留乐观空列表 + `warning` toast（`library.fetchAll` 内部已吞错保留旧值，`stores/library.ts:46-48`），不二次回滚。
- **并发**：清空进行中该维度菜单项视为禁用（`clearing` 全局一次只允许一个维度清空；二次点击直接 `return` 并 toast `正在清空中…`）。

性能上限：`N≤500` 前端循环可接受（每次 `invoke` 约数 ms）；若实测 `N=500` 超过 5s，后续迭代下沉为 Rust `db_clear_dimension`（见 06 §5 预留，不在本期）。
