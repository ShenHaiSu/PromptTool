# 02 总体架构与技术选型（纯 Web）

## 1. 架构一句话

```
Vue 3 SPA（静态托管） + IndexedDB（唯一业务存储） + localStorage（仅偏好）
+ 文件导出/导入（备份/迁移唯一通道） — 无后端 API、无鉴权、无遥测
```

服务端只提供 `dist/` 静态文件（任何静态托管均可），不接收、不存储业务数据。

## 2. 技术选型

- 前端：沿用 `Vue 3.5 + Pinia + Vite 6 + Tailwind 3 + shadcn-vue + TanStack Virtual`，不换栈，复用全部组件/stores/engine/composables。
- IndexedDB 访问：二选一（本手册默认 **原生 + 轻量封装**，理由：零新增依赖、与现有 `db.ts` 签名对齐最容易）：
  - A（默认）：`src/lib/idb.ts` 自研 Promise 封装（open/upgrade/tx/store），约 150 行，无依赖。
  - B（可选）：`dexie@4`，如团队更看重索引/查询可读性。切换不影响上层（适配层签名不变）。
- 唯一 ID：沿用现有 `crypto.randomUUID()`（Tauri/Rust 侧也是字符串 id），不动。
- 时间：`Date.now()` 整数毫秒，沿用 SQLite `created_at/updated_at` 语义。
- 文件：导出用 `Blob + <a download>`；导入用 `input[type=file] + File.text()`（主路径），`showOpenFilePicker/showSaveFilePicker` 仅作渐进增强。
- CSV：直接复用 `src/lib/export.ts`（已是前端 Blob 实现），删除 Rust `db_export_csv` 调用分支。

## 3. 与 tauri 分支的对应关系

- `src/lib/db.ts`（invoke）→ `src/lib/db.idb.ts`（IndexedDB），**函数名/参数/返回值保持一致**，stores/components 只改 import。
- `src-tauri/` 在 `web-pure` 分支保留但不再构建；`package.json` 删除 `@tauri-apps/*` 依赖与 `tauri` script。
- `dbRegistry/business/meta/migration` 相关 UI 下线（见 06），`temp_carry` 改为 `localStorage` 或 IDB 单键 store。

## 4. 非目标

- 不做多端同步、不做账号系统、不做服务端搜索、不做 PWA 离线缓存（可选见 09）。
- 不兼容旧 exe 旁 `data/pmf.db` 的自动迁移；旧数据走“Tauri 版导出 → Web 版导入”。
