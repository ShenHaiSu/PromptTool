## 1. 总体选型

- **不新增表、不改 schema：** 仅写 `modules`，复用 `dimensions` 外键与现有索引 `idx_modules_dimension`。
- **前后端职责切分：**
  - 前端负责“行解析 → 去重预览 → 统计” 的即时反馈（纯本地，无 invoke）；
  - 后端负责“权威去重 → 事务写入 → 报告” 的一致性保障。
- **单事务批量：** 后端 1 次 `BEGIN IMMEDIATE` 完成 N 行（N≤500），避免 N 次往返；单行失败仅记录 `errors/warnings`，不回滚已成功行（与 `segment.rs:206-378` 的事务内逐行容错一致）。
- **invoke 键名：** 严格 camelCase（`dimId/contentEn/displayName/isNsfw`），遵循 `docs/pitfalls/01-invoke-arg-case.md`。

## 3. 前端 — 行解析库 `moduleBatch.ts`

### 3.1 导出类型

```ts
export type BatchLineStatus =
  | 'ok'               // 有效，可入库
  | 'empty'            // 空行，已忽略
  | 'duplicate_in_batch' // 批次内重复（第 2 次及以后出现）
  | 'too_long'         // 超 500 字符，已截断（仍可入库，带 warning）
  | 'invalid'          // 仅保留扩展位，首版不用

export type ParsedBatchLine = {
  lineNo: number        // 原始行号（1-based，含空行）
  raw: string           // 原始行（含首尾空白）
  contentEn: string     // trim 后内容（too_long 时已截断至 500）
  displayName: string   // 派生：contentEn.slice(0, 20)
  status: BatchLineStatus
  warnings: string[]
}

export type ParsedBatch = {
  lines: ParsedBatchLine[]  // 与输入行一一对应（含 empty，便于预览定位）
  stats: {
    total: number           // 输入总行数（含空行）
    valid: number           // status === 'ok' | 'too_long' 的行数（可提交数）
    empty: number
    duplicateInBatch: number
    tooLong: number
  }
}

export type BatchOptions = {
  maxLines?: number   // 默认 500
  maxLen?: number     // 默认 500
  dedupCaseSensitive?: boolean // 默认 true（与后端口径一致）
}
```

### 3.2 核心函数

```ts
export function parseBatchText(text: string, opts?: BatchOptions): ParsedBatch
export function toBatchItems(parsed: ParsedBatch): Array<{ contentEn: string; displayName: string }>
// 仅挑 status === 'ok' | 'too_long' 的行，转为提交 payload
export function filterValidItems(parsed: ParsedBatch): Array<{ contentEn: string; displayName: string }>
```

### 3.3 解析规则（与 `02 §3` 对齐）

1. 按 `/\r?\n/` 切行，保留行号；
2. `raw.trim() === ''` → `empty`；
3. `contentEn.length > maxLen` → `too_long`，`warnings.push('超长已截断至 500')`，`contentEn = contentEn.slice(0, 500)`；
4. 批次内去重：维护 `Map<contentEn, firstIndex>`（大小写敏感），第 2 次出现起标记 `duplicate_in_batch`；
5. 超 `maxLines`（默认 500）截断，`warnings` 透出“已截断，剩余请分批”；
6. `displayName` 统一派生 `contentEn.slice(0, 20)`，超长截断逻辑与 `segment.rs:291` 一致。

> 校验仅做前端预览，后端仍做二次校验与截断（权威）。

### 5.3 处理流程（`batch_create_modules_into`）

```
1. 校验 dimId 非空；SELECT id FROM dimensions WHERE id=? AND is_deleted=0，不存在则 Err("维度不存在或已删除")
2. 校验 mode ∈ {skip, overwrite}，否则 Err
3. 归一化 weight：Option<f64> → clamp 0.5~2.0，round(×10)/10；非 finite 则 warning 并重置 1.0
4. 统计 totalRequested = items.len()
5. 批次内去重：HashSet<String> seen（contentEn 精确匹配，大小写敏感），重复则 duplicateInBatch++，按 mode 视为"已存在"处理或跳过（见 6）
6. BEGIN IMMEDIATE
   for (idx, item) in items.iter().enumerate() {
     contentEn = item.contentEn.trim()
     if empty → emptyIgnored++，continue
     if len > 500 → warnings.push("第 {idx} 行超长已截断")，truncated++，contentEn = chars().take(500).collect()
     displayName = item.displayName.filter(trim非空).unwrap_or(contentEn.chars().take(20).collect())
     weight = item.weight.or(payload.weight).unwrap_or(1.0) → clamp/round
     isNsfw = item.isNsfw.or(payload.isNsfw).unwrap_or(false)
     // 去重命中
     hit = find_module_hit(conn, &ModuleDto{ dimension_id: dimId, content_en: contentEn, ... }, &dimId)?
     match hit {
       Some(hitId) if mode==overwrite → UPDATE modules SET content_en/display_name/weight/is_nsfw/notes/updated_at；modulesUpdated++
       Some(_) /*skip*/           → modulesSkipped++
       None                       → INSERT modules (id=uuid, dimension_id, content_en, display_name, weight, is_nsfw, is_enabled=1, is_deleted=0)；modulesCreated++
     }
   }
   COMMIT
7. 返回 BatchCreateReport
```

- 批次内重复的第 2 次出现：此时 `seen` 已含该 `contentEn`，若此前已 `INSERT`，则 `find_module_hit` 会命中刚插入的行，效果等同于去重；`duplicateInBatch` 计数独立于 `modulesSkipped`，便于前端展示。
- 单行 `INSERT/UPDATE` 失败：`errors.push` 并继续，不中断事务（与 `segment.rs:238-360` 的逐行容错一致）。
- 事务失败（`BEGIN` 失败等）：`ROLLBACK` 并 `Err`。

### 5.4 文本变体 `db_batch_create_modules_text`

- 服务端按 `/\r?\n/` 切行，`trim` 后空行计 `emptyIgnored`，其余每行构 `BatchCreateItem{ contentEn: line }`，复用同一 `batch_create_modules_into`。

## 6. 去重与幂等语义

| 场景 | `skip` | `overwrite` |
|------|--------|-------------|
| 同维度 `contentEn` 已存在 | 跳过，不更新任何字段；`modulesSkipped++` | 覆盖更新 `displayName/weight/isNsfw/notes/updatedAt`；`modulesUpdated++` |
| 批次内重复（第 2 次） | 视为已存在，跳过 | 视为已存在，覆盖（等价于更新第 1 次刚写入的行） |
| 不同维度同 `contentEn` | 不视为重复，各自独立 | 同左 |

> 大小写敏感：`'White Shirt' ≠ 'white shirt'`，与现有 `find_module_hit` 的 `WHERE content_en=?` 语义一致；如需不敏感，后续可扩展 `COLLATE NOCASE`。

---

## 7. 错误与限流

- `dimId` 非法 / 维度不存在 → 直接 `Err`，前端 `push('创建失败: ...', 'error')`；
- `items.length === 0` → `Err("无有效内容")`；
- `items.length > 500` → 后端截取前 500，`warnings.push("已截断至 500 行，剩余请分批")`，`truncated` 计数；
- 单行 `contentEn` 为空 → `emptyIgnored++`，不计入 `valid`；
- 单行 DB 异常 → `errors.push("第 N 行 ...")`，继续处理后续行。

---

## 8. 事件与刷新契约

- 成功后前端：`emit(LIBRARY_CHANGED, { source: 'module-batch', op: 'batch-create-modules' })` → `App.vue:86` 的 `handleLibraryChanged` 触发 `dimensionPanelRef.refresh()` + `library.scheduleFetch()`；
- 乐观更新：无需，前端等待 `report` 后刷新即可；500 行事务通常 <200ms。

## 9. 安全与兼容

- 仅写 `modules`，不触 `assembly_items/template_items`，无需 `dimensionKey` 非空校验（`modules` 无此列）；
- `weight` 钳制 `0.5~2.0`，`displayName` 截断 500，前端与后端双重保障；
- 旧数据不受影响；新增命令为增量，不破坏现有 `db_create_module` 单条路径。
