# 08 · 施工顺序与风险回滚

> 分 4 批，每批独立可验收、可回滚。预计触点文件 12 个，无第三方依赖新增。

## 1. 顺序（后批依赖前批）

| 批 | 内容 | 主文件 | 开关 |
|----|------|--------|------|
| B1 | 文件名预占位+反查（02）+ 纯函数单测 | `queue.rs` 字段与 `stem_for/normalize`；`ImageTaskCard/DetailDialog`；`ImageQueuePanel` 搜索框 | 无（字段 Option 自兼容） |
| B2 | 自动备料 top-up（01） | `scheduler_loop` 钩子 + `refillInflight` 合并 | `loopEnabled` 即开关，关=现状 |
| B3 | 主库 ledger + 看板（03） | `meta_schema.sql` + worker 落账 + stats 三命令 + `StatsReportDialog` 双入口 | 看板只读，落账 `INSERT OR IGNORE` |
| B4 | 单发 Tab（04） | `App.vue` Tabs + `SingleShotPanel` + preview/save 两命令（复用 B1/B3 命名与落账） | 面板按需挂载，不影响前两 Tab |

B1→B2 可并行开工（同 `queue.rs` 不同函数，合码注意锁序）；B3 落账点需等 B1 文件名终值；B4 必须最后（复用 B1 命名 + B3 落账）。

## 2. 风险表

| 风险 | 对策 |
|------|------|
| top-up hungry 洪泛（高并发连发） | 800ms 节流 + `want` 钳制 + 前端在途合并；800ms 窗口验收 A2 豁免 |
| seq 重号（同秒并发入队） | 占位在 `tasks/order` 锁内 `next_day_seq` 原子分配；落盘仍过 `unique_filename_in` |
| 预占 stem 与实际名不一致 | 卡片 `filename ?? stem` 双显；反查同时比两字段（02 §2.1） |
| ledger 写拖慢 worker | 落账放 `emit_task` 后台 `tokio::spawn`，失败只 `eprintln` 不改任务终态 |
| base64 大图内存 | 单发一次只留一张预览；生成中禁用按钮；不进 Pinia/store |
| 老库升级 | `IF NOT EXISTS` + `task_id UNIQUE` + 字段全 `default`；回滚=删新代码，老 ledger 表留空无害 |

## 3. 回滚

- B1/B2：回退 `queue.rs` 钩子与前端行即回现状（内存字段消失不影响落盘文件）。
- B3：停调 stats Dialog 即回；ledger 表保留（只增不查无影响）。
- B4：摘掉 `center-tab-single` 按钮与两命令，前两 Tab 零感知。
