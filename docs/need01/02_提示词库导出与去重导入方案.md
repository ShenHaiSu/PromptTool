# 02 提示词库导出与去重导入方案

> **关联代码：** `src-tauri/src/commands/db.rs`（全部 DTO 与命令）· `src-tauri/src/commands/migration.rs:408-473`（`db_import_legacy_db`，保留不变）· `src/lib/db.ts`（TS invoke 封装）· `src/engine/models.ts`（领域模型）· `src/lib/export.ts`（现有 CSV 导出）
> **目标：** 将"词库"（dimensions + modules + rules 等）导出为可移植 JSON；导入时**按业务键去重**合并进当前库，重复执行不产生重复数据。

---

## 一、现状分析

当前系统**已具备**的 IO 能力与**缺失**部分：

| 能力 | 现状 | 位置 |
|------|------|------|
| 拼装结果导出 CSV | ✅ 已有（`序号/提示词/维度构成/冲突警告`） | `src/lib/export.ts` + `db_export_csv` |
| 旧库整体导入 | ✅ 已有（ATTACH + INSERT OR IGNORE，按主键 id 去重） | `migration.rs::db_import_legacy_db` |
| **词库导出（dimensions+modules）** | ❌ 缺失 | — |
| **词库去重导入（JSON/CSV）** | ❌ 缺失 | — |

> 现有 `db_import_legacy_db` 的去重仅按 **主键 `id`**（`INSERT OR IGNORE`），跨机器迁移时 id 不同会重复导入，不满足"去重导入"要求。本方案新增**按业务键去重**的导入器，两者并存。

### 1.1 现有领域模型（导出/导入的数据载体）

```ts
// src/engine/models.ts
interface Dimension { id: string; key: string; nameCn: string; nameEn: string;
  sortOrder: number; isMultiSelect: boolean; isEnabled: boolean; icon?: string | null }
interface Module { id: string; dimensionId: string; contentEn: string; displayName: string;
  weight: number; isEnabled: boolean; isNsfw: boolean; usageCount: number;
  exampleImage?: string | null; notes?: string | null; dimensionKey?: string | null }

```

`rules` 表（`id, name, type, source_dimension_id, source_module_id, target_dimension_id, target_module_id, message, is_enabled`）为预置冲突规则，一并纳入词库导出。

## 二、导出格式设计（统一 JSON）

### 2.1 文件格式：`pmf-library.json`

```jsonc
{
  "format": "pmf-library",
  "formatVersion": 1,
  "exportedAt": 1756000000,           // unix 秒
  "appVersion": "3.0.0",
  "schemaVersion": 1,                  // 与 schema.sql 版本对应
  "dimensions": [
    { "id": "dim_01", "key": "body", "nameCn": "模特身材特点", "nameEn": "Body",
      "sortOrder": 4, "isMultiSelect": 0, "isEnabled": 1, "icon": null }
  ],
  "modules": [
    { "id": "mod_body_01", "dimensionId": "dim_01", "dimensionKey": "body",
      "contentEn": "slim fit", "displayName": "修身", "weight": 1.0,
      "isEnabled": 1, "isNsfw": 0, "usageCount": 12,
      "exampleImage": null, "notes": null }
  ],
  "rules": [
    { "id": "rule_01", "name": "套装互斥", "type": "mutex",
      "sourceDimensionId": "dim_05", "sourceModuleId": null,
      "targetDimensionId": "dim_03", "targetModuleId": null,
      "message": "已选全身套装，上装/下装将自动忽略", "isEnabled": 1 }
  ],
  "tags": [],
  "counts": { "dimensions": 14, "modules": 311, "rules": 3, "tags": 0 }
}
```

**字段规则：**
- `modules` 同时携带 `dimensionId` 与 `dimensionKey` 冗余：导入时**优先用 `dimensionKey` 定位维度**（key 是业务唯一键，跨机器稳定），`dimensionId` 仅作回退与完整性校验。
- `isMultiSelect`、`isEnabled`、`isNsfw` 用 **0/1 整数**（与 SQLite 存储一致），导入时原样映射；反映射在 DTO 层完成（`i64 != 0`）。
- `createdAt/updatedAt/usageCount` 等运行态字段：`usageCount` 导出但不作为去重依据，导入时可选择重置。
- 时间戳、`counts` 仅供人读与校验，导入时忽略。

### 2.2 文件命名约定

```
pmf-library-YYYYMMDD-HHmmss.json     # 自动导出默认名
```

## 三、导出实现（Rust）

### 3.1 新增命令 `db_export_library`

**文件：** `src-tauri/src/commands/db.rs`

```rust
#[derive(Debug, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct LibraryExportPayload {
    pub format: String,
    pub format_version: i64,
    pub exported_at: i64,
    pub app_version: String,
    pub schema_version: i64,
    pub dimensions: Vec<DimensionDto>,
    pub modules: Vec<ModuleDto>,
    pub rules: Vec<RuleDto>,
    pub tags: Vec<TagDto>,
}

#[tauri::command]
pub fn db_export_library(app: AppHandle, path: String) -> Result<LibraryExportPayload, String> {
    let conn = open_conn(&app)?;
    // 1) 读全部 dimension（含 is_deleted=0）
    // 2) 读全部 module（含 is_deleted=0，JOIN dimensions 取 dimension_key）
    // 3) 读全部 rule（含 is_deleted=0）
    // 4) 读全部 tag / module_tags
    // 5) 组装 payload → serde_json::to_vec_pretty → std::fs::write(path)
    // 返回 payload（前端可回显统计）
}
```

**关键点：**
- 只导出 `is_deleted=0` 的行（软删除数据不导出）。
- `DimensionDto`/`ModuleDto` 已有字段，`RuleDto`/`TagDto` 为新增 DTO（见 5.1），字段命名与 schema 列一一对应。
- 写文件用**原子写**：先写 `path.tmp` 再 `rename`，避免写入中断产生半个文件。
- 若忽略 `path` 参数可返回 JSON 字符串给前端自行保存（`invoke` 返回 `String`）。**推荐双模式**：`path` 为空 → 返回 JSON 字符串（前端 Blob 下载）；`path` 非空 → 直接写磁盘文件。

## 四、去重导入算法（核心）

### 4.1 去重键定义

| 实体 | 主键（表） | **去重业务键（导入判定）** |
|------|-----------|---------------------------|
| dimensions | `id` | `key`（UNIQUE，业务唯一） |
| modules | `id` | **(a) `id` 命中** 或 **(b) `dimensionKey + contentEn` 精确匹配** |
| rules | `id` | `id` 命中 或 `(name + type + source/target)` 全部匹配 |
| tags | `id` | `name`（UNIQUE） |

> **modules 去重逻辑说明：** 同库重导（id 一致）用 (a) 判定，直接命中；跨库/跨机器导入（id 是新 uuid）用 (b) 判定——`contentEn` 在**同一维度下**完全相同即视为同一词条，吸收换机、重建带来的 id 漂移。

### 4.2 合并算法（伪代码）

```
# ===== 阶段 1：维度 =====
dimIdMap = {}   # 文件 dimension.id → 库 dimension.id
for fdim in payload.dimensions:
    row = SELECT * FROM dimensions WHERE key = fdim.key AND is_deleted = 0
    if row 存在:
        if mode == 'overwrite':
            UPDATE dimensions SET name_cn/name_en/sort_order/is_multi_select/is_enabled/icon
            WHERE id = row.id                     # 保留库内 id，不覆盖 key
            dims_updated += 1
        else:
            dims_skipped += 1
        dimIdMap[fdim.id] = row.id
    else:
        newId = (fdim.id 未被占用) ? fdim.id : uuid_v4()   # 尽量保留文件 id
        INSERT INTO dimensions (...) VALUES (newId, ...)
        dims_created += 1
        dimIdMap[fdim.id] = newId

# ===== 阶段 2：模块 =====
for fmod in payload.modules:
    # 维度定位：优先 dimensionKey → dimIdMap → 报错跳过
    dimKey = fmod.dimensionKey or (dimId 查库取 key)
    if dimKey 不存在于库: errors.push(...); continue
    # 去重判定
    rowA = SELECT * FROM modules WHERE id = fmod.id AND is_deleted = 0            # (a) id
    rowB = SELECT m.* FROM modules m JOIN dimensions d ON m.dimension_id = d.id
           WHERE d.key = dimKey AND m.content_en = fmod.contentEn AND m.is_deleted = 0  # (b) 内容
    if rowA 或 rowB 命中:
        if mode == 'overwrite':
            UPDATE modules SET content_en/display_name/weight/is_enabled/is_nsfw/notes
            WHERE id = hit.id
            # 若命中行维度与文件模块维度不一致 → 以库内维度为准
            modules_updated += 1
        else:
            modules_skipped += 1
    else:
        newId = uuid_v4()                          # 模块无稳定外部 id，一律新建
        INSERT INTO modules (..., dimension_id = dimIdMap[fmod.dimensionId 或按 key 查])
        modules_created += 1

# ===== 阶段 3：规则 =====（同上模式，去重键 id 或 name+type+source/target）
# ===== 阶段 4：标签 =====（去重键 name）
# 全部阶段在同一事务内；任一失败整体 ROLLBACK
```

### 4.3 导入模式（`mode` 参数）

| 模式 | 值 | 行为 | 适用场景 |
|------|-----|------|----------|
| **跳过** | `skip` | 去重键命中 → 保留现有行，跳过；未命中 → 插入 | 默认、安全、合并入库 |
| **覆盖** | `overwrite` | 去重键命中 → 用文件内容更新该行；未命中 → 插入 | 用标准库同步/修复本机词条 |

### 4.4 边界与冲突处理

| 情况 | 处理 |
|------|------|
| 文件维度 key 与库中 key 相同但 id 不同 | 合并到库中该 key 的维度（保留库 id） |
| 文件维度 id 与库中某维度 id 相同但 key 不同 | 视为冲突，**重新生成 uuid** 插入为“新维度”（记录错误信息提示） |
| 文件模块 contentEn 与库中多条匹配 | 取 `created_at` 最早一条为命中行，其余忽略（列为冲突警告） |
| 模块的 dimensionKey/dimensionId 均无法解析 | 记 `errors` 并跳过该条，事务继续 |
| 文件格式/版本不支持 | 直接报错拒绝导入，不改动任何数据 |
| 导入文件与库数据 100% 相同 | 全部 skipped，0 created/updated（幂等验证） |

## 六、测试方案

### 6.1 单元测试（`db.rs` 模块测试 + TS vitest）

| 用例 | 验证点 |
|------|--------|
| 导出 payload 字段完整 | format/formatVersion/counts 正确，dimensions/modules 均含 `is_deleted=0` 数据 |
| 导出文件可反序列化（roundtrip） | 导出字符串 → 再解析 → 与内存数据一致 |
| 导入同一文件两次 → 幂等 | 第一次 created>0，第二次全部 skipped、0 新增 0 更新 |
| 跨 id 去重（同 key/content 不同 id） | 不产生重复条目，命中 (b) 判定 |
| 三种维度冲突 | id 同 key 异 → 合并；key 同 id 异 → 合并并保留库 id；id 异 key 异 → 新建 |
| `mode=skip` vs `mode=overwrite` | skip 不改现有行；overwrite 更新字段且保留库 id |
| 非法文件（format/version 错误） | 报错拒绝，库无改动 |

### 6.2 集成测试

- `bun run build` + `cargo test` 通过。
- 手工：导出当前库 → 修改若干词条 → 以 `overwrite` 导入 → 验证词条更新、新增/重复计数正确。
- 手工：导出 A 库 → 导入 B 库（不同实例）→ 验证无重复词条、维度正确合并。

## 七、验收标准

| 编号 | 验收项 |
|------|--------|
| [B1] | 词库导出生成标准 JSON，文件头、维度、词条、规则完备，可被再次导入 |
