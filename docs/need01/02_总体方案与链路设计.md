# 02 — 总体方案与链路设计

> 结论先行：以**维度头右键菜单为唯一入口**，打通`维度 → 分片 → 聚合提示词 → LLM → 粘贴多片 JSON → 合并校验 → 选择性批量回填 → 库刷新`的闭环；不引入应用内 LLM 直连，保持**可复制/可下载/可离线校验**的形态，与 `SegmentImportDialog` 的三步范式对齐。

---

## 1. 目标与非目标

### 目标

- G1 — 维度面板维度行支持右键，首项**批量翻译当前维度**可一键打开翻译对话框。
- G2 — 维度内 `N` 条按 **30 条/片**（可配 50）分片生成**聚合翻译提示词**，支持**批量复制/批量下载**。
- G3 — 支持**多片结果批量粘贴**的宽容解析与**合并校验**，分页预览并支持**按片/按行选择性回填**。
- G4 — 选中子集**事务性批量更新** `modules.display_name`，成功后刷新 `library` 与面板。

### 非目标

- 不做应用内 LLM API 调用、不做自动翻译、不改 `contentEn`。
- 不引入新表/新标记、不改 `assembly`/`template` 相关链路。
- 不做跨维度批量翻译（v1 以单维度为边界）。

---

## 2. 用户旅程（Happy Path）

```
[维度头右键] → 上下文菜单“批量翻译（中文描述）”
  → 对话框 Step1：展示维度与分片（例 237 条 → 8 片，30/片）
    → 一键复制本片 / 一键复制全部 / 下载全部 .md
  → 用户将各片提示词分别投喂 LLM，得到多片 JSON
  → 对话框 Step2：粘贴多片 JSON（支持一次贴多片、含 fence、含多余文本）
    → 解析 → 合并去重校验 → 分页预览（按片着色、按 id 去重提示）
    → 勾选要回填的行（默认全选合法行，提供“仅选中可见/取消全选”）
  → 点击“应用到词库（K 条）” → 后端批量更新 display_name
    → Toast + Report（成功/跳过/错误），触发 library 刷新，面板条目即时呈现中文
```

异常分支见 05 §5。

## 3. 信息架构与窗口

```
DimensionPanel（浏览模式）
 ├─ 维度头 [data-testid="dimension-header-{key}"]  ← 监听 contextmenu
 │    └─ ContextMenu（Teleport body, fixed, calcMenuPos）
 │         └─ ① 批量翻译（中文描述）  ← v1 首项
 │            ②（预留）批量重命名 / 导出该维度 等
 └─ 对话框 DimensionTranslateDialog（Teleport body, z-40, 三步）
      ├─ Step1 生成聚合提示词（分片列表 + 复制/下载）
      ├─ Step2 粘贴 LLM 结果（textarea + 选择文件 + 转 JSON 按钮）
      └─ Step3 预览与回填（分页 + 选择 + 应用 + 报告）
```

与现有 `ModuleBatchDialog` / `SegmentImportDialog` 的 **fixed + bg-black/40 + Teleport** 范式一致，`z-index` 层级与关闭手势一致。

## 4. 分层与职责

| 层 | 模块 | 职责 |
|----|------|------|
| 视图 | `DimensionPanel.vue` | 监听 `contextmenu`、打开菜单、传递 `dimension + modules` 给对话框 |
| 视图 | `DimensionTranslateDialog.vue`（新增） | 三步状态机、分片展示、复制/下载、粘贴解析预览、触发回填 |
| 组合式 | `useDimensionContextMenu.ts`（新增，可内联） | 菜单开关、定位（`calcMenuPos`）、`Escape` / 点击外部关闭 |
| 领域 | `lib/translationPrompt.ts`（新增） | 分片 `chunkModules`、单片/全量提示词 `buildTranslationPrompt`、`buildAllTranslationPrompts`、`estimateTokens` |
| 领域 | `lib/translationParse.ts`（新增） | 多片粘贴宽容解析 `parseTranslationText`、合并 `mergeTranslationBatches`、校验 `validateTranslationBatch`、ID 归一 |
| 传输 | `lib/db.ts` 追加 | `dbBatchUpdateDisplayNames` / `dbBatchUpdateDisplayNamesText` 封装（含 camelCase invoke） |
| 存储 | `src-tauri/src/commands/translation.rs`（新增） | 事务性批量更新 `modules.display_name`、去重与长度约束、上报 `TranslationUpdateReport` |
| 状态 | `stores/library.ts` | `scheduleFetch` 刷新唯一数据源 |
| 事件 | `lib/libraryEvents.ts` | `emit(LIBRARY_CHANGED)` 触发刷新 |

## 5. 关键设计决策与权衡

| 决策 | 选项 | 结论与理由 |
|------|------|------------|
| 分片尺寸 | 20/30/50 | **默认 30，可配 50**。30 在多数 LLM 8k 上下文下留足余量（prompt≈2-3k tokens）且便于用户分批投喂；50 作为快捷切换，封顶 100 以防超限（04 §2）。 |
| 交换格式 | 纯 CSV / 纯 JSON / 混合 | **`pmf-translation` v1 JSON 为主，支持 `id → 中文` 扁平 map 兼容**。JSON 可携带 `dimensionKey/chunkId` 便于合并校验；兼容旧 LLM 输出的无 `format` 但含 `items`/`mappings` 的形态。 |
| 入口形态 | 维度内按钮 / 全局菜单 / 右键 | **维度头右键**。意图与对象强绑定、避免面板按钮拥挤、与 OS 习惯一致；后续维度级能力可同菜单扩展。 |
| 直连 LLM | 应用内调用 / 仅生成提示词 | **仅生成提示词**。不引入 key 管理、计费与网络；复用用户已有 LLM 会话与最强模型。 |
| 回填粒度 | 全量覆盖 / 差异预览 | **选择性回填 + 预览**。解析结果默认全选合法行，用户可取消；提交时仅对选中 id 更新，失败逐项报告不阻塞成功项。 |

## 7. 事件与刷新链路

```
DimensionTranslateDialog 回填成功
  → push(Toast success)
  → emit(LIBRARY_CHANGED, { source:'dimension-panel', op:'batch-update-display-names' })
  → App.vue handleLibraryChanged → library.scheduleFetch()
  → DimensionPanel computed(modulesByDim) 重新求值，中文即时可见
```

失败不触发刷新；错误与警告随 `report` 在对话框内留存。

---

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 维度内 1000+ 条生成 30+ 片，用户逐片投喂繁琐 | 提供**一键复制全部**（分片间 `---` 分隔）与**批量下载**（`pmf-translate-{key}-{ts}.md` 多文件或单 md 多段）；对话框记忆上次分片配置 |
| LLM 输出带 fence/多余解释/多片 JSON 拼在一起 | `extractJsonBlock` + fence 剥离 + **多块提取**（见 05 解析策略） |
| 用户贴回内容含非本维度 id | 校验阶段**按选中维度 id 白名单**过滤，非本维度一律判为 `unknownId` 并置于预览警告中 |
| 回填覆盖用户既有中文 | 预览行展示**原 `displayName` → 新中文**对比，默认全选但允许用户取消；报告回显 `updated: K` |
