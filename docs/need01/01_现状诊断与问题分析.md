# 01 — 现状诊断与问题分析

> 结论先行：中文显示名缺失的根因在**批量入库时对 `displayName` 的回退截断**与**前端列表对空 `displayName` 的英文回退**叠加，而维度面板既无右键入口也无批量翻译闭环；本需求以**维度为边界的右键菜单 + 分片聚合提示词 + 粘贴解析批量回填**补齐该缺口。

---

## 1. 背景输入

- 批量场景：单维度内轻松达到**几百上千**条（`batch.rs` 限制 500/次，`moduleBatch.ts` 前端同样 500 截断；大库 `total > 200` 即进入防抖）。
- 导入后：用户无精力逐条在 `ModuleEditDialog` 中手写 `displayName`，导致`英文截断当中文`长期存在。

---

## 2. 现有显示链路还原

### 2.1 数据模型

| 层 | 位置 | 字段 | 作用 |
|----|------|------|------|
| Schema | `src-tauri/resources/schema.sql:31-46` | `modules.content_en`, `modules.display_name` | `content_en` 为真值，`display_name` 可空 |
| 模型 | `src/engine/models.ts:26-38` | `Module.contentEn`, `Module.displayName` | 前端唯一形态 |
| DTO | `src/lib/db.ts:36-48` | `ModuleDto` | `displayName` 映射 `display_name`，允许空回退 |

### 2.2 入库侧回退（后端真值）

```rust
// src-tauri/src/commands/segment.rs:286-291
let display_name = seg.display_name
  .filter(|s| !s.trim().is_empty())
  .unwrap_or_else(|| content_en.chars().take(20).collect());
```

```rust
// src-tauri/src/commands/batch.rs:173-178
let display_name = item.display_name
  .filter(|s| !s.trim().is_empty())
  .unwrap_or_else(|| safe_truncate_chars(&content_en, 20));
```

> 缺 `displayName` 时数据库已写入**英文截断**，此后单纯读库无法区分是用户中文还是回退英文。

### 2.3 展示侧回退（前端二次回退）

- `DimensionPanel.vue:689` — 列表仅渲染 `{{ m.displayName }}`，若 `displayName` 即英文截断，用户视角即`英文当中文`。
- `ModuleEditDialog.vue:61-65` — 创建时 `displayName` 为空则 `contentEn.trim()` 回填，编辑态透传；无批量入口。
- `ModuleBatchDialog.vue:84-92` — `parseBatchText` 产生的 `displayName = contentEn.slice(0,20)` 再批量入库，路径与上同。

### 2.4 既有对话框体系

| 组件 | 职责 | 启发 |
|------|------|------|
| `ModuleBatchDialog.vue` | 同维度按行批量新增 | 粘贴→校验→分页预览→批量 `dbBatchCreateModules` 的三段式可直接复用 |
| `SegmentImportDialog.vue` | 三步分段导入（原始串→LLM 输出→预览导入） | **生成指令 / 粘贴解析 / 预览导入**的步骤范式是翻译链路的直接参照 |
| `segmentPrompt.ts` / `segmentParse.ts` | 指令构建与结果解析 | 聚合提示词模板、分片估算、JSON 宽容解析（`extractJsonBlock`、fence 去除）已沉淀 |
| `need05Position.ts` | `calcPopoverPos` / `calcMenuPos` | 右键菜单视口自适应已有纯函数与单测 |

## 3. 痛点拆解

### P1 — 回退截断不可识别

库中已无`是否为回退值`的标记，无法自动识别哪些 `displayName` 需翻译；只能以**维度为边界**批量覆盖，或以后增量识别（见 05 §6）。

### P2 — 单条编辑链路不可扩展

`ModuleEditDialog` 一次一行的交互在大 N 下不可用；亦无“选中多行批量翻译”的批量入口。

### P3 — 缺维度级批量入口

`DimensionPanel.vue` 维度头的交互仅有：单击折叠、Ctrl+点击禁用、以及 `+`/`批量`/`✎` 三个小按钮；**尚无 `contextmenu` 监听与右键菜单容器**（`00_目录`已确认空目录）。

### P4 — 上下文长度风险

维度内 500+ 条直接打成一个 Prompt 必超限；`segmentPrompt.ts:104` 对 500 已设上限并在 `108` 对 50+ 追加大体量提示，说明项目侧已意识到分片必要，但翻译场景未落地。

## 4. 约束与边界（来自代码）

| 约束 | 来源 | 对设计的影响 |
|------|------|--------------|
| `display_name` 无真假标记 | `schema.sql` + `batch.rs` | 回填应为**显式的用户批量覆盖**，需预览与勾选，不做静默清洗 |
| 去重键为 `dimension_id + content_en` | `db.rs:find_module_hit`, `batch.rs:208` | 回填**按 `module.id` 定点更新**，与去重正交 |
| `invoke` 键为 `camelCase` | `db.ts:1-7`, `pitfalls/01-invoke-arg-case.md` | 新增命令参数名必须 `camelCase` |
| 前端唯一数据源为 `library` | `stores/library.ts`, `App.vue: library.scheduleFetch` | 批量回填后必须 `emit(LIBRARY_CHANGED)` 并走 `scheduleFetch` 刷新面板 |
| Tailwind + Radix + 现有 Dialog 风格 | `DimensionPanel.vue` 模板 | 新对话框与菜单沿用 `fixed + bg-black/40 + z-40/70 + Teleport` 范式 |

## 5. 机会点

1. **右键菜单是通用扩展点**：首项做翻译，后续可挂“批量重命名 / 导出该维度 / 批量禁用”等，已有 `need05Position` 可直接承载。
2. **聚合提示词是可复用资产**：参考 `segmentPrompt.ts` 的 `buildDimensionTable + few-shot + Output Format` 形态，翻译提示词可做得同样可测。
3. **解析回填可复用 `segmentParse` 的宽容策略**：fence 剥离、`extractJsonBlock`、分段状态机、分页预览已有套路。

---

## 6. 本需求要解决的判定问题

1. 维度头如何无侵入地接入 `contextmenu` 且不与现有单击/Ctrl 冲突？
2. 上千条如何分片、每片提示词长什么样、如何一键复制/下载？
3. LLM 返回的多片 JSON 如何合并校验、如何让用户预览与选择性回填？
4. 回填是 `display_name` 的**幂等批量更新**，失败与部分成功如何呈现与回滚？

> 以上四问的回答分别落在 `03` `04` `05` `06`；本文件不展开方案，只定问题。
