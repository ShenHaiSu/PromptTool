# 05 — 结果解析与批量回填设计

> 结论先行：LLM 多片结果以 **宽容解析→多块提取→合并去重→维度白名单校验** 四步归一为 `PendingMap<id → zh>`，分页预览并支持**选择性批量**回填；后端以**事务 + 逐项校验 + 报告**保证幂等更新，失败项不影响成功项。

---

## 1. 交换格式 — `pmf-translation` v1

### 1.1 规范 JSON（LLM 应输出）

```json
{
  "format": "pmf-translation",
  "formatVersion": 1,
  "dimensionKey": "top",
  "chunkId": "c01",
  "totalChunks": 8,
  "items": [
    { "id": "m_top_1", "zh": "宽松白衬衫" },
    { "id": "m_top_2", "zh": "黑色短款背心" }
  ]
}
```

### 1.2 兼容形态（亦接受）

| 形态 | 示例 | 处理 |
|------|------|------|
| 扁平 map | `{ "format":"pmf-translation", "items": {"m_1":"中文", ...}}` | 视作 `Object.entries(items)` 转 `[{id, zh}]` |
| 无 `format` 但含 `items` 数组 | `{ "items": [{ "id":"m_1","zh":"中文"}] }` | 视为 pmf-translation，补 `chunkId=unknown` |
| 多片 JSON 直接拼接 | `}{` 或 `---` 分隔的两段 JSON | 多块提取后合并 |
| 含 ```json fence | ```json {...} ``` | 去 fence 后提取 |
| 前后含解释文本 | `以下是翻译：{...} 请查收` | `extractJsonBlock` 提取 |

`formatVersion !== 1` 与 `format !== "pmf-translation"` 在**严格块**上记 `error`，在**兼容块**上降为 `warning` 并仍解析。

---

## 2. 前端解析流水线

```
rawText: string（用户一次粘贴的全部内容，可能含多片 JSON + fence + 解释）
  → splitAndExtractJsonBlocks(rawText): string[]  // 多块提取
  → perBlockParse(block): { kind:'json'|'unknown', items:[{id,zh}], chunkId?, dimensionKey?, errors[] }
  → mergeTranslationBatches(blocks): MergeResult
  → validateTranslationBatch(mergeResult, { dimension, modules }): ParsedTranslation
```

### 2.1 多块提取 — `extractTranslationJsonBlocks`

复用 `segmentParse.extractJsonBlock` 思路并扩展为**多块**：

1. 去除首尾 ```fence（`^```(?:json)?\s*` / ` ```\s*$`）。
2. 扫描全文，以平衡大括号计数提取每个顶层 `{...}` 块（`depth` 跟踪，`inString` 转义感知）。
3. 每个候选块 `JSON.parse` 试探，成功则收为一块，失败则记 `errors` 并跳过该段。
4. 若未提取到任何块但全文含 `"zh"` 关键字，尝试整体 `JSON.parse` 一次（兜底）。

### 2.2 合并与去重 — `mergeTranslationBatches`

| 场景 | 策略 |
|------|------|
| 跨片同 `id` 多次出现 | **后者覆盖前者**，计 `warnings: "id m_x 重复，已取最后一次的值"`，最终 `PendingMap` 去重 |
| 同片内重复 `id` | 同上 |
| `id` 空或 `zh` 空 | 该项计 `errors` 并丢弃，不入 `PendingMap` |
| `zh` 超长 | 截断至 500，计 `warnings` |
| `dimensionKey` 与当前维度不一致 | 计 `warnings`，不阻断（便于用户跨维度误贴时可见） |

### 2.3 校验 — `validateTranslationBatch`

输入 `dimension: Dimension` 与 `modules: Module[]`（当前维度白名单）。

| 校验项 | 结果 |
|--------|------|
| `id` 不在白名单 | `unknownId` — 行置灰、默认不勾选、Badge `非本维度` |
| `zh` trim 后为空 | `emptyZh` — 行标红、默认不勾选 |
| `zh` 与原 `displayName` 相同 | `unchanged` — 可选，预留“去重不变项”过滤 |
| 合法 | `ok` — 默认勾选 |

统计：`totalUnique / hit / unknown / duplicate / empty / unchanged`。

## 3. 预览与选择

- `PendingMap: Map<id, { zh, sourceChunkId, warnings[] }>`，行模型：

```ts
type TranslationRow = {
  id: string
  contentEn: string       // 来自白名单 modules 的真值，便于对照
  oldDisplayName: string  // 可能是回退截断
  newZh: string           // 可编辑
  status: 'ok' | 'unknownId' | 'emptyZh' | 'duplicate'
  warnings: string[]
  selected: boolean
}
```

- 排序：按白名单 `modules` 原序（稳定），未知 id 挂尾。
- 编辑：行内 `newZh` 可改，失焦即 `trim` 并重校验（`emptyZh` 即时反馈）。
- 选择：默认**全选 `ok`**，提供 `全选合法 / 取消全选 / 仅选当前页 / 反选`；过滤器联动选择（如“仅看非本维度”时全选即为误操作，故过滤态下的全选仅作用于可见行并二次确认）。

## 4. 后端批量回填

### 4.1 单次事务语义

- **输入**：`TranslationUpdatePayload { dimensionId: string, items: Array<{ id: string, displayName: string }>, mode: 'update' }`。
  - `dimensionId` 必填，用于服务端二次校验维度归属（防跨维度串改）。
  - `items` 已由前端去重并过滤为选中合法子集；空数组直接 `Err("无有效更新")`。
- **处理**（`translation.rs`）：
  1. 校验维度存在且 `is_deleted=0`。
  2. `BEGIN IMMEDIATE`。
  3. 逐项：
     - `SELECT dimension_id, display_name FROM modules WHERE id=?1 AND is_deleted=0`；不存在计 `errors` 并跳过。
     - `dimension_id != payload.dimensionId` 计 `errors: "id m_x 不属于维度 {key}"` 并跳过。
     - `displayName.trim()` 空计 `errors` 并跳过；长度>500 截断并计 `warnings`。
     - `UPDATE modules SET display_name=?1, updated_at=?2 WHERE id=?3`，成功计 `updated`。
  4. `COMMIT`；任一 SQL 异常则 `ROLLBACK` 并返回 `Err`。

- **报告**：

```ts
type TranslationUpdateReport = {
  totalRequested: number
  updated: number
  skipped: number        // 未命中/跨维度/空值
  warnings: string[]
  errors: string[]
}
```

幂等：重复提交相同 `zh` 亦计 `updated`（`UPDATE` 仍执行，`updated` 反映语句执行数而非差异数）。

### 4.2 不做事项

- 不改 `content_en` / `weight` / `is_nsfw` / `notes`。
- 不做 `display_name` 去重合并（同中文多模块允许并存）。
- 不做跨维度批量（`dimensionId` 单值约束）。

## 5. 异常与边界

| 场景 | 前端 | 后端 |
|------|------|------|
| 粘贴为空 | 禁用“解析并预览”，Toast 引导 | — |
| 多块 JSON 中部分块解析失败 | 成功块入预览，失败块在顶部 `errors` 列表展示块序号与原因 | — |
| 全部 id 均非本维度 | 预览显示“0 命中，请确认维度”；应用按钮 `disabled` | 若强行提交，`updated=0, errors` 逐项回显 |
| LLM 漏译（`items.length < chunkSize`） | 未覆盖的白名单 id 不在预览中，统计提示 `命中 {hit}/{N}` | 仅对提交的 `items` 生效，不补漏 |
| 大粘贴（>500 id） | 前端分页承载，`PendingMap` 上限 2000，超限提示分批 | 后端 `items` 上限 1000（与 `batch.rs` 对齐），超限 `Err` 提示分批 |
| 并发回填 | 前端 `applying` 锁，按钮 `disabled` | `BEGIN IMMEDIATE` 串行化 |

---

## 6. “疑似回退值”可选增强（v1 不做，预留）

库中无法区分真中文与回退英文时，可在预览阶段对 `oldDisplayName` 做启发式标记（`old === contentEn.slice(0,20) && !/[\u4e00-\u9fff]/.test(old)`），Badge `疑似回退`，并提供“仅回退值”过滤。**v1 不自动过滤**，仅作为后续迭代。
