# 06 · 接口契约（命令 / 事件 / 类型）

> 新增命令 6 个，事件 0 个（复用 hungry），类型扩展 2 处。全部 camelCase。

## 1. Tauri 命令

| 命令 | 参数 | 返回 | 需求 |
|------|------|------|------|
| `iq_find_by_filename` | `{query: string}` | `ImageTask\|null` | 2b 反查 |
| `stats_ledger_summary` | `{from: yyyy-MM-dd, to}` | `{total,succeeded,failed,pixels,avgElapsedMs}` | 3 看板头 |
| `stats_ledger_daily` | `{from,to}` | `[{day,total,succeeded,pixels}]` | 3 日表 |
| `stats_ledger_hourly` | `{day}` | `[{hour,total,succeeded,pixels}]`（24行，空小时补0） | 3 小时柱 |
| `iq_generate_one_preview` | `{prompt,size,ratio}` | `{imageBase64,mime,elapsedMs}`（≤100MB守卫同队列） | 4 生成 |
| `iq_save_preview` | `{imageBase64,prompt,size,ratio,outputDir?}` | `{filename,filePath}` + 附带 ledger 落账 | 4 保存 |

- 注册位置：`commands/image_queue/mod.rs` + `commands/meta.rs`（stats 三命令建议挂 meta 侧，贴近主库）。
- 错误：沿用 `Result<T,String>` + 前端 toast；`find` 无结果走 `Ok(None)` 非 Err。

## 2. 事件（无新增）

- `image-queue://hungry{want}`：需求1 top-up 复用；前端 `ImageQueuePanel onMounted` 同一订阅处理饥饿与 top-up（`refillFromEngine` 内合并在途，见 01 §2.2）。
- `image-queue://task-updated` 载荷自动多出 `expectedStem/filename`（02）；老监听忽略未知字段。

## 3. TS 类型（`lib/imageQueueApi.ts` + 新 `lib/statsApi.ts`）

```ts
interface ImageTaskView { // 扩展
  expectedStem?: string | null; filename?: string | null;
}
interface LedgerSummary { total:number; succeeded:number; failed:number; pixels:number; avgElapsedMs:number }
```

- `imageQueueApi.ts` 加 `iqFindByFilename(query)`；新建 `statsApi.ts` 包三查询 + `singleShotApi`（preview/save）——或统一并入 `imageQueueApi.ts`（二选一，施工时定，保持单文件<400行）。
- `stores/imageQueue.ts` 不新增 store；报表 Dialog 直调 `statsApi`，单发面板本地 `ref` 管 base64（不进 Pinia，避免大串进 devtools）。
