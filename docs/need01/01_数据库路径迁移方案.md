# 01 数据库路径迁移方案

> **关联代码：** `src-tauri/src/commands/migration.rs:89-95`（`db_path_for`）· `migration.rs:380-392`（`init_db`）· `migration.rs:408-473`（`db_import_legacy_db`）· `src-tauri/src/commands/db.rs:10-16`（`open_conn`）· `src-tauri/src/lib.rs:10-13`（`setup`）
> **目标：** 数据库从 `%APPDATA%\com.pmf.tauri-app\pmf.db` 迁至 `exe 所在目录\data\pmf.db`

---

## 一、现状分析

### 1.1 当前路径生成链

```
┌─ lib.rs:11  setup 调用 init_db(&app.handle())
├─ migration.rs:89-94  db_path_for(app)
│   └─ app.path().app_data_dir()  →  %APPDATA%\com.pmf.tauri-app\pmf.db
├─ migration.rs:380-392  init_db(app)
│   └─ 硬编码 dir = app.path().app_data_dir()  →  %APPDATA%\com.pmf.tauri-app
│         └─ create_dir_all(dir)  →  dir.join("pmf.db")
├─ db.rs:10-16  open_conn(app)
│   └─ 调用 db_path_for(app)  →  同上
└─ migration.rs:410  db_import_legacy_db
    └─ 调用 db_path_for(app)  →  同上
```

**所有数据库操作**都通过 `open_conn`（间接调用 `db_path_for`）或 `init_db` 内部使用 `app_data_dir()`，**改动点集中**，共 3 处：

| 位置 | 函数 | 行号 | 改动方式 |
|------|------|------|----------|
| `migration.rs` | `db_path_for()` | L89-95 | 改路径逻辑 |
| `migration.rs` | `init_db()` | L380-392 | 改路径逻辑（`db_path` 的 dir 计算与 `db_path_for` 对应） |
| `migration.rs` | `db_import_legacy_db()` | L410 | 直接调用 `db_path_for`，无需改 |

### 1.2 当前路径表现（开发模式）

```
exe:          E:\ProgramFiles\PromptTool\src-tauri\target\debug\tauri-app.exe
app_data_dir: C:\Users\<用户名>\AppData\Roaming\com.pmf.tauri-app\pmf.db
```

### 1.3 迁移风险

- **写入权限**：exe 所在目录如果在 `Program Files` 下，默认不可写。用户明确要求"不侵入用户路径"，故**不做 fallback 到 AppData**，写入失败时明确报错。
- **WAL 伴生文件**：`pmf.db-wal`、`pmf.db-shm`，迁移时必须用 SQLite 级 `backup API` 确保一致性，不依赖文件系统直接拷贝。
- **开发/打包双模式**：`exe_dir()` 在 dev 和 release 模式下返回不同路径，但 `data/` 始终在 exe 旁。

## 二、目标路径

```
exe:  E:\AnyDir\app.exe
data: E:\AnyDir\data\pmf.db
      E:\AnyDir\data\pmf.db-wal  (WAL journal)
      E:\AnyDir\data\pmf.db-shm  (WAL shared memory)
```

**路径定位函数：**

```rust
/// 返回 exe 所在目录下的 data/ 目录
pub fn data_dir_for(app: &AppHandle) -> Result<PathBuf, String> {
    let exe_dir = app.path().exe_dir().map_err(|e| e.to_string())?;
    // 开发模式：exe_dir = src-tauri/target/debug/ → data/ 在 debug/data/
    // 打包模式：exe_dir = 安装目录 → data/ 在安装目录下
    Ok(exe_dir.join("data"))
}
```

> 选用 `app.path().exe_dir()` 而非 `std::env::current_exe()`，因为它是 Tauri 封装的跨平台 API，返回已规范化的目录路径。

## 三、实现方案

### 3.1 新增函数：`data_dir_for` + `exe_db_path_for`

**文件：** `src-tauri/src/commands/migration.rs`

```rust
/// 数据库文件所在目录 = exe_dir/data/
pub fn data_dir_for(app: &AppHandle) -> Result<PathBuf, String> {
    let exe_dir = app.path().exe_dir().map_err(|e| e.to_string())?;
    Ok(exe_dir.join("data"))
}

/// 完整数据库文件路径
pub fn exe_db_path_for(app: &AppHandle) -> Result<PathBuf, String> {
    Ok(data_dir_for(app)?.join("pmf.db"))
}
```

### 3.2 修改 `db_path_for`（存量入口统一）

```rust
/// 修改前：app.path().app_data_dir()?.join("pmf.db")
/// 修改后：重定向到 exe 旁
pub fn db_path_for(app: &AppHandle) -> Result<PathBuf, String> {
    exe_db_path_for(app)
}
```

### 3.3 修改 `init_db`：新路径写入 + 旧库自动迁移

```rust
pub fn init_db(app: &AppHandle) -> Result<PathBuf, String> {
    let dir = data_dir_for(app)?;
    std::fs::create_dir_all(&dir).map_err(|e| {
        format!(
            "无法创建数据库目录 '{}': {}。\n\
             提示：请确保程序所在目录可写，或使用管理员权限运行。",
            dir.display(), e
        )
    })?;
    let db_path = dir.join("pmf.db");
    let is_new_file = !db_path.exists();

    // ---- 旧库自动迁移：新库不存在但旧 appdata 库存在 → 备份迁移 ----
    let legacy_path = app.path().app_data_dir()
        .map_err(|e| e.to_string())?
        .join("pmf.db");
    if is_new_file && legacy_path.exists() {
        // 用 SQLite backup API 确保 WAL 一致性
        migrate_legacy_db(&legacy_path, &db_path)?;
        eprintln!("[pmf] 旧库已迁移: {} → {}",
            legacy_path.display(), db_path.display());
    }

    let conn = open_and_pragmas(&db_path)?;
    if is_new_db(&conn) {
        conn.execute_batch(SCHEMA_SQL).map_err(|e| e.to_string())?;
    }
    migrate_if_needed(&conn)?;
    seed_if_empty(&conn, app)?;
    Ok(db_path)
}
```

### 3.4 新增 `migrate_legacy_db` — SQLite Backup API 安全迁移

```rust
/// 使用 rusqlite 的 backup API 将旧库完整复制到新路径（含 WAL checkpoint）
fn migrate_legacy_db(legacy: &Path, new_path: &Path) -> Result<(), String> {
    let src = Connection::open(legacy).map_err(|e| e.to_string())?;
    // 先 checkpoint 源库 WAL
    src.execute_batch("PRAGMA journal_mode=WAL; PRAGMA wal_checkpoint(TRUNCATE);")
        .map_err(|e| e.to_string())?;
    // 目标库
    let dst = Connection::open(new_path).map_err(|e| e.to_string())?;
    let backup = rusqlite::backup::Backup::new(&src, &dst)
        .map_err(|e| e.to_string())?;
    backup.run_to_completion(50, std::time::Duration::from_millis(250), None)
        .map_err(|e| e.to_string())?;
    dst.execute_batch("PRAGMA wal_checkpoint(TRUNCATE);")
        .map_err(|e| e.to_string())?;
    Ok(())
}
```

### 3.5 保留 `db_import_legacy_db` 用户手动导入

该命令 `db_import_legacy_db(app, legacy_path)` 内部调用 `db_path_for(app)` 获取新路径，不受迁移影响。用户在设置中仍可手动选择旧库文件导入。

### 3.6 开发模式优化（可选）

若希望在开发模式时 `data/` 出现在项目根目录而非 `target/debug/` 下，可增加检测：

```rust
pub fn data_dir_for(app: &AppHandle) -> Result<PathBuf, String> {
    let exe_dir = app.path().exe_dir().map_err(|e| e.to_string())?;
    // 开发模式检测：exe 在 target/debug/ 或 target/release/ 内
    let exe_str = exe_dir.to_string_lossy().replace('\\', "/");
    if exe_str.contains("/target/debug") || exe_str.contains("/target/release") {
        // 回退到 current_dir（项目根目录）的 data/
        if let Ok(cwd) = std::env::current_dir() {
            return Ok(cwd.join("data"));
        }
    }
    Ok(exe_dir.join("data"))
}
```

> 此为可选项，默认走 exe 旁。最终选择由用户确认。

## 四、旧库自动迁移流程

```
                                 ┌──────────────────────────┐
                                 │  data/pmf.db 是否存在？  │
                                 └──────────┬───────────────┘
                                          │ 否
                                          ▼
                                 ┌──────────────────────────┐
                                 │  %APPDATA%/pmf.db        │
                                 │  是否存在？               │
                                 └──────────┬───────────────┘
                                          │ 是
                                          ▼
                   ┌─────────────────────────────────────────┐
                   │  migrate_legacy_db()                     │
                   │  ① 打开旧库（只读），wal_checkpoint     │
                   │  ② 打开新库（空文件）                    │
                   │  ③ rusqlite Backup API 全量复制          │
                   │  ④ 新库 wal_checkpoint(TRUNCATE)         │
                   │  ⑤ 旧库保留不动（回滚安全）               │
                   └─────────────────────────────────────────┘
                                          │
                                          ▼
                              ┌────────────────────┐
                              │  继续 init_db 后续  │
                              │  schema / migrate  │
                              │  seed 等（幂等）    │
                              └────────────────────┘
```

**迁移后数据完整性：** dimensions、modules、tags、module_tags、assemblies、assembly_items、templates、rules 及所有索引全部保留。

## 六、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| exe 目录不可写（如 `Program Files`） | 程序启动失败 | `init_db` 中 `create_dir_all` 失败时返回明确错误信息，指引用户以管理员权限运行或安装到可写路径 |
| 旧库迁移过程中断 | 新库不完整 | `migrate_legacy_db` 使用 SQLite Backup API（事务级原子），异常时 `drop` 连接自动回滚；旧库始终保留不变 |
| OS 权限拒绝读取旧 appdata | 无法自动迁移 | 降级为静默跳过，用户可手动使用 `db_import_legacy_db` |
| 开发模式 target 清理 | data/ 随 target 一起被删除 | 正常行为，开发模式数据不持久；若需持久可使用种子数据重新导入 |
