## 1. 问题陈述

> "我有一大段按照回车符分隔的属于同一类别的片段提示词"

典型输入形如（以 `top / 上装` 为例）：

```
oversized white shirt
cropped black tank top
lace-trim silk camisole
...
(50~300 行)
```

期望：选定一个已存在的**维度（Dimension）**，一次性将上述 N 行作为 N 个**词条（Module）**写入该维度下，无需逐条弹窗、无需走 LLM。

---

## 2. 现有前端交互盘点

### 2.1 路径 A — 维度面板单条新建（主路径）

- **入口：** `DimensionPanel.vue:277-284` 维度头部的 `+`（`dim-create-module-${dim.key}`）→ `ModuleEditDialog.vue`
- **形态：** `ModuleEditDialog` 仅支持**单条**录入：`dimensionId`（下拉/已预选）+ `contentEn`（必填）+ `displayName` + `weight` + `isNsfw` + `notes`
- **后端：** `dbCreateModule(dimId, contentEn, displayName, weight)` → `db_create_module` 单行 `INSERT INTO modules`
- **结论：** N 行需要点击 N 次弹窗、填写 N 次，不满足批量诉求。

### 2.2 路径 B — 分段导入（SegmentImportDialog，三步向导）

- **入口：** `App.vue:293` `StatusBar` → `SegmentImportDialog`；`segment.rs` + `segmentParse.ts` 支撑的 `pmf-segments` 方案
- **设计目标：** 从**多条完整 Prompt**中切分出**跨维度**片段，需经 LLM 标注 `[dimensionKey] content` 或 JSON，再校验、预览、去重导入（`dbImportSegments` / `db_import_segments`）。
- **能力：** 虽然最终也能批量写 `modules`（`segment.rs: import_segments_into` 事务内逐条 `find_module_hit` 去重 + `INSERT`），但：
  1. 要求先"生成解析指令 → 丢给 LLM → 粘回结果"，链路过重；
  2. 核心假设是**多维度混合**，对"全部同维度、按行即一条"的场景要额外构造 `pmf-segments` JSON，属间接绕路；
  3. 无"选定维度 + 粘贴 N 行直插"的快捷态。

### 2.3 路径 C — 词库导入（LibraryDialog）

- **形态：** `pmf-library` JSON（dimensions + modules + rules + tags）跨库迁移，粒度是整库，不面向"一个维度内追加 N 行"的轻量操作。
- **结论：** 非本题场景。

### 2.4 小结判定

| 能力 | 是否存在 | 是否覆盖本题 |
|------|----------|--------------|
| 单条新建词条 | ✅ 已有 | ❌ 不覆盖批量 |
| 跨维度 LLM 分段批量 | ✅ 已有 | ⚠️ 可绕路但体验/成本不匹配 |
| **同维度、按回车 N 行直插** | **❌ 缺失** | **本次新增** |

> **诊断结论：目前没有批量插入的直连方案。**最接近的绕路是把 N 行拼成 N 个 `pmf-segments` prompts（每个 prompt 含 1 个 segment，`dimensionKey` 相同），再走 `SegmentImportDialog` 导入——但这要求用户手写/脚本生成 JSON，且经过校验/预览/去重配置，操作成本与心智负担均偏高。

## 3. 用户故事与验收口径

**US-01（核心）：**
作为运营/提示词维护者，我在维度面板已选定维度 `X`，粘贴一段以回车分隔的文本（每行一个英文片段），点击"批量创建"，系统将有效行批量写入维度 `X`，并告知成功/跳过/失败明细，面板自动刷新，无需刷新页面或重启应用。

**验收要点（先行定义，详见 03）：**

- 粘贴 1~500 行，空行、首尾空白自动忽略；
- 同批次内重复行按去重策略处理；
- 已存在（同维度 + `contentEn` 精确匹配）按 `skip / overwrite` 处理；
- 单行 `contentEn` 长度上限 500 字符（与 `segment.rs:252` 一致），超长截断并告警；
- 批量操作为单事务或分批事务，失败不污染已提交部分（至少做到"已成功行不回滚"的可预期行为，见 §5）；
- 操作后 `DimensionPanel` 与 `BatchFactory` 侧的计数/列表自动刷新（复用 `LIBRARY_CHANGED` 事件）。

## 4. 约束与复用

- **存储约束（Need04）：** `modules.dimension_id` 外键 + `assembly_items.dimension_key` / `template_items.dimension_key` 非空；批量创建仅写 `modules` 表，不触及明细表。
- **去重口径复用：** `db.rs: find_module_hit` — `(id 命中) ∨ (同维度 contentEn 精确匹配取最早)`，本功能沿用。
- **前端约束：** Tauri v2 `invoke` 参数名必须为 **camelCase**（`pitfalls/01-invoke-arg-case.md`），新增命令的 `dimId` 等键名需遵守。
