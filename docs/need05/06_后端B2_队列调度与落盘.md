# B2 后端施工：队列调度、并发、落盘（`06`）

> 前置：B1（`05`）的 `generate_one`、`ImageQueueConfig`、client 缓存。
> 本层负责：任务状态机、并发调度、饥饿补货信号、熔断、下载落盘、复现元数据、10 个 `iq_*` 命令。

## 1. 状态与命令清单

### 1.1 `ImageQueueState`（`queue.rs`，`app.manage` 注入）

```rust
pub struct ImageQueueState {
    pub config: RwLock<ImageQueueConfig>,          // B1
    pub tasks: RwLock<HashMap<String, ImageTask>>, // 全量任务（含 finished，上限 2000，超限清最旧 finished）
    pub order: RwLock<VecDeque<String>>,           // 入队顺序（分页拉取用）
    pub running: AtomicUsize,                      // 当前 running 计数（信号量外再计一次，供 hungry 判断）
    pub consec_fail: AtomicUsize,                  // 连续失败计数（成功清零，≥5 熔断）
    pub stop_flag: AtomicBool,                     // true = 已停止/熔断，调度循环退出
    pub generation: AtomicU64,                     // 每次 start 自增，旧调度循环凭此退出（防 start/stop 竞态）
    pub client_cache: Mutex<HashMap<ClientFingerprint, reqwest::Client>>, // B1
}
```

全部用 `std::sync` 原语；调度循环为 `tauri::async_runtime::spawn` 的后台任务，
**`start` 幂等**：已在运行则直接返回当前 generation。

事件（`app.emit`，命名空间固定前缀）：

| 事件 | payload | 触发 |
|---|---|---|
| `image-queue://task-updated` | `ImageTask` | 任务每次变迁（Queued→Running→…→落盘） |
| `image-queue://stats` | `{queued, running, succeeded, failed, consecFail, stopped}` | 变迁后 emit，F2 节流 500ms 渲染 |
| `image-queue://hungry` | `{want: usize}` | loop 开启且 `queued==0` 时，`want = concurrency - running`（F3 补货） |
| `image-queue://halted` | `{reason: "manual"|"circuit"|"io"|"disk", message}` | 停止/熔断，F2 toast + 运行条状态 |

## 2. 调度循环（核心伪代码即实现约束）

### 2.1 主循环

```rust
async fn scheduler(app: AppHandle, state: &ImageQueueState, gen: u64) {
    let sem = Arc::new(Semaphore::new(state.config.read().concurrency()));
    loop {
        if state.stop_flag.load() || state.generation.load() != gen { break; }
        let next = take_next_queued(&state); // 顺序取最早 Queued
        match next {
            Some(task) => {
                let permit = sem.clone().acquire_owned().await;
                state.running.fetch_add(1);
                emit_stats(&app, &state);
                spawn_worker(app.clone(), state.clone(), task.id, permit, gen);
            }
            None => {
                if state.config.read().loop_enabled && !state.stop_flag.load()
                    && state.running.load() == 0 {
                    emit_hungry(&app, &state); // F3 补货；补货到达前 sleep 800ms 再 poll
                }
                sleep(300ms).await;
                // 退出条件：非 loop 且无 queued 且 running==0 → 自然结束（stop_flag 置 true，emit halted manual? 不，
                // 自然收尾 emit stats 即可，不 toast 打扰）
            }
        }
    }
}
```

要点：

- `concurrency` 热更新：`iq_set_config` 时若调度运行中，**不重建**在途 sem，
  而是记录 `pending_permits`，新 worker 按新容量 acquire（实现：`semaphore.add_permits(delta)` /
  `forget`，tokio Semaphore 支持动态增减，文档必须写清用 `add_permits`）。
- `take_next_queued` 必须在同一把锁内完成“找 + 置 Running”，防双 worker 抢同一任务。

### 2.2 worker（单任务全链路）

```rust
async fn worker(app, state, task_id, _permit, gen) {
    set_status(task_id, Running); emit(task);
    let (client, cfg) = snapshot_client_and_config(&state); // 快照：任务不受中途改配置影响
    match generate_one(&client, &cfg, &task.prompt).await {
        Ok((url, ms)) => match download_and_persist(&app, &cfg, &task, &url).await {
            Ok(path) => { succeed(task_id, url, path, ms); consec_fail = 0; }
            Err(e) => fail(task_id, format!("下载/落盘失败：{e}"), retryable = is_io(e));
        }
        Err(IqError::Retryable(e)) if task.retry_count < 2 => {
            task.retry_count += 1; sleep(backoff); requeue(task_id); // 状态回 Queued，emit
        }
        Err(e) => fail(task_id, e.to_string(), ...),
    }
    state.running.fetch_sub(1);
    if fail { consec_fail += 1; if consec_fail >= 5 { halt_circuit(&app, &state, gen); } }
    emit(task); emit_stats;
}
```

- `Cancelled`：`iq_stop` 时 running worker 被 abort（`JoinHandle::abort`，handle 表由 state 持有
  `HashMap<taskId, JoinHandle>`，worker 结束自行移除），abort 的任务置 Cancelled，**不计入熔断**。
- prompt 长度上限：Agnes 未明示，`iq_enqueue` 截断到 4000 字符（超限记 warning 入 error 字段前缀，不拒绝）。

### 2.3 并发语义

- `concurrency ∈ 1..=8`，semaphore 容量即并发；下载阶段同样占用 permit（全链路占用，
  避免“生成 2 张 + 下载 8 张”挤爆带宽）。
- 2K/4K 大图提示由 F1 承担，后端不限速，只保证流式写文件（§4.2）。

### 2.4 停止与熔断

- `iq_stop`：`stop_flag=true`，`generation+=1`（旧循环退出），abort 所有 running，queued 保留。
- 熔断：`consec_fail>=5` → 同 stop + `emit halted{reason:"circuit"}`；F2 toast 红色并定位首个失败任务。
- 磁盘水位：worker 落盘前检查输出目录所在盘剩余空间（`sysinfo`？一期为零依赖，用
  Windows `GetDiskFreeSpaceExW` / Unix `statvfs` 各 20 行封装，<500MB 即 `halted{reason:"disk"}`）。
  输出目录不可写（probe 失败）→ `halted{reason:"io"}`。

## 3. 入队去重与上限

1. 去重键：`ir_hash` 有则按 hash，无则按 `prompt` 归一化（trim + 连续空白折叠）；
   与 **已存在非 Cancelled 任务** 撞键即跳过，返回中标记 `skipped: true`（`iq_enqueue` 返回改为
   `Vec<EnqueueResult{taskId?, skipped}>`，F3 据此 toast“已跳过 N 条重复”）。
2. 队列上限：`tasks` 总量 2000，超限拒绝新入队并 Err（前端分批入队，见 F3）；
   finished 任务保留供回放，`iq_clear_finished` 清理。

## 4. 下载与落盘（复用 export.rs 四件套）

### 4.1 目录归一（照抄 `normalize_export_dir` 语义，函数独立 `normalize_image_dir`）

- `""` → `{data_dir}/output/images`（默认，**用户要求的 dataDir 默认**）；
- 相对路径 → 相对 `data_dir` 拼接（并 strip 历史 `data/` 前缀，与 export 一致）；
- 绝对路径 → 直接用；无论哪种，不存在则 `create_dir_all`，随后 `.pmf_write_probe.tmp` 可写探测。
- 用户自定义路径经 `iq_set_config` 校验通过后写入 `image_queue.json`（记住，见 B1 §4.3）。

### 4.2 下载（流式，不全量进内存）

```rust
async fn download_and_persist(app, cfg, task, url) -> Result<String, String> {
    let dir = ensure_image_dir(app, &cfg.output_dir)?;
    let resp = client.get(url).send().await...; // 用独立轻量 client（无代理？不——图片域可能同样需代理，
    // 一期与 API 共用同一 client，保证代理环境一致）
    // content-type 校验：image/* 方可；否则 Err（Agnes 偶发返回 json 错误页）
    // 大小上限 100MB，超限中止；
    // stream 分块写 .tmp 文件 → 校验 PNG/JPEG 魔数 → atomic rename
}
```

- 文件名：`{yyyyMMdd_HHmmss}_{seq}_{size}_{ratio}_{hash8}.png`，
  `seq` 为当日自增（`tasks` 中同日计数 + 后缀碰撞时复用 `unique_filename_in` 追加 `-1`）；
  扩展名按 content-type 定（png/jpeg/webp），魔数校验失败记失败。
- 同名 `.json`（复现元数据）：`{prompt, irHash, size, ratio, model, imageUrl, elapsedMs, createdAt, taskId}`，
  与图片原子写配对（先写图后写 json，json 失败不影响成功状态，仅记日志）。
