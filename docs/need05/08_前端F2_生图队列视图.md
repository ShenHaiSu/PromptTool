## 2. store 任务域（`src/stores/imageQueue.ts` 续 F1）

```ts
export type ImageTaskStatus = 'queued' | 'running' | 'succeeded' | 'failed' | 'cancelled'
export interface ImageTaskView {
  id: string; prompt: string; irHash?: string | null
  size: string; ratio: string; status: ImageTaskStatus
  imageUrl?: string | null; filePath?: string | null
  elapsedMs?: number | null; error?: string | null
  retryCount: number; createdAt: number
}
export interface IqStats { queued: number; running: number; succeeded: number; failed: number; consecFail: number; stopped: boolean }
```

```ts
// store 内续：
const tasks = ref<Map<string, ImageTaskView>>(new Map()) // 主存 Map，顺序另存 order 数组
const order = ref<string[]>([])
const stats = ref<IqStats>({ queued: 0, running: 0, succeeded: 0, failed: 0, consecFail: 0, stopped: true })
const runningGen = ref<number | null>(null)
let unlisten: Array<() => void> = []
let statsTimer = 0

async function initQueue(): Promise<void> {
  const page = await iqList(0, 100)           // 首屏回填（B2 iq_list）
  replaceAll(page.items)
  await subscribeEvents()                      // listen('image-queue://task-updated' 等 4 个)
}
function disposeQueue(): void { unlisten.forEach(fn => fn()); unlisten = [] }

async function enqueueCurrentBatch(prompts: Array<{ prompt: string; irHash?: string }>): Promise<void> {
  // 分批入队：每批 100 条（B2 上限 2000），返回 skipped 计数并 toast（F3 调用）
}
async function start(): Promise<void> { runningGen.value = await iqStart(); }
async function stop(): Promise<void> { await iqStop(); }
async function retry(id: string): Promise<void> { await iqRetry(id) }
async function remove(id: string, deleteFile = false): Promise<void> { await iqRemove(id, deleteFile) }
async function clearFinished(): Promise<void> { ... }
```

事件处理约束：

1. `task-updated` → `tasks.set + order`（新 id 追加），**不**全量刷新；
2. `stats` → 500ms 节流写入 `stats`（`statsTimer` 合并， trailing 触发一次）；
3. `hungry` → 转交 F3 `refillFromEngine(want)`（本 store 只 emit，不直接调随机引擎，保持依赖单向：F3 的联动模块订阅 store 的 hungry 回调）；
4. `halted` → 按 reason toast：manual→info“已停止”；circuit→error“连续 5 次失败已熔断，请检查密钥/网络后重试”；
   io/disk→error 透传 message；同时 `stats.stopped=true`。
5. `listen` 失败（非 Tauri 环境如纯 web 预览）→ 降级轮询 `iqList` 每 3s（`__TAURI__` 缺失时），并在面板顶部 amber 条提示“事件通道不可用，已降级轮询”。

图片缩略图：`filePath` 不能直接 `<img src>`（Tauri 需 `convertFileSrc`），
统一用 `@tauri-apps/api/core` 的 `convertFileSrc(filePath)` 转 URL；转失败/文件缺失显示占位块（prompt 前 60 字）。
`imageUrl` 远程 URL **默认不直显**（省带宽、避代理），仅在本地文件缺失且用户点“预览原图”时新窗口打开。

## 3. `ImageQueuePanel.vue` 结构（三段式，`data-testid` 即验收钩子）

```html
<section data-testid="image-queue">
  <div data-testid="iq-runbar"> <!-- 运行条 -->
    <Button data-testid="iq-start" :disabled="running">开始</Button>
    <Button data-testid="iq-stop" :disabled="!running">停止</Button>
    <Button data-testid="iq-enqueue-current">入队当前结果</Button>
    <span data-testid="iq-stats">成功 x · 失败 x · 排队 x · 运行 x/并发n</span>
    <span data-testid="iq-consec" v-if="consecFail>0">连续失败 consecFail/5</span>
  </div>
  <div data-testid="iq-empty" v-if="!order.length">暂无生图任务 — …</div>
  <div data-testid="iq-virtual-scroll" ref="parentRef" v-else> <!-- 虚拟化，参数与 BatchFactory 一致 -->
    <ImageTaskCard v-for="v in virtualItems" :model="tasks.get(order[v.index])" />
  </div>
  <div> <!-- 底部栏 -->
    <Button data-testid="iq-clear-finished">清空已完成</Button>
    <Button data-testid="iq-open-output">打开输出目录</Button> <!-- invoke db_reveal_in_explorer(outputDirResolved) -->
  </div>
</section>
```

- 虚拟化参数照抄 BatchFactory：`estimateSize 110 / overscan 5 / measureElement`；
  任务卡含缩略图时行高动态测量（`measureRow` 同名复用）。
- 运行条并发指示：`运行 x/并发n` 的 n 取生效配置（`stats` 不带 n，面板用 `config.concurrency`）。
- `iq-enqueue-current`：把 `useBatchStore().results` 全部转 `{prompt: finalPrompt, irHash: hash}` 入队（F3 §2 同一函数，按钮是手动入口）。

## 4. `ImageTaskCard.vue`（对标 BatchCard，卡片行为逐项）

- 首行：状态 Badge（queued 灰 / running 蓝闪 / succeeded 绿 / failed 红 / cancelled 黄）+ `size·ratio` + 耗时；
- 缩略图（succeeded 且有 filePath）：64px 左缩略，点开展示大图弹层（复用 `PromptPreviewDialog` 模式，新建 `ImagePreviewDialog` 或直接 opener 打开文件——一期选后者，零新依赖，点击缩略图即 `reveal/open` 文件）；
- prompt 区：前 60 字 + 展开；复制按钮（clipboard + textarea 兜底，与 BatchCard 同代码）；
- 失败态：红字 error（已脱敏，后端保证）+ `iq-retry-{id}` 重试按钮；
- 删除：`iq-remove-{id}`；running 态禁用并 title“运行中不可删，请先停止”；
- `data-testid` 规范：`image-task-{id}`、`image-task-retry-{id}`、`image-task-remove-{id}`、`image-task-copy-{id}`。

## 5. 空 / 错 / 满 / 边界态矩阵

| 状态 | 表现 |
|---|---|
| 空队列 | `iq-empty` 文案 + “去批量工厂随机”快捷按钮（切 Tab，见 F3 §4） |
| 后端未配置 key | 运行条下 amber 条“未设置 API 密钥”+ 跳转配置按钮；`start` 直接拦截 toast，不发 invoke |
| 队列满（2000） | enqueue 返回 Err 时红 toast“队列已满，请先清空已完成” |
| 事件降级（web 预览） | 顶部 amber 条 + 3s 轮询 |
| 图片文件被用户手动删除 | 缩略图占位 + “文件缺失” Badge + 保留重试（按 task 重下：`iq_retry` 语义覆盖重下载） |
