# F3 前端施工：随机联动与无限循环（`09`）

> 本篇是“循环生成 / 点击随机后循环”双开关的唯一语义实现位。
> 联动方向：批量工厂（生产 prompt）→ 生图队列（消费 prompt）；饥饿补货反向调用引擎。
> 依赖：`stores/batch`、`stores/assembly`、`stores/library`、`stores/imageQueue`（F1/F2）。

## 1. 语义定稿（双开关真值表，代码与文档必须一致）

| loopEnabled | loopAfterRandom | 点击随机行为 | hungry 补货 |
|---|---|---|---|
| false | false | 仅产 prompt，不入队 | 无 |
| false | true（UI 禁止此态） | 开关 disabled，前端强制先开 loop | 无 |
| true | false | 仅产 prompt，不入队（手动点入队才进队列） | 有（队列见底且运行中） |
| true | true | 产 prompt → **整批入队** → 若未运行则 `start` | 有 |

- `loopAfterRandom` 为 true 要求 `loopEnabled` 为 true：F1 表单 disabled + B1 后端钳制，双保险。
- “循环”的生产者只有两个：① 点击随机的整批入队；② hungry 事件的按需 1 条补货。**后端不直接生产 prompt**（Rust/TS 边界干净，见 B2 §2.1）。

## 2. `BatchFactory.vue` 改动（精确到函数，逐行施工）

### 2.1 `onRandom` 尾部追加联动（现有流程不动，在 `await nextTick()` 之前插入）

```ts
async function onRandom(): Promise<void> {
  ...现有：ensureFresh → generate/generatePartial → toast → nextTick...
  await tryLoopAfterRandom() // 新增，失败只 toast，不抛（不污染随机主链路）
}

async function tryLoopAfterRandom(): Promise<void> {
  const iq = useImageQueueStore()
  if (!iq.config.loopEnabled || !iq.config.loopAfterRandom) return
  if (batch.results.length === 0) return
  if (iq.config.apiKeyState === 'unset' && !iq.config.apiKey) {
    push('已生成 prompt，但未设置生图密钥，未入队', 'warning')
    return
  }
  const items = batch.results.map(r => ({ prompt: r.finalPrompt, irHash: r.hash }))
  const { enqueued, skipped } = await iq.enqueueBatch(items) // 分批，每批100
  if (!iq.isRunning()) await iq.start()
  push(`已入队 ${enqueued} 条${skipped ? `（跳过重复 ${skipped}）` : ''}，循环生图中`, 'success', 1600)
}
```

约束：

1. `try/catch` 包裹全函数，catch 中 `push('自动入队失败：'+msg, 'error')`，绝不 throw；
2. 可控随机（partial）同样联动，`irHash` 照带；
3. `count` 上限 500（现有 clamp）与 B2 队列上限 2000 配合：`enqueueBatch` 内分批，
   遇“队列满”即停并 toast 剩余条数。

## 3. 饥饿补货 `refillFromEngine(want: number)`（F2 收到 hungry 后调此函数）

归属：`src/lib/imageLoop.ts` 新增（不进 store，保持 store 瘦）：

```ts
export async function refillFromEngine(want: number): Promise<{ enqueued: number; skipped: number }> {
  const iq = useImageQueueStore()
  const library = useLibraryStore()
  const assembly = useAssemblyStore()
  const batch = useBatchStore()
  // 前置：双开关仍开、运行中、want>0，否则直接返回 {0,0}
  // 1. 若 library 为空 → fetchAll 一次；仍空则返回（toast 节流：10s 内只提示一次“词库为空”）
  // 2. 用当前锁/锚按 BatchFactory 同规则取 1 条：
  //    usePartial && selectedItems.length ? partialRandomAssembly(ancored, 1) : randomAssembly(lockedIds, 1)
  //    （直接调 engine 函数，不经过 batch store 的 results，避免冲掉用户当前批量结果！）
  // 3. 去重：hash/window 由引擎内部处理；队列侧 B2 再按 irHash 撞键跳过
  // 4. adaptToModel(assembly.config) 得 finalPrompt → iq.enqueueBatch([{prompt, irHash}])
  // 5. want>1 时循环 want 次（每次 1 条，保证去重窗口逐步生效），上限 min(want, 并发数)
}
```

硬性规则：

1. 补货**永不写 `batch.results`**（用户批量结果是手动资产，循环补货是后台行为）；
2. 补货失败（词库空/引擎异常）静默记日志 + 节流 toast，不弹 error 轰炸；
3. `want` 钳制 `1..=concurrency`，防止后端误发大数；
4. 页面卸载/组件 unmount 时补货中的 promise 置 cancel 标记，完成后丢弃结果（不入队），防内存泄漏与“关了还在跑”。

## 5. 停止 / 续跑 / 熔断的前端配合

| 场景 | 前端行为 |
|---|---|
| 用户点停止 | `iq.stop()` → 运行条 stopped 态；queued 保留；toast info“已停止，可续跑”；开始按钮文案变“继续” |
| 续跑 | 点开始 → `iq.start()`（后端 generation+1，queued 继续）；若队列空且 loop 开 → hungry 立即补货 |
| 熔断 halted(circuit) | 红 toast + 运行条红 Badge“熔断停止”+ 自动切到队列 Tab 定位首个 failed 卡 |
| 输出目录被删/不可写 | halted(io/disk) 透传 message；配置面板输出路径红框 |
| 关闭窗口时仍在跑 | `onBeforeUnmount` 不 stop（任务在后端继续，符合“队列”心智）；下次打开 `initQueue` 回填继续看 |

## 6. 联调剧本（手工验收脚本，按序执行）

1. 配好 key，loop 全关 → 随机 5 条 → 断言队列为空（无联动）。
2. 开 loop（不开联动）→ 点“入队当前结果”→ 点开始 → 等 2 张成功 → 点停止 → 断言 queued 保留，点开始续跑。
3. 开联动 → 随机 5 条 → 断言自动入队 5 条且运行中 → 等 hungry 补货（看 stats.running 持续 >0 且总数增长）。
4. 填错 key → 联动随机 → 首个任务失败 → 连败 5 次熔断 toast。
5. 并发改 1→4（运行中热改）→ 观察 running 峰值变化。
