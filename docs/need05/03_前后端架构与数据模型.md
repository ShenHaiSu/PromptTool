# 03 前后端架构与数据模型设计

> 约束现状：前端 Vue3 + Pinia + Tailwind；后端 Tauri2 + Rust（`serde/serde_json/rusqlite/uuid/chrono/csv`，
> **无 HTTP 客户端**，需新增 `reqwest` + `tokio`）；落盘有 `export.rs: normalize_export_dir` 可复用；
> 当前工程**无任何生图/代理代码**，本模块为全新垂直切片。

## 1. 总体架构

```text
批量工厂(随机引擎) ──prompt──▶ useImageQueueStore ──invoke──▶ Rust image_queue
        │                              │                        ├─ 请求 builder(agnes.rs)
        │                              │                        ├─ 并发调度(tokio::Semaphore)
        │                              │                        ├─ 下载+落盘(images.rs)
        │                              └◀──tauri event──────────┘   └─ 配置/密钥(config.rs)
```

- **前端只做配置 + 队列视图 + 事件订阅**；所有网络、并发、落盘、重试都在 Rust 端。
  理由：Agnes 单次 11s 级、超时 300s，Rust 超时/代理/并发语义远比浏览器 fetch 可靠；
  且 Key 不必进渲染进程内存以外的长期存储。
- 随机 prompt 生产仍走现有 `randomAssembly / partialRandomAssembly`（含去重窗口与禁忌），
  生图模块**只消费 `finalPrompt`**，不复制随机逻辑；循环补货由前端按“饥饿信号”调用引擎取 1 条后 `enqueue`。

## 2. Rust 后端（`src-tauri/src/commands/image_queue.rs`，新增）

- 依赖新增：`reqwest = { version = "0.12", features = ["json", "rustls-tls"] }`，
  `tokio = { version = "1", features = ["full"] }`，`futures = "0.3"`；
  异步命令使用 Tauri2 原生 `async` command 支持。
- 状态：`ImageQueueState { config: RwLock<ImageQueueConfig>, client: RwLock<Client指纹缓存>,
  semaphore: RwLock<Arc<Semaphore>>, tasks: RwLock<HashMap<TaskId, ImageTask>>, cancel: RwLock<HashMap<TaskId, CancelToken>> }`，
  通过 `app.manage()` 注入。
- 命令清单：
  - `iq_set_config(cfg)` / `iq_get_config()`（Key 只进内存；`remember=true` 才写 secrets 文件）
  - `iq_test_connection()`——发最小文生图（`1K/1:1/response_format=url`，prompt 固定探针句）或 `GET` 健康检查，返回延迟
  - `iq_enqueue(prompts: Vec<EnqueueItem>) -> Vec<TaskId>`
  - `iq_start()` / `iq_stop()` / `iq_retry(task_id)` / `iq_remove(task_id)` / `iq_clear_finished()`
  - `iq_list(limit, status?) -> Vec<ImageTaskView>`（队列视图分页拉取，事件做增量）
- 请求 builder（`providers/agnes.rs`，`ImageProvider` trait，`protocol` select 即此处分发）：
  ```rust
  // 必须遵守 01 §4：response_format 只进 extra_body；图生图只用 extra_body.image
  { "model": "agnes-image-2.5-flash", "prompt": p, "size": s, "ratio": r,
    "extra_body": { "response_format": "url" } }
  ```
  连接超时 15s、全程超时 300s（可配）；400 不重试，仅重试超时/连接失败/5xx（最多 2 次，指数退避）。
- 代理：`client_builder.proxy(Proxy::all(&proxy_url)?)`，开关关闭即重建无代理 client；
  client 按 `(api_base, proxy_on, proxy_url, timeout)` 指纹缓存复用。
- 落盘（`images.rs`）：目录归一复用 `normalize_export_dir` 思想（空→默认 `output/images`，
  相对→相对 data_dir）；文件名 `{yyyyMMdd_HHmmss}_{序号}_{size}_{ratio}_{hash8}.png`，
  同名 `.json` 存 `{prompt, irHash, size, ratio, model, elapsedMs, sourceUrl}`；
  下载失败（URL 404/超时）记失败可重试，不写空文件。

## 3. 数据模型

```ts
// 前端：src/stores/imageQueue.ts（新 Pinia store）
interface ImageQueueConfig { protocol: 'agnes'; loop: boolean; loopAfterRandom: boolean;
  apiBase: string; apiKey: string; outputDir: string;
  size: '1K'|'2K'|'3K'|'4K'; ratio: '1:1'|'3:4'|'4:3'|'16:9'|'9:16'|'2:3'|'3:2'|'21:9';
  concurrency: number; proxyOn: boolean; proxyUrl: string; rememberKey: boolean }
type ImageTaskStatus = 'queued' | 'running' | 'succeeded' | 'failed' | 'cancelled';
interface ImageTaskView { id: string; prompt: string; irHash?: string; size: string; ratio: string;
  status: ImageTaskStatus; filePath?: string; url?: string; elapsedMs?: number;
  error?: string; createdAt: number }
```

```rust
// 后端镜像结构（serde camelCase 对齐前端）
struct ImageQueueConfig { protocol: String, loop_enabled: bool, loop_after_random: bool,
  api_base: String, #[serde(skip_serializing)] api_key: String, output_dir: String,
  size: String, ratio: String, concurrency: u8 /*钳制1..=8*/, proxy_on: bool, proxy_url: String }
```

- 持久化：非敏感配置进 `localStorage`（前端）+ 随应用 data_dir 存 `image_queue.json`（后端为真源，
  启动时下发）；敏感（Key/代理）默认不持久。
- 事件：`image-queue://task-updated`（单任务变更）、`image-queue://hungry`（运行数 < 并发，
  且 loop 开启，前端补货 1 条）、`image-queue://stats`（成功/失败/排队计数，节流 500ms）。

## 4. 并发与循环控制流

- `iq_start`：按 `concurrency` 重建 `Semaphore(1..=8)`；spawn 调度循环：取 queued 任务 → 限信号量 →
  发请求 → 下载落盘 → emit 更新；若无 queued 且 `loop_enabled` → emit `hungry` 等前端补货（后端不直接调随机引擎，
  保持 Rust/TS 边界干净）。
- `iq_stop`：cancel 所有 running（AbortHandle），queued 保留；循环 hungry 暂停。
- 熔断：连续失败计数 ≥ 5 自动 stop 并 toast（计数成功清零；400 计入失败但不重试）。
- 去重：入队前按 `irHash`（有）或 prompt 文本去重，重复提示并跳过。
