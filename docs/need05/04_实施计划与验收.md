# 04 实施计划、风险与验收

## 1. 分阶段实施（每阶段可独立交付验证）

### P0 协议层 + 单张生成（1–2 天）

- 新增 `reqwest/tokio` 依赖；`image_queue.rs` + `agnes.rs` builder；`iq_set/get_config`、
  `iq_test_connection`、`iq_enqueue + iq_start` 单任务链路；落盘 + 同名 json。
- 前端最小面板：11 项配置表单 + 测试连接 + 单条入队。
- 验证：`cargo test`（extra_body 位置断言）+ 手工 1K/1:1 生成落盘。

### P1 队列 + 并发（1–2 天）

- `Semaphore` 并发调度、`hungry/stats/task-updated` 事件、重试/取消/清空已完成、
  并发 1–8 钳制、熔断（连续失败 ≥ 5）。
- 前端队列视图（虚拟化复用 BatchFactory 模式）+ 运行条。
- 验证：并发 3 × 6 任务，观察信号量占用、失败重试、取消生效。

### P2 循环 + 随机联动（1 天）

- `loop / loopAfterRandom` 语义（见 02 §3）；BatchFactory 随机成功后整批入队 + start；
  饥饿补货（每次 1 条，复用去重窗口）；停止/续跑。
- 验证：开双开关后点随机 5 条 → 队列持续补货；点停止即停；续跑不断链。

### P3 打磨（1 天）

- 缩略图画廊、打开文件位置（复用 `db_reveal_in_explorer`）、复制 prompt、失败重试；
  secrets 文件权限、日志脱敏；文档回填 CHANGELOG。

## 2. 风险与对策

| 风险 | 对策 |
|---|---|
| 顶层 `image` 误用（01 §4） | builder 单测断言 `extra_body` 位置；Code Review 必查项 |
| 生成慢（11s+）导致 UI 假死 | 全部异步 + 事件驱动；前端永不 `await` 整批完成 |
| Key 泄露（日志/截图/仓库） | 内存默认 + 脱敏日志 + `.gitignore` secrets；绝不进 docs |
| 代理环境差异（公司网关/Clash/TUN） | client 指纹缓存 + 测试连接先行；一期只保 http/https |
| 无限循环失控（费用/磁盘） | 熔断 + 磁盘水位 + 停止常驻按钮；默认 loop 关闭 |
| 大图（4K）内存/带宽 | 默认流式下载直写文件，不全量进内存；4K 下并发建议 ≤ 2（UI 提示） |

## 4. 范围确认（已关闭，2026-09-22 用户拍板）

1. 一期是否排除图生图 UI（协议层仅预留）？→ **排除**（B1 预留 `unimplemented!`，无 UI）。
2. 「记住密钥」是否接受 obfuscation 级本地存储（非系统钥匙串）？→ **接受，允许记住**，
   实现为 XOR+base64 混淆文件（B1 §4.3），注释如实写明强度，二期可换系统钥匙串。
3. 输出目录默认跟随应用 data_dir 还是跟随用户图片库？→ **默认 dataDir，用户可指定并记住**
  （B2 §4.1 + `image_queue.json` 持久化）。
