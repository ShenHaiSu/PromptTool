## 1. 现状（已核实）

- 入口：`src/components/DimensionPanel.vue#573 onDimContextMenu` → 菜单 `#1060 dim-ctx-clear`（空维度 disabled）→ `onClearFromMenu#604` → `openClearConfirm` → 内联确认框 `#1102`（`clearAgreed` 勾选门禁）。
- 执行：`doClearDimension#640-679` 循环：
  `await dbSoftDeleteModule(m.id)`（`src/lib/db.ts#192` → `invoke('db_soft_delete_module')`）× N，每轮还做一次 `modulesByDim = {...g}` + `filter` + 进度 `clearProgress.done=i+1`。
- 后端：`src-tauri/src/commands/db.rs#377 db_soft_delete_module` 仅支持单 `id`（`UPDATE modules SET is_deleted=1 WHERE id=?2`），无批量命令；在 `src-tauri/src/lib.rs#56-67` 注册。迁移有事务命令可仿照（`db_migrate_dimension` + `BEGIN IMMEDIATE/COMMIT`，见 `db.rs#668-762`）。

## 2. 现状 4 个问题

| # | 问题 | 证据 |
|---|------|------|
| P1 | N 次 IPC + N 次 `open_conn`，200 条 ≈ 200 往返，慢且易 `db locked` | `DimensionPanel.vue#653-655` |
| P2 | N 次响应式全量赋值 + `filter`，O(N²）+ N 次重渲染 | `#657-659` |
| P3 | 非原子：“回滚”只恢复了前端 `snapshot`，紧接着 `fetchAll()` 又用后端部分删除真相覆盖，前端“已恢复显示”会被刷掉，文案误导 | `#661-666` |
| P4 | `groupedKey`（`dim.id ?? dim.key`）双键兼容包袱，逐轮搬运易错 | `#644-645` |

> 另：`clearProgress done/total` 的逐条进度条在单命令后不再有意义，转为不确定态即可。

## 3. 方案对比

| 方案 | 说明 | 结论 |
|------|------|------|
| A. 新增 `db_clear_dimension`（推荐） | 单事务 `UPDATE ... WHERE dimension_id=? AND is_deleted=0`，返回 `cleared` | 1 次 IPC、原子、代码最简 |
| B. 前端 `Promise.all` 并发删 | 仍 N 次 IPC，且 SQLite 写锁冲突更大 | 否决 |
| C. 前端分片 + 并发上限 | 复杂度高，仍非原子 | 仅作 A 不可用时的降级 |

### 4.2 TS 封装：`src/lib/db.ts`（`dbMigrateDimension` 旁）

```ts
export type ClearDimensionReport = { cleared: number };
export async function dbClearDimension(args: { dimensionId: string }): Promise<ClearDimensionReport> {
  const r = await invoke<{ cleared: number }>('db_clear_dimension', { dimensionId: args.dimensionId });
  return { cleared: r.cleared };
}
```

注意 `invoke` 键名用 `dimensionId`（camelCase，见 `db.ts#1-7` 踩坑说明）。

### 4.3 Vue：重写 `doClearDimension`（`DimensionPanel.vue#640-679`）

```ts
async function doClearDimension(): Promise<void> {
  const dim = clearTarget.value;
  if (!dim || clearing.value) return;
  const list = [...(modulesByDim.value[dim.id] ?? [])];
  if (list.length === 0) { clearConfirmOpen.value = false; return; }
  clearing.value = true;
  const snapshot = [...list]; // 仅乐观 UI 快照
  // 乐观：一次置空该维度分组（单次赋值，单次渲染）
  // library.modulesByDim = { ...g, [dim.id]: [] };
  try {
    const r = await dbClearDimension({ dimensionId: dim.id });
    // 以服务端 cleared 为准；若与 list.length 不一致，以 fetchAll 为准并 warn
    const ids = new Set(list.map((m) => m.id));
    for (const it of [...assembly.selectedItems])
      if (it.module.dimensionId === dim.id || ids.has(it.module.id)) assembly.removeModule(it.module.id);
    emit(LIBRARY_CHANGED, { source: 'dimension-panel', op: 'clear-dimension' });
    await library.fetchAll();
    push(`已清空维度「${dim.nameCn}」，删除 ${r.cleared} 条` + (linked…), 'success', 2200);
    clearConfirmOpen.value = false;
  } catch (e) {
    // 原子命令失败 = 后端未动：恢复快照 + fetchAll 对齐即可，无“部分删除”
    // library.modulesByDim = { ...g, [groupedKey]: snapshot };
    emit(LIBRARY_CHANGED, { source: 'dimension-panel', op: 'clear-dimension-failed' });
    await library.fetchAll();
    push(`清空失败：${String(e)}，未删除任何条目`, 'error');
    // 对话框保持打开，可重试；clearing=false
  } finally { clearing.value = false; }
}
```

- 删除 `clearProgress.done/total` 逐条更新，按钮改为 `clearing ? '清空中…' : '确认清空（N 条）'`（testid 不变）。
- `groupedKey` 逻辑保留一行兼容即可，不再进循环。
- 可选降级：`catch` 若为 `unknown command` 则回退旧循环（Web/旧后端兼容），默认不做以控制 scope，审阅时定。

## 6. 风险与回滚

- 新命令发版前旧前端调不到 → 本次前后端同仓同发，无版本差；Web 预览走 mock，不受影响。
- `dimension_id` 外键脏数据（`modules.dimension_id` 指向已删维度）→ `read_migrate_src` 校验会拦，错误直显，前端恢复快照即可。
- 回滚：单提交 revert（Rust 注册 + `db.ts` + `DimensionPanel.vue` + 测试同 revert），旧逐条逻辑无残留依赖（`dbSoftDeleteModule` 保留给单条删除用）。
