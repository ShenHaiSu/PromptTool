# Need04 — 随机生成尊重维度顺序权重 · 目录与总览

> **需求**：随机生成（批量工厂 `随机` / `可控随机`）与画布拼装的最终提示词段顺序，必须尊重每个维度的 `Dimension.sortOrder`；新建维度可插队到任意位置，不再永远沉底。
> **一句话方案**：废弃 `assembly.ts DIM_ORDER` 硬编码的主排序地位、降级为兜底；`DB sortOrder` 为唯一真相源；`library.dimOrderMap` 唯一建图；`random` 内部自建、`assembly` 跨 store 自取，组件层零改动。

- **输出路径**：`docs/need04/`（本目录）
- **版本**：v1.0 — 2026-09-21

## 二、术语

| 术语 | 含义 |
|------|------|
| **维度 / Dimension** | `dimensions` 表的一行，`key` 为机器键，`sortOrder` 为顺序权重（数字越小越靠前） |
| **顺序权重** | 即 `Dimension.sortOrder`，`dbGetDimensions` 已按它升序返回 |
| **`DIM_ORDER`** | `src/engine/assembly.ts` 内 14 维硬编码映射（`gender:0 … camera:13`），本需求后降级为兜底 |
| **`dimOrderMap`** | `Record<dimensionKey, sortOrder>`，由 `library.dimensions` 派生，排序的唯一运行时输入 |
| **随机链路** | `BatchFactory → batch.generate/generatePartial → randomAssembly/partialRandomAssembly → assemble` |
| **画布链路** | `DimensionPanel/BatchCard/useDragSort/HistoryPanel → assembly.set* → reassemble → assemble` |
| **透传式（已否决）** | 每个组件手算 `map` 并逐层传入；本方案否决，见 02 §3 |
| **自取式（本方案）** | `random` 内部自建、`assembly` 跨 store 自取，组件零改 |

---

## 三、方案一句话

`library` 新增 `computed dimOrderMap`；`random` 用 `buildDimOrderMap(dimensions)` 现算现传；`assembly.reassemble` 跨 `store` 读 `library.dimOrderMap`；`sortByOrder` 按 `map > DIM_ORDER > MAX_SAFE_INTEGER` 三级排序；`seed` 与 DB 不动，无迁移。
