# Need04-01 — 现状诊断与问题分析

## 一、现象（用户原话）

1. 随机生成时是否尊重了每个维度的顺序权重？
2. 是不是新建的维度永远都排在最后面？

## 二、证据链（全部可复现）

### 2.1 入口拿的是有序数组

`src/components/BatchFactory.vue:62-82 onRandom`：

```ts
const dims = library.dimensions // 来自 dbGetDimensions，已有序
batch.generate(dims, grouped, lockedIds, count.value, cfg, allowNsfw.value)
```

`src/lib/db.dimensions.ts:7-13`：

```ts
export async function dbGetDimensions(): Promise<Dimension[]> {
  const rows = await tx(db, 'dimensions', 'readonly', (s) => getAll<DimRow>(s['dimensions']!))
  return rows
    .filter((d) => d.isDeleted === 0)
    .sort((a, b) => a.sortOrder - b.sortOrder) // ← DB 层已按 sortOrder 升序
    .map(rowToDimension)
}
```

`src/stores/library.ts:29-35 fetchAll` 原样透传 `dimensions.value = dims`，顺序保持。

### 2.3 重排走硬编码，与 DB 无关

`src/engine/assembly.ts:61-87`：

```ts
const DIM_ORDER: Record<string, number> = {
  gender: 0, ethnicity: 1, height: 2, body: 3, face: 4,
  top: 5, bottom: 6, outfit: 7, shoes: 8, accessories: 9,
  pose: 10, props: 11, background: 12, camera: 13,
}
export function sortByOrder(items, mode, dimOrderMap?) {
  if (mode === 'customDragOrder') return [...items]
  // 注释写着“优先读 DB sort_order 映射”，但调用方从不传
  return [...items].sort((a, b) => {
    const oa = dimOrderMap?.[ka] ?? DIM_ORDER[ka] ?? 99 // ← 永远走中间列
    const ob = dimOrderMap?.[kb] ?? DIM_ORDER[kb] ?? 99
    return oa - ob
  })
}
```

全仓搜索 `assemble(` 调用点：`random.ts ×2`、`stores/assembly.ts:16 reassemble` 均未传 `dimOrderMap`。即 `need02` 预留的参数从未被接线。

### 2.4 画布链路同病

`src/stores/assembly.ts:15-19`：

```ts
function reassemble() {
  const { ir: nextIr, finalPrompt: nextFinal } = assemble(selectedItems.value, config.value) // ← 同样缺 map
}
```

`assembly` store 自身不持有 `dimensions`，也没有从 `library` 取数，所以画布拖拽/`DimensionPanel` 改 `sortOrder` 后同样不生效。随机与画布行为一致（都不尊重），这是不幸中的万幸：修一处语义，两处同时正。

## 三、根因一句话

**`assemble` 支持 `dimOrderMap`，但两条生产链路（随机 ×2、画布 ×1）都没传，排序永远回退到 `DIM_ORDER` 硬编码。**

## 四、影响矩阵

| 场景 | 当前行为 | 预期行为 |
|------|----------|----------|
| 内置 14 维改 `sortOrder`（如 `pose` 调到最前） | 随机/画布无视，仍按 `gender→…→camera` | 按新 `sortOrder` 输出 |
| 新建维度（`key` 不在 `DIM_ORDER`） | 一律 `99` 并列沉底 | 按其 `sortOrder` 插队任意位置 |
| 多个新建维度之间 | 靠 `Array.sort` 稳定性保留 `picked` 顺序（即 DB 序），相对有序 | 同左（保持） |
| 越晚新建越靠后？ | 是。`dbCreateDimension` 默认 `sortOrder = max+1`（`db.dimensions.ts:117-141`），`99` 同分组内按输入序排，晚建的 `sortOrder` 大故靠后；即使手动把新建维度改成 `sortOrder=0` 也救不回来 | 按值排序，不再与创建时间绑定 |
| `sortBy='customDragOrder'` | 直接返回输入序，反而“尊重”了 `dimensions` 顺序 | 保持不变 |

## 五、为什么不动 DB / seed

`src/lib/seed-data.ts:35-48` 的 `sortOrder 1..14` 与 `DIM_ORDER 0..13` 是同序（仅 `+1` 偏移），新库天然对齐；老库 14 维即种子值（`seed.ts` 幂等、非空不重写）。`dbGetAllModulesGrouped` 已按 `sortOrder` 分组（`db.dimensions.ts:36-39`）。所以无需迁移，纯前端排序语义问题。
