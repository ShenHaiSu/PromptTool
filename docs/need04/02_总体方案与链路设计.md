# Need04-02 — 总体方案与链路设计

## 一、目标

- 随机生成与画布拼装的段顺序唯一听 `Dimension.sortOrder`。
- 新建维度可插队任意位置；`sortOrder` 越小越靠前，与创建时间解绑。
- 组件层零改动；无 DB 迁移；老单测最小扰动；单 commit 可回滚。

## 二、全链路（改造后）

```
DB dimensions (sortOrder 升序)
  └─ library.fetchAll → dimensions[] ─┬─ computed dimOrderMap ──────┐
                                      │                              │
BatchFactory.onRandom                │                              │
  ├─ batch.generate(dims, ...)       │                              │
  │    └─ randomAssembly(dimensions) │                              │
  │          └─ buildDimOrderMap(dimensions) → assemble(picked, cfg, undefined, map)
  ├─ batch.generatePartial(dims, ...)│                              │
  │    └─ partialRandomAssembly(dimensions) → 同上                   │
  └─ BatchCard 回填画布 ─────────────┼─ assembly.set*(items) ───────┘
                                      └─ reassemble() {
                                           const map = useLibraryStore().dimOrderMap
                                           assemble(selected, config, undefined, map)
                                         }
```

要点：`map` 只在 `reassemble/assemble` 瞬间使用，不缓存、不落盘；`library` 为空时 `map={}` 自动回退兜底。

## 三、关键决策（含否决项）

| # | 决策 | 选择 | 理由 |
|---|------|------|------|
| D1 | 排序口径 | `DB sortOrder` 唯一真相源，`DIM_ORDER` 降级为 fallback（保留常量，不删除） | 新库天然同序（01 §5）；删光则单测/离线/历史缺 `key` 无兜底。彻底删除是 `方案B-原型`，本方案是 `B-改良` |
| D2 | 建图位置 | `library` 新增 `computed dimOrderMap`，唯一建图点 | 消灭多处 `Object.fromEntries` 重复；`computed` 实时，无一致性负担 |
| D3 | 随机链路供给 | `random.ts` 内部 `buildDimOrderMap(dimensions)` 自建 | `dimensions` 本来就是入参，`batch.ts` 与 `BatchFactory` 零改；符合“数据跟函数走” |
| D4 | 画布链路供给 | `assembly` 跨 store 自取（`import { useLibraryStore }`），即 **自取式** | 否决 **透传式**（每个组件手算 `map` 逐层传入）：`setSelected/addModule/…/setConfig` 全要加参，6 处调用方（`DimensionPanel/useDragSort/HistoryPanel/IrConflictEditorDialog/BatchCard/App`）易漏一处，漏了静默错序最难查。Pinia 官方允许跨 store 读，且是单向依赖（`library` 不反向引 `assembly`），无循环 |
| D5 | 函数签名 | `assemble(selected, config, rules?, dimOrderMap?)` 保持不变 | 老单测不破；`random` 处写 `assemble(picked, config, undefined, map)`，丑但兼容。若重构为 `options` 对象则全仓调用点+单测全改，留待后续 |
| D6 | 未知 `key` | `?? Number.MAX_SAFE_INTEGER` 沉底（替代现 `99` 语义，见 03） | 新老未知维度一视同仁沉底；同值靠 `Array.sort` 稳定性保输入序 |

## 四、不做之事

1. 不改 `DB` 表结构、`seed-data.ts`、`seed.ts`、`dbGetDimensions` 排序、不写迁移脚本。
2. 不改 `weightedSample` 权重语义、不改 `applyRules/evaluateRules` 冲突语义、不改 `adaptToModel`。
3. 不改 `customDragOrder` 语义（首行直接返回）。
4. 不引入 `assembly ↔ library` 双向依赖；不做 `map` 持久化；不重排历史快照。

## 五、与 need02/need03 的关系

- `need02` 预留的 `dimOrderMap` 注释（`assembly.ts:80`）本次真正接线，语义不变。
- `ruleTypes.ts:48 dimOrderMap?` 若有规则求值需要顺序，保持直通，不另起口径。
- `need03` 组合器若拼接示例顺序，复用同一 `dimOrderMap`，不另建。
