# Need05-01 — 功能 A：维度排序以 DB `sortOrder` 为唯一真相源

## 一、解决什么问题

`src/engine/assembly.ts` 里硬编码了 14 维顺序表 `DIM_ORDER`（`gender:0 … camera:13`），`sortByOrder` 之前是 `dimOrderMap?.[k] ?? DIM_ORDER[k] ?? 99`：

1. **新建维度永远沉底**：新建维度不在 `DIM_ORDER` 里，只能落到 `99` 桶，与其他未知维度混排，用户调了 `sortOrder` 也枉然；
2. **`99` 会与正常值碰撞**：`sortOrder` 是 `max+1` 持续增长的（见 02 文档），总有一天超过 99；
3. **随机链路根本没传 `map`**：`randomAssembly / partialRandomAssembly` 调 `assemble(picked, config)`，第 4 参 `dimOrderMap` 缺省，等于随机生成永远走硬编码排序。

## 二、实现逻辑（三级回退 + 双链路自取）

核心就一句话（`need04-03` 原话）：**L1 `dimOrderMap`（DB 真相源）> L2 `DIM_ORDER`（兜底）> L3 `MAX_SAFE_INTEGER`（沉底）**。

- `customDragOrder` 模式短路返回输入序（用户拖拽意图高于一切权重），不动。
- 同值之间靠 `Array.prototype.sort` 的稳定性保输入序（即 DB 序），**禁止加第二关键字**（如按 key 字母排）。
- 传参策略是否决“透传式”（每个组件手算 map 往下传），采用“自取式”：
  - 随机链路：`random.ts` 内部用全量 `dimensions` 现算 `buildDimOrderMap(dimensions)`（提循环外），直接传给 `assemble`；
  - 画布链路：`stores/assembly.ts` 的 `reassemble()` 跨 store 读 `useLibraryStore().dimOrderMap`；
  - 组件层（`BatchFactory / DimensionPanel / BatchCard / HistoryPanel`）**零改动**。

## 三、逐文件实现（Tauri 照搬对照表）

已核实 `tauri` 分支 4 个文件均为改造前旧状态，可按下表逐一搬运（行号为 `web-pure HEAD` 侧）：

### 3.1 `src/engine/assembly.ts`（核心语义）

```ts
import type { AssemblyConfig, Dimension, SelectedItem } from './models' // 新增 Dimension 类型导入

export function buildDimOrderMap(dims: Dimension[]): Record<string, number> {
  return Object.fromEntries(dims.map((d) => [d.key, d.sortOrder]))
}

export function sortByOrder(items: SelectedItem[], mode: string, dimOrderMap?: Record<string, number>): SelectedItem[] {
  if (mode === 'customDragOrder') return [...items]
  // need04：L1 dimOrderMap（DB sortOrder 唯一真相源）> L2 legacy DIM_ORDER > L3 沉底
  return [...items].sort((a, b) => {
    const ka = a.module.dimensionKey ?? ''
    const kb = b.module.dimensionKey ?? ''
    const oa = dimOrderMap?.[ka] ?? DIM_ORDER[ka] ?? Number.MAX_SAFE_INTEGER // 旧值 99
    const ob = dimOrderMap?.[kb] ?? DIM_ORDER[kb] ?? Number.MAX_SAFE_INTEGER // 旧值 99
    return oa - ob
  })
}
```

`tauri` 侧注意：`assemble(selected, config, rules?, dimOrderMap?)` 的第 4 参签名在 Tauri 早已存在（need02 留的），**签名不用改**，只改 `sortByOrder` 内部两行 + 新增 `buildDimOrderMap`。`DIM_ORDER` 表保留作 L2 兜底。

### 3.2 `src/engine/random.ts`（随机链路）

两处同构改动（`randomAssembly` + `partialRandomAssembly`），以 `randomAssembly` 为例：

```ts
import { assemble, buildDimOrderMap } from './assembly'
// ...
const dimOrderMap = buildDimOrderMap(dimensions) // 建在 while 循环外，避免每次尝试重建
while (results.length < count && attempts < maxAttempts) {
  // ...picked 逻辑完全不动...
  const { ir } = assemble(picked, config, undefined, dimOrderMap) // 旧：assemble(picked, config)
}
```

要点：用**全量 `dimensions`**（含未抽中/anchor 段所在维度）建图，不能用 `picked` 建图，否则缺键回退 L2/L3。

### 3.3 `src/stores/library.ts`（唯一建图点）

```ts
// need04 D2：唯一建图点，由 dimensions 派生 sortOrder 映射，reassemble 瞬间读取
const dimOrderMap = computed<Record<string, number>>(() =>
  Object.fromEntries(dimensions.value.map((d) => [d.key, d.sortOrder])),
)
// 别忘了在 return 中导出 dimOrderMap
```

### 3.4 `src/stores/assembly.ts`（画布链路）

```ts
import { useLibraryStore } from '@/stores/library'
function reassemble() {
  // need04 D4：跨 store 自取 library.dimOrderMap；library 为空时 map={} 自动回退 DIM_ORDER
  const library = useLibraryStore()
  const { ir: nextIr, finalPrompt: nextFinal } = assemble(
    selectedItems.value, config.value, undefined, library.dimOrderMap,
  )
  ir.value = nextIr
  finalPrompt.value = nextFinal
}
```

`library` 为空（首屏未 `fetchAll`）时 `map={}`，`sortByOrder` 自动回退 L2，与现状行为一致，不会崩。
