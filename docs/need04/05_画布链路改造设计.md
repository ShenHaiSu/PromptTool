## 三、为什么是自取而不是透传

| 方案 | 改动面 | 缺陷 |
|------|--------|------|
| A. 透传式（已否决）：`setSelected(items, map?)` 等全加参，6 处组件每次现算 | `assembly.ts` 7 个方法 + `DimensionPanel/useDragSort/HistoryPanel/IrConflictEditorDialog/BatchCard/App` | 漏传一处即静默错序；样板代码满天飞 |
| B. 自取式（本方案）：`reassemble` 内部读 `library.dimOrderMap` | 1 个函数 | 引入 `assembly → library` 单向依赖 |

依赖分析：`library.ts` 只引 `db` 与 `models`，不引 `assembly`，故无循环。单测中 `createPinia()` 外单独 `useAssemblyStore()` 而未初始化 `library` 时，`useLibraryStore()` 返回空 `dimensions` → `map={}` → 回退 `DIM_ORDER`（03 §1 L2），与现状一致，不炸单测。

## 五、`library.dimOrderMap` 定义（详见 06）

```ts
const dimOrderMap = computed<Record<string, number>>(() =>
  Object.fromEntries(dimensions.value.map((d) => [d.key, d.sortOrder])),
)
```

`computed` 实时派生，无需 `watch` 同步、无需持久化。`reassemble` 每次调用取 `.value`（Pinia setup store 自动解包，模板外需注意，但本处在 `setup` 作用域内直接 `library.dimOrderMap` 即拆包值）。
