## 1. 设计目标与非目标

**目标：**

- 单次点击仅生成 `1~2` 条时，连续多次点击的历史整体**均匀、不短期重复**；
- 每次点击的**锁定预设可不同**（`lockedIds` / `anchoredItems` 变化），随机范围随之变化，均匀策略仍有效；
- **内存 <10KB、单次 <16ms、无后端依赖**，刷新后历史不丢；
- 保留 `module.weight` 的运营偏好语义，均匀是“长期拉平”而非“抹平权重”。

**非目标：**

- 不引入种子（seed）/可复现随机；
- 不改变 `count=N` 的批次内去重语义（保留），仅新增跨次层；
- 首版不做“与上一次至少 K 个维度不同”的强差异约束（可后置为距离过滤）；
- 不改动后端 Rust 与数据库 schema。

---

## 2. 选型结论（前置摘要）

> 详见 `01 §4` 初筛，本需求最终方案为 **改良版方案 3 = 模块级频率衰减（主）+ 作用域分区滑动窗口（辅）**。

| 维度 | 说明 |
|------|------|
| 主策略 | `effectiveWeight = weight / (1 + hits[moduleId] * alpha)`，`hits` 为全局 `Map<moduleId, count>`，模块级，跨锁定生效 |
| 辅策略 | `recentByScope: Map<scopeKey, string[]>` 窗口 `20`，`scopeKey = sorted(lockedIds)+enabledDimsFingerprint+allowNsfw`，命中则重抽，解决短期体感重复 |
| 协同 | 频率衰减负责长期均匀，滑动窗口负责短期不撞车；前者不分区，后者分区 |
| 衰减 | 每 `100` 次生成对全量 `hits *= 0.95`，避免早期模块永久失宠 |
| 成本 | `hits` 条目 `≈ 模块数 ≤1000`，`recentByScope ≤64分区*20hash≈1280` 哈希，序列化后 <30KB，计算仅多一次乘法+Set 查 |

**为何排除 IR 级主策略（历史 Set / 洗牌袋）：** IR 的 `hash` 含全维度组合，`lockedIds` 一变则 hash 空间完全不相交，去重永远不命中；分区存储则分区数指数膨胀，内存与命中率均不可控。

## 3. 功能规则

### 3.1 作用域 `scopeKey`

用于滑动窗口的分区键，频率表不分区。

```
scopeKey = hash(
  lockedIdsSorted.join(',') + '|' +
  enabledDimKeysSorted.join(',') + '|' +
  allowNsfw + '|' +
  generationMode // 'random' | 'partial'
)
```

- `lockedIdsSorted`：`Set<string>` 排序后拼接；`partial` 模式取 `anchoredItems.map(m.id)` 排序
- `enabledDimKeysSorted`：`dimensions.filter(d=>d.isEnabled).map(d=>d.key)` 排序
- `allowNsfw`：`'0'|'1'`
- 实现用 `sort().join('|')` 的字符串本身即可，无需二次哈希；长度 <200 字符

### 3.2 频率衰减（主）

- **数据：** `hits: Record<moduleId, number>`，初始 `0`，每次某 `module` 被抽中 `hits[id]++`
- **计算：** 抽样前 `effectiveWeight = clampWeight(weight) / (1 + (hits[id] ?? 0) * ALPHA)`，`ALPHA=1.0`
- **退化：** 若 `sum(effectiveWeight) <= 0` 则退化为原 `pool[Math.floor(Math.random()*pool.length)]` 均匀兜底（与 `weightedSample` 现有分支一致）
- **衰减：** `totalGenerations % 100 === 0` 时 `for (k in hits) hits[k] *= 0.95`，并对 `<0.01` 的条目删除以控制膨胀
- **作用域：** 全局，不按 `scopeKey` 分区，因此换锁定后未锁定维度的历史惩罚依然有效

### 3.3 滑动窗口（辅）

- **数据：** `recentByScope: Record<scopeKey, string[]>`，每分区队列长度 `≤20`
- **判定：** 生成 `ir.hash()` 后若 `recentByScope[scopeKey].includes(hash)` 则视为撞车，`continue` 重试
- **入队：** 命中成功后 `queue.push(hash); if(queue.length>20) queue.shift()`
- **分区 LRU：** 维护 `scopeAccessOrder: string[]`，新区键入队；当 `Object.keys(recentByScope).length > 64` 淘汰最久未访问分区
- **与频率协同：** 窗口仅做“短期硬去重”，不影响 `hits` 的累加；重抽次数计入 `attempts`

### 3.4 双层协同流程（单次 `randomAssembly` 视角）

```
输入：dimensions, modulesByDim, lockedIds, count, config, allowNsfw, history{ hits, recentByScope }
scopeKey = buildScopeKey(...)
recentWindow = recentByScope[scopeKey] ?? []
seenThisCall = Set() // 保留原批次内去重
attempts = 0; results = []
while results.length < count && attempts < count*15:
  attempts++
  // 1. 按维度抽样，权重用 effectiveWeight
  picked = []
  for dim in dimensions (isEnabled):
    pool = filter(isEnabled, isNsfw分量)
    if lockedInDim: picked += locked; continue
    n = (isMultiSelect ? rand 0/1/2 : 1)
    if n==0 continue
    effectiveWeights = pool.map(m => m.weight / (1 + hits[m.id]*ALPHA))
    sampled = weightedSample(pool, effectiveWeights, n) // 内部仍用 Math.random()*total
    picked += sampled
  if picked.empty continue
  {ir} = assemble(picked, config)
  h = ir.hash()
  // 2. 辅策略：窗口去重
  if recentWindow.includes(h) continue
  // 3. 原策略：批次内去重
  if seenThisCall.has(h) continue
  // 4. 提交
  seenThisCall.add(h); results.push(ir)
  // 5. 更新历史（仅对成功结果）
  for seg in ir.segments: hits[seg.sourceModuleId] = (hits[seg.sourceModuleId]??0)+1
  recentWindow.push(h); trim 20
end
totalGenerations++
if totalGenerations % 100 == 0: decay hits
persist(history)
return results
```

`partialRandomAssembly` 同理，`scopeKey` 含 `anchoredIds`，`gapDimensions` 的抽样同样走 `effectiveWeight`。

### 3.5 持久化

- **Key：** `localStorage['pmf:randomHistory:v1']`
- **值：** `JSON.stringify({ hits, recentByScope, totalGenerations, version: 1 })`
- **写入：** 每次 `generate` / `generatePartial` 成功后（`results.length>0`）写入；失败不写
- **读取：** `batch.ts` / `randomHistory` store 初始化时 `JSON.parse`，异常则丢弃回退为空
- **容量：** `hits ≤1000` 条 + `recent ≤1280` 哈希，JSON <30KB，远低于 `localStorage` 5MB
- **清除：** 浏览器“清除站点数据”即清空，回落为无历史的纯随机；提供 `clearHistory()` 供调试/设置页调用（首版可仅暴露于控制台）

### 3.6 配置常量（集中于 `src/engine/randomHistory.ts`）

| 常量 | 默认 | 说明 |
|------|------|------|
| `ALPHA` | `1.0` | 频率惩罚强度，越大越均匀 |
| `WINDOW_SIZE` | `20` | 每分区窗口长度 |
| `MAX_SCOPES` | `64` | 分区 LRU 上限 |
| `DECAY_EVERY` | `100` | 每 N 次生成衰减一次 |
| `DECAY_FACTOR` | `0.95` | 衰减系数 |
| `MAX_ATTEMPTS_FACTOR` | `15` | `count * factor` 重试上限（原 10 上调） |
| `STORAGE_KEY` | `pmf:randomHistory:v1` | 含版本便于迁移 |
| `HITS_PRUNE_THRESHOLD` | `0.01` | 衰减后小于此值的 hits 删除 |

## 4. 交互与行为表现

### 4.1 用户故事

**US-01（核心）：** 作为使用者，我将“生成数量”设为 `1`，连续点击“随机生成” 20 次，期望 20 条结果中短期无重复、长期各模块出现频次方差显著小于纯随机。

**US-02（锁定可变）：** 我先锁定 `top=白衬衫` 点 5 次，再改锁 `top=黑皮衣` 点 5 次，期望后 5 次的 `bottom/pose` 等未锁定维度的均匀性仍受前 5 次历史影响（不因锁定变化而重置）。

**US-03（画布补齐）：** 我在画布锚定若干模块后点“部分随机”，补齐的维度同样享受历史均匀性。

### 4.2 交互不变点

- `BatchFactory` 的“随机生成”按钮 `data-testid="batch-random-btn"` 文案、位置、loading 态保持不变；
- `AssemblyCanvas` 的 `data-testid="assembly-empty-random"` / `data-testid="assembly-partial-random"` 保持不变；
- 不新增显式 UI 控件；历史状态对用户透明（可选在控制台打印 `hits` 调试）。

### 4.3 状态与反馈

- 生成中 `isGenerating=true` 已有，保持；
- 生成后 `results` 追加/替换行为保持（由调用方决定）；
- 若 `maxAttempts` 耗尽仍未凑齐 `count`（池子过小或窗口过严），返回已得条数，不抛错；`hits/recent` 仅对成功条数更新。

## 5. 边界与异常

| 场景 | 处理 |
|------|------|
| 池子极小（某维度仅 1 模块） | 频率衰减退化为均匀，窗口可能导致重试增多；`maxAttempts*15` 耗尽则返回已得，窗口不扩大 |
| `allowNsfw` 切换 | `scopeKey` 含该位，自动分区，不串扰 |
| 维度启用/禁用切换 | `scopeKey` 含 `enabledDimKeys`，自动分区 |
| `localStorage` 不可用/超限 | `try/catch` 静默降级为内存态，不阻断生成 |
| `hits` 极大（长期使用） | 衰减+剪枝已控制；即便累计 1w 次，`hits` 仍为 `≤模块数` 条目 |
| 多标签页并发 | 以最后写入为准，不做跨 Tab 同步；影响仅为短期窗口的轻微重复，可接受 |

## 6. 与现有能力的协同

- 保留 `randomAssembly` 的批次内 `seen` 去重，与新窗口为“双重去重”；
- 保留 `applyRules` / `filterPoolByAnchor` 的语义过滤，抽样前已过滤 `isEnabled/isNsfw`；
- `library.ensureFreshForRandom()` 仍保证池子新鲜，历史层不感知库大小变化。
