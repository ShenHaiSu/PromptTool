# 01 分段文本格式与分部逻辑方案

> **关联代码：** `src-tauri/resources/schema.sql`（`dimensions`/`modules` 表）· `src/engine/models.ts`（`Dimension`/`Module`/`PromptIR`）· `src/engine/assembly.ts`（`DIM_ORDER`）· `src/lib/db.ts`（`dbGetDimensions`/`dbCreateModule`）· `docs/samplePrompt/**`（14 维 × 28 条样本形态）· `src-tauri/src/commands/db.rs:247-279`（`db_create_module`）· `src-tauri/src/commands/migration.rs`（`data/pmf.db` 路径约束）
> **目标：** 定义一套“标准、可版本化、可校验、可批量”的分段文本格式（主格式为 `pmf-segments` JSON，辅以 tagged 文本兜底），明确分部的归类逻辑（按什么维度切、切几段、切不准怎么办），并给出本地解析与校验方案；格式与逻辑均为 Need03-02 的 LLM 解析与前端导入的契约来源。

## 一、现状分析

### 1.1 用户手头的“整串提示词”长什么样

典型文生图文生图 Prompt 为一句英文逗号串，例：

```
slim waist, long legs, hourglass figure, oval face with natural makeup,
white oversized shirt, high-waisted wide-leg jeans, white sneakers,
gold hoop earrings, standing with hands in pockets, holding coffee cup,
minimalist white studio backdrop, 85mm lens shallow depth of field soft lighting
```

特征：无显式维度标签、逗号分隔、短语粒度不均（有的含 3-4 个子句）、含权重写法（`(xxx:1.3)` / `[xxx]`）与质量词，长度 30-300 词。现有系统 **无** 将此类连续串逆向拆回维度结构的能力；`docs/samplePrompt/` 虽已按维度分文件存放样本，但那是“分好”的结果，不是输入形态。

### 1.2 现有维度与存储形态

| 维度 key | 中文 | 是否多选 | 典型内容 |
|----------|------|----------|----------|
| gender | 性别 | 单选 | a female model |
| ethnicity | 人种 | 单选 | East Asian face |
| height | 身高 | 单选 | 170cm tall |
| body | 身材 | 单选 | slim waist, hourglass figure |
| face | 面部 | 单选 | oval face, natural makeup |
| top | 上装 | 单选 | white oversized shirt |
| bottom | 下装 | 单选 | high-waisted wide-leg jeans |
| outfit | 套装 | 单选 | red bodycon dress（与 top/bottom 互斥） |
| shoes | 鞋袜 | 单选 | white sneakers / barefoot |
| accessories | 配饰 | **多选** | gold hoop earrings, leather bag |
| pose | 姿势 | 单选 | standing with hands in pockets |
| props | 道具 | 单选 | holding coffee cup |
| background | 背景 | 单选 | minimalist white studio |
| camera | 相机 | 单选 | 85mm lens, soft lighting |

- 表结构见 `schema.sql:dimensions` / `modules`，`modules.dimension_id → dimensions.id`，软删除 `is_deleted`，唯一约束 `dimensions.key`。
- `PromptIR.segments: { dimensionKey, text, weight, sourceModuleId }[]` 为拼装中间态，与 `assembly.ts: DIM_ORDER` 排序一致；`adapters.ts` 将 `weight` 转为 SD/MJ/Flux 语法。
- 新增维度（Need02 已支持）必须自动纳入分段体系，**不允许硬编码维度表**。

### 1.3 需要补齐的能力

| 缺口 | 说明 |
|------|------|
| 标准化的“拆后”承载格式 | LLM 输出与前端解析的共同契约，类似 `pmf-library` JSON 之于整库 |
| 分部归类逻辑 | 明确“某短语属于哪个维度”的判定依据与兜底策略（未分配、冲突、细粒度） |
| 本地解析/校验器 | 纯前端、无网络可跑，负责把 LLM 输出转为可入库的 `Segment[]` 并给出可定位的错误 |

## 二、标准化批量分段文本格式设计

### 2.1 设计原则

1. **JSON 为主、tagged 文本为辅**：JSON 机器友好、可严格校验；tagged 文本供 LLM 偶发输出不规范时兜底。
2. **英文内容、中文说明分离**：`contentEn` 为落库原文（英文），中文仅用于 `displayName`/提示词说明，不进入落库片段。
3. **版本化**：文件头 `format` + `formatVersion`，与 `pmf-library` 一致，便于演进。
4. **批量原生**：顶层即支持 `prompts: PromptEntry[]`，单条为 `prompts.length === 1` 的特例，避免单/批量两套格式。
5. **与 DB 解耦**：`dimensionKey` 为业务键（稳定），`dimensionId` 仅作可选冗余；导入时以 `dimensionKey` 为准。

### 2.2 主格式：`pmf-segments` JSON v1

#### 2.2.1 文件结构

```jsonc
{
  "format": "pmf-segments",
  "formatVersion": 1,
  "createdAt": 1756000000,              // unix 秒，LLM 生成时或前端解析时填
  "generator": "llm: gpt-4o | manual",  // 来源标记，导入时原样落 notes 可选
  "source": {
    "note": "批量导入批次备注，可空",
    "rawCount": 2                        // 本次原始 Prompt 条数
  },
  "counts": {
    "prompts": 2,
    "segments": 18,
    "unassigned": 1
  },
  "prompts": [
    {
      "id": "p01",                       // 批次内唯一，LLM 可自拟；缺失时前端补 p01/p02...
      "raw": "slim waist, long legs, ... 85mm lens soft lighting",
      "segments": [
        {
          "dimensionKey": "body",
          "dimensionId": null,           // 可选，缺失不校验
          "contentEn": "slim waist, long legs, hourglass figure",
          "displayName": null,           // 可选，缺失时前端回退为 contentEn 截断
          "weight": 1.0,                 // 可选，默认 1.0，范围 0.5-2.0
          "isNsfw": false,               // 可选，默认 false
          "confidence": 0.92,            // 可选，LLM 自评 0-1，便于人工复核排序
          "notes": null                  // 可选
        },
        {
          "dimensionKey": "face",
          "contentEn": "oval face with natural makeup",
          "weight": 1.0,
          "isNsfw": false
        },
        // ...
        {
          "dimensionKey": "unassigned",  // 见 3.4
          "contentEn": "ultra detailed, 8k",
          "notes": "无法归入现有维度，疑似质量词"
        }
      ]
    },
    {
      "id": "p02",
      "raw": "red bodycon dress, knee-length, ...",
      "segments": [ /* ... */ ]
    }
  ]
}
```

> **单条简化写法（兼容）：** 允许顶层直接为单条 `PromptEntry`（含 `raw` + `segments`）或 `{ raw, segments }` 数组，解析器统一归一为 `prompts[]`。但文档与 LLM 提示词以批量结构为准，避免歧义。

#### 2.2.2 字段约束

| 字段 | 位置 | 类型 | 必填 | 约束 |
|------|------|------|------|------|
| `format` | 顶层 | string | 是 | 必须为 `pmf-segments` |
| `formatVersion` | 顶层 | number | 是 | 当前为 `1`，不支持其他版本 |
| `createdAt` | 顶层 | number | 否 | unix 秒，缺失时前端填当前时间 |
| `generator` | 顶层 | string | 否 | 自由文本 |
| `source.note` | source | string | 否 | 批次备注 |
| `source.rawCount` | source | number | 否 | 仅作一致性校验，不强制 |
| `counts` | 顶层 | object | 否 | 仅作人读/校验，解析时忽略并重算 |
| `prompts` | 顶层 | array | **是** | 长度 1-500，建议单次 ≤100 |
| `prompts[].id` | entry | string | 否 | 批次内唯一，缺失自动补 |
| `prompts[].raw` | entry | string | **是** | 原始整串，1-2000 字符，非空 |
| `prompts[].segments` | entry | array | **是** | 长度 0-N，空表示整条未分配 |
| `segments[].dimensionKey` | segment | string | **是** | 必须为 `dimensions.key` 之一或 `unassigned` |
| `segments[].dimensionId` | segment | string\|null | 否 | 不参与校验，仅作导入辅助 |
| `segments[].contentEn` | segment | string | **是** | 1-500 字符，trim 后非空；英文原文 |
| `segments[].displayName` | segment | string\|null | 否 | 中文短概括，缺失回退为 `contentEn` 截断 20 字 |
| `segments[].weight` | segment | number\|null | 否 | 默认 1.0，范围 0.5-2.0，步进 0.1，超出则 clamp 并告警 |
| `segments[].isNsfw` | segment | boolean | 否 | 默认 false |
| `segments[].confidence` | segment | number\|null | 否 | 0-1，超出忽略 |
| `segments[].notes` | segment | string\|null | 否 | 自由文本，长度 ≤500 |

**校验失败即整 entry 标为“待人工复核”**，不阻塞其他 entry 解析；`counts` 与实际不一致时仅告警，不报错。

#### 2.2.3 辅格式：Tagged Text（兜底）

当 LLM 未返回合法 JSON 时，允许用户粘贴如下形式，解析器同样可识别：

```
[body] slim waist, long legs, hourglass figure
[face] oval face with natural makeup
[top] white oversized shirt
[bottom] high-waisted wide-leg jeans
[shoes] white sneakers
[accessories] gold hoop earrings
[pose] standing with hands in pockets
[props] holding coffee cup
[background] minimalist white studio backdrop
[camera] 85mm lens, shallow depth of field, soft lighting
[unassigned] ultra detailed, 8k
```

规则：
- 行首 `[dimensionKey]` + 空格 + 内容；`dimensionKey` 大小写不敏感，自动归一为小写。
- 支持 `weight` 后缀：`[top] white shirt :1.3` 或 `[top] (white shirt:1.3)`，解析器提取 `weight`。
- 空行与 `#` 注释行忽略；未带标签的行视为延续上一段（合并）。
- 多条 Prompt 之间以 `---` 或空行 + `### Prompt N` 分隔。

> 前端提供“将 tagged 转为 pmf-segments JSON”的一键转换按钮，便于用户在文本与 JSON 间切换。

#### 2.2.4 文件命名与传输

```
pmf-segments-YYYYMMDD-HHmmss.json
pmf-segments-YYYYMMDD-HHmmss.txt   # tagged 文本
```

- 前端通过 `<textarea>` 粘贴或 `<input type=file>` / 拖拽读取 `.json` / `.txt` / `.csv`（csv 仅作原始 prompts 批量输入，不作为分段结果格式）。
- Rust 侧如需落盘，采用 `atomic_write`（先写 `.tmp` 再 `rename`），与 `db_export_library` 一致。

## 三、分部逻辑（归类策略）

### 3.1 维度目录是唯一真源

```
dbGetDimensions() → Dimension[] (按 sortOrder)
       │
       ├─→ 生成 LLM 提示词中的“维度表”（02-§3）
       ├─→ 校验 segments[].dimensionKey 是否合法
       └─→ 前端预览按维度分组/着色
```

- 14 个预置维度见 1.2，自定义维度自动追加到表末（按 `sortOrder`）。
- `isMultiSelect` 影响**校验告警**而非**解析拒绝**：单选维度在同一 `prompt` 内出现多条 `segments` 时，解析器标记 `warning: "单选维度出现多条片段，将按最后一条入库或拆为多模块（多选）"`，由用户在预览区决定保留策略（保留全部/仅保留最后一条）。

### 3.2 切分粒度

| 原则 | 说明 |
|------|------|
| 一短语一段 | 每个 segment 应对一个“可独立复用”的短语，如 `slim waist` 而非整句 `slim waist long legs hourglass figure` 的必要拆分由 LLM 自主决定；但鼓励将同维度连续短语合并为一条（如 body 的三词合并为一条 `contentEn`），减少碎片化 |
| 逗号为天然切点 | 原始串按逗号切为候选短语，再按语义归类到维度 |
| 权重与质量词单列 | `(xxx:1.3)` / `masterpiece, best quality, 8k` 归入 `unassigned` 或 `camera`（若含镜头语义），不强行归入人物维度 |
| 保留原文标点与大小写 | `contentEn` 保留 LLM 输出的原文片段，不做额外规范化（仅 trim） |

### 3.3 维度语义边界（供 LLM 提示词使用）

| 维度 | 归入 | 不归入 |
|------|------|--------|
| gender | 性别表达（female/male/androgynous） | 人种、身材 |
| ethnicity | 人种/族裔/肤色族属 | 性别、妆容 |
| height | 身高数值/高矮描述 | 身材比例（归 body） |
| body | 身材、体型、腿/腰/胸等身体特征 | 服装（归 top/bottom/outfit） |
| face | 脸型、五官、妆容、发型、表情 | 身材、服装 |
| top/bottom/outfit | 上/下装 vs 全身套装（互斥，见 3.4） | 配饰、鞋袜 |
| shoes | 鞋、袜、赤足 | 服装本体 |
| accessories | 饰品、包、帽、眼镜等可多选小件 | 服装、道具 |
| pose | 姿态、站/坐/走、肢体朝向 | 手持物（归 props） |
| props | 手持/交互物、伞/杯/花等 | 姿态本身 |
| background | 场景、地点、环境光 | 相机参数 |
| camera | 镜头、焦段、光圈、灯光、画质词 | 场景内容 |

> 此表将**原文**注入 02-§3 的 LLM 提示词模板，作为“维度表 + 一句话说明 + 1-2 例”的生成来源。

### 3.4 特殊与兜底

| 场景 | 策略 |
|------|------|
| **outfit vs top/bottom 互斥** | 同一 prompt 内若 LLM 同时产出 `outfit` 与 `top`/`bottom`，解析器标记 `warning: "套装与上/下装互斥"`，导入时按 `assembly.ts: R01` 规则：保留 `outfit`，`top`/`bottom` 仅作为独立 modules 入库，不自动剔除（入库与拼装是两层，拼装时才生效） |
| **未分配 `unassigned`** | 无法归入任何维度、或质量词/权重残留，统一归入 `unassigned`，导入时可选：① 忽略 ② 归入 `camera` ③ 提示用户新建维度；默认“忽略并在报告中列出” |
| **NSFW** | `isNsfw` 由 LLM 标记，前端预览以红点标识；若未标记但 `contentEn` 含常见 NSFW 词，解析器可追加 `warning` 提示复核（不自动改值） |
| **weight** | 仅对需要强调的片段填 `weight`（默认 1.0 不填亦可）；`(xxx:1.3)` 形式由 LLM 转为 `weight:1.3`，前端显示 `w1.3` |
| **超长 Prompt** | 单条 `raw` >2000 字符截断并告警；单批次 `prompts` >500 条分批导入（前端分片调用 Rust） |
| **空片段** | `contentEn` 经 trim 为空的段直接丢弃并计入 `warnings` |

## 四、本地解析与校验方案

### 4.1 架构

```
粘贴/文件 → 探测格式（JSON / tagged） → 归一为 RawSegments
                                        │
                                        ├─→ 结构校验（必填/类型/枚举）
                                        ├─→ 业务校验（dimensionKey 存在性、weight 范围、contentEn 长度）
                                        ├─→ 维度一致性校验（DB 维度表联动）
                                        └─→ 产物：ParsedBatch { prompts: ParsedPrompt[], warnings[], errors[] }
```

- 纯前端实现：`src/lib/segmentParse.ts`，无 Rust 依赖，便于即时预览；Rust 侧仅在最终入库时做二次校验（复用同一套规则，避免绕过）。
- 解析为**容错模式**：单条 entry 失败不影响其他 entry；每条 entry 产出 `status: 'ok' | 'needs_review' | 'error'`。

### 4.2 探测与分支

```ts
function detectFormat(text: string): 'json' | 'tagged' | 'unknown' {
  const t = text.trim()
  if (!t) return 'unknown'
  if (t.startsWith('{') || t.startsWith('[')) {
    try { JSON.parse(t); return 'json' } catch {}
  }
  if (/^\s*\[[a-z_]+\]/im.test(t)) return 'tagged'
  // 包含 "format" / "prompts" / "segments" 关键词亦判为 json
  if (/"(format|prompts|segments|dimensionKey)"/.test(t)) return 'json'
  return 'unknown'
}
```

- `json` 分支：`JSON.parse` → 归一化（兼容单条/批量/大小写 key）→ 逐字段校验。
- `tagged` 分支：按行解析 `\[key\]` → 合并续行 → 产出单 `PromptEntry`（`raw` 为原文重组）；多文件多段以 `---` 切分为多 entry。
- `unknown`：返回 `errors: [{ message: "无法识别格式，请粘贴 pmf-segments JSON 或 [dimension] Tagged 文本" }]`。

### 4.3 校验规则（与 2.2.2 对齐）

| 层级 | 规则 | 失败行为 |
|------|------|----------|
| 顶层 | `format === "pmf-segments"` 且 `formatVersion === 1` | `error`，整批拒绝（tagged 分支无此校验） |
| entry | `raw` 非空，长度 1-2000 | 空则 `error`，超长 `warning` 并截断 |
| entry | `segments` 为数组 | 非数组则 `error`，该 entry 置 `error` |
| segment | `dimensionKey` 非空字符串 | 空则 `error` |
| segment | `dimensionKey` 为 DB 已有 key 或 `unassigned` | 未知 key → `warning`（标为待复核，不丢弃） |
| segment | `contentEn` 非空，长度 1-500 | 空则丢弃该 segment 并 `warning` |
| segment | `weight` 若存在则为 number，clamp 至 0.5-2.0 | 超范围 `warning` 并 clamp |
| segment | `isNsfw` 若存在则为 boolean | 非 boolean 则忽略并 `warning` |
| segment | `notes` 若存在长度 ≤500 | 超长截断并 `warning` |

### 4.5 输出类型（TS）

```ts
// src/lib/segmentParse.ts
export type RawSegment = {
  dimensionKey: string; dimensionId?: string | null;
  contentEn: string; displayName?: string | null;
  weight?: number | null; isNsfw?: boolean;
  confidence?: number | null; notes?: string | null;
}
export type RawPromptEntry = {
  id?: string; raw: string; segments: RawSegment[];
}
export type RawBatch = {
  format?: string; formatVersion?: number;
  createdAt?: number; generator?: string;
  source?: { note?: string; rawCount?: number };
  counts?: { prompts?: number; segments?: number; unassigned?: number };
  prompts: RawPromptEntry[];
}

export type ParsedSegment = RawSegment & {
  status: 'ok' | 'warning' | 'error';
  warnings: string[];  // 如 "单选维度多段"、"weight 已 clamp"
}

export type ParsedPrompt = {
  id: string; raw: string;
  segments: ParsedSegment[];
  status: 'ok' | 'needs_review' | 'error';
  warnings: string[]; errors: string[];
  stats: { total: number; unassigned: number; unknownDimension: number };
}

export type ParsedBatch = {
  kind: 'json' | 'tagged';
  prompts: ParsedPrompt[];
  warnings: string[]; errors: string[];  // 顶层
  stats: { prompts: number; segments: number; unassigned: number; errors: number };
}

export function parseSegmentsText(text: string): { batch: RawBatch, kind: 'json'|'tagged'|'unknown', errors: string[] }
export function validateBatch(batch: RawBatch, dimensions: Dimension[]): ParsedBatch
export function parseAndValidate(text: string, dimensions: Dimension[]): ParsedBatch
// 工具
export function toTaggedText(batch: ParsedBatch): string
export function toSegmentsJson(batch: ParsedBatch): string // pretty JSON
```


**LLM 输出（pmf-segments JSON，单 entry）：**

```json
{

  "formatVersion": 1,
  "createdAt": 1756000000,
```

## 五、与入库的衔接

- 解析产物 `ParsedBatch` 直接驱动 02-§5 的导入流程：
  - `status === 'ok'` 的 segments 默认勾选待导入；
  - `status === 'needs_review'` / `unknownDimension` / `unassigned` 默认不勾选，高亮提示人工确认；
  - `weight` / `isNsfw` 随 `db_create_module` 或批量入库命令落库（`modules.weight` / `is_nsfw`）。
- `displayName` 缺失时落库前由前端补为 `contentEn.slice(0,20)`（与 `import_sample_prompts.py` 的 `DISPLAY_NAMES` 兜底一致）。
- 去重键与 `pmf-library` 保持一致：`dimensionKey + contentEn` 精确匹配（`find_module_hit` 逻辑），保证多次导入同一拆解结果幂等。

## 七、测试方案

### 7.1 自动化（vitest）

| 用例 | 验证点 |
|------|--------|
| JSON 单条 roundtrip | 序列化 → `parseAndValidate` → 字段一致、`status === 'ok'` |
| JSON 批量 3 条 | `stats.prompts === 3`，每条 `segments` 正确 |
| tagged 单条 → JSON 转换 | `toSegmentsJson(parseTagged(...))` 可再解析 |
| 兼容：顶层单 entry 无 `prompts` 包裹 | 自动归一为 `prompts:[entry]` |
| 维度校验：未知 key | 标记 `unknownDimension` + `needs_review`，不丢弃 |
| 单选维度多段告警 | 同 entry 内 `accessories` 多段不告警，`body` 多段告警 |
| weight 超范围 | `weight: 3.0` → clamp 2.0 + warning |
| 空 contentEn | 丢弃该 segment，entry 级 warning |
| 非法 JSON | `kind === 'unknown'` + 顶层 error |
| 样本文生串 → 模拟 LLM 输出 | 用 1 条真实样例串 + 手写 segments JSON 回放解析 |

## 八、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| LLM 输出非严格 JSON（多余解释、markdown 包裹） | 高 | 解析失败 | 解析器先做 `extractJsonBlock`（截取首个 `{...}` 块），并支持 tagged 兜底；提示词中强制“只输出 JSON，无其他文字” |
| 自定义维度 key 含特殊字符 | 低 | 校验误判 | 正则放宽为 `^[a-z0-9_]+$` 大小写不敏感，入库前再做 `key` 唯一校验（复用 `db_create_dimension` 错误提示） |
| 单批次过大（>100 条） | 中 | 预览卡顿 | 预览分页（每页 10 条 Prompt），解析本身无虚拟化压力 |
| 权重/NSFW 误标 | 中 | 入库数据不准 | 默认不勾选 `weight !== 1.0` / `isNsfw:true` 的复核提示，需人工确认后再勾选导入 |
