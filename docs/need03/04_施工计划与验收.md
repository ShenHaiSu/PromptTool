## 3. 手工验收步骤

| 步骤 | 操作 | 期望 |
|------|------|------|
| 3.1 | 将生成数量设为 `1`，连续点击 `BatchFactory` 的“随机生成” 20 次 | 20 条结果短期无重复（窗口 20 内 `hash` 不撞），肉眼可见各维度交替出现，非连续 3 次同 `top` |
| 3.2 | 锁定 `top=白衬衫` 后连点 5 次，再改锁 `top=黑皮衣` 连点 5 次 | 后 5 次的 `bottom/pose/background` 等未锁定维度的分布仍受前 5 次惩罚影响（高频模块出现率下降），而非重置为纯随机 |
| 3.3 | 在画布锚定 2 个模块后点“部分随机” 10 次 | 补齐维度同样不短期重复，`shoes:barefoot` / `background:studio` 的语义过滤与历史窗口协同生效 |
| 3.4 | 连续生成累计 100 次（可脚本循环 `batch.generate`）后观察 `localStorage` | `hits` 触发一次衰减（`totalGenerations % 100 == 0`），早期高频 `moduleId` 的 `hits` 值下降，刷新后仍持久 |
| 3.5 | 切换 `allowNsfw` / 启用/禁用某维度后各连点 5 次 | `scopeKey` 自动分区，NSFW/启用维度切换前后的窗口不串扰 |
| 3.6 | 将某维度池子压至 1 个启用模块，连点 10 次 | 不抛错、不卡死，`maxAttempts=15` 耗尽后返回已得条数（可能每条相同，因池子本身无多样性），窗口不导致无限重试 |
| 3.7 | 刷新页面后连点 5 次 | 历史仍生效（`loadHistory` 生存），非回退为纯随机 |
| 3.8 | 控制台执行 `useBatchStore().clearHistory()` 后连点 | 回落为纯随机，短期重复率回升，`localStorage` 对应 key 被清除 |
| 3.9 | `localStorage` 手动填入非法 JSON 后刷新再生成 | `loadHistory` 丢弃非法值回退空历史，生成不报错，`localStorage` 被重写为合法结构 |

## 5. 风险与回退

| 风险 | 缓解 |
|------|------|
| 窗口过严导致 `maxAttempts` 耗尽、返回条数 < `count` | `MAX_ATTEMPTS_FACTOR=15` 已上调；池子极小时允许少于 `count` 返回，不抛错；必要时可对 `count=1` 的场景将窗口临时放宽为 `10` |
| `hits` 长期累积导致某模块永久失宠 | `DECAY_EVERY=100` + `*0.95` + `<0.01` 剪枝，100 次后高频模块权重回升 |
| 分区数膨胀 | `MAX_SCOPES=64` LRU 淘汰，`scopeKey` 长度 <200，常驻 <30KB |
| `localStorage` 不可用/超限（隐私模式） | `try/catch` 静默降级为内存态，不阻断生成；下次可用时自动重建 |
| 多标签页并发写入 | 以最后写入为准，不做跨 Tab 同步；影响仅为窗口的轻微重复，可接受 |
| 权重钳制与频率公式叠加导致有效权重过小 | `effectiveWeight` 先 `clamp 0.1~2.0` 再衰减，`sum<=0` 时走 `weightedSample` 均匀兜底，不会卡死 |

**回退：** 仅新增 1~2 个文件与 `random.ts/batch.ts` 的可选参分支；将 `ALPHA` 设为 `0` 或令 `generate` 不传 `history` 即可一键回退为现行纯随机；`localStorage` 的 `version` 字段保证可丢弃重建，回退后删除 `pmf:randomHistory:v1` 即清理。
