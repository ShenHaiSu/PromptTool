## 3. 两条入库通道的选型

| 通道 | 后端 | 语义 | 结论 |
|------|------|------|------|
| `db_import_segments`（`segment.rs:141-411`） | `pmf-segments` 跨维度分段 | 按 `dimensionKey` 路由多维度，需 `unassigned_strategy`（ignore/to_camera/prompt_new） | **不采用**：本需求是单维度生成，引入跨维度路由与 unassigned 处理是过度设计 |
| `db_batch_create_modules`（`batch.rs:73-281`） | 同维度批量新建 | `dim_id + items[{contentEn, displayName?, weight?, isNsfw?, notes?}]`，`mode skip/overwrite`，批内归一去重 + `find_module_hit` 库内去重，后端 500 条截断 | **采用**：零后端变更，语义正好是「给一个维度批量加新片段」 |

- `find_module_hit`（`db.rs:1416`）：`(a) id 精确命中；(b) 同 dimension_id + content_en 精确匹配取最早`。大小写敏感、无模糊归一——文档与预览文案必须如实传达（「仅精确英文去重」），不得承诺模糊去重。
- 前端批量解析 `src/lib/moduleBatch.ts`：按行一符一义（`ok/empty/duplicate_in_batch/too_long`，`DEFAULT_MAX_LINES=500/MAX_LEN=500`）+ `ModuleBatchDialog.vue` 预览（过滤+分页 50/行）——新预览页的过滤/分页/批量选择交互照抄它与翻译 Step3 的并集（见 03）。

## 4. 示例来源现状

- `docs/samplePrompt/<14维度>/*.txt`：每维度约 28 条英文样例（如 `top/top_01.txt: oversized white shirt, rolled sleeves`），是优质 few-shot 语料，但**仅存在于仓库 docs**，运行时前端不可读（无后端命令暴露、无构建期打包）。
- DB 现有词条：`useLibraryStore.modulesByDim[dim.id]` 是运行时唯一真源，最能代表用户已收录风格。
- **缺口**：没有任何「随机抽示例 + 拼进提示词」的代码（`segmentPrompt.ts` 的 `EXAMPLE_1/2_JSON` 是写死的 pose/顶装两例，与目标维度无关）。

## 5. 痛点与缺口清单

1. **无生成能力**：导入（`SegmentImportDialog`/`ModuleBatchDialog`）与翻译（`DimensionTranslateDialog`）都是「存量加工」，新片段只能逐条手写或外部写好再贴回。
2. **风格不可控**：即使外部用 LLM 生成，也没有「倾向/风格」输入位与维度约束位，LLM 产出维度漂移（如给 `top` 生成连衣裙——应归 `outfit`）与格式漂移（自由文本无法解析）。
3. **示例无代表性**：写死的跨维度 few-shot 无法体现目标维度的已有分布与粒度（如 `camera` 维度的焦段/光圈写法）。
4. **空维度禁用惯性**：翻译菜单空维度禁用是合理的（无物可译），但生成菜单空维度**必须可用**（空维度最需要生成）——测试与禁用逻辑不能照抄。
