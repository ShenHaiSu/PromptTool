# Need03 — 02 总体方案与链路设计

> **结论先行**：整条链路是 Need01 翻译链的「生成镜像」——把「分片聚合翻译」换成「倾向组合生成」，把「回填 `display_name`」换成「批量新建 `modules`」。LLM 始终在应用外部（复制进、粘贴回），应用内不存任何密钥、不调任何网络。

---

## 1. 全链路（5 段，2 段在应用外）

```
维度头右键 → [Dialog ① 倾向+数量+拼接预览 → 复制/下载]
  → （应用外）用户粘贴给任意 LLM → LLM 返回 pmf-fragments 文本
  → [Dialog ② 粘贴 LLM 结果 → 解析]
  → [Dialog ③ 预览勾选 → db_batch_create_modules 入库 → LIBRARY_CHANGED 刷新]
```

与 Need01 的对照：

| 环节 | Need01 翻译 | Need03 生成（本需求） |
|------|-------------|----------------------|
| 菜单入口 | `批量翻译（中文描述）`，空维度禁用 | 新增 `✨ 片段批量生成`，**空维度可用** |
| Step1 | 按 30/50 分片生成 N 片聚合提示词 | 按倾向+数量生成 **1 段**组合提示词（含随机示例） |
| Step2 | 粘贴多片翻译 JSON | 粘贴生成结果（JSON 主 + 纯行 fallback） |
| Step3 | 按 `id` 定点回填 `display_name` | 按 `contentEn` 去重**新建**模块 |
| 后端 | `db_batch_update_display_names(_text)` | `db_batch_create_modules`（复用，不新增） |

## 2. 窗口与分层

- **表现层**：`DimensionPanel.vue`（菜单第 4 项 + Dialog 挂载）→ `DimensionGenerateDialog.vue`（三步）。
- **逻辑层（纯函数，可单测）**：`fragmentGeneratePrompt.ts`（采样+拼接+估算）与 `fragmentGenerateParse.ts`（探测+解析+校验）。二者不依赖 `window`/`invoke`，与 `translationPrompt/translationParse` 同级。
- **桥接层**：`src/lib/db.ts` 已有 `dbBatchCreateModules`（`db.ts:512+`，`invoke('db_batch_create_modules', {dim_id, items, mode, …})`，注意 `dim_id` 下划线风格经 camelCase 转换——以 06 契约为准，施工时对照 `pitfalls`）。
- **数据层**：零变更。`dimensions`/`modules` 表不动，不新增迁移。
- **外部段**：LLM 调用在浏览器/客户端之外完成；对话框提供复制、下载 `.md`、预估 token 三件套，用户自理模型选择。

## 3. 关键决策（5 条，评审重点）

1. **走 `batch` 不走 `segments`**：单维度生成不需要跨维度路由与 `unassigned` 策略；`batch.rs` 的 500 条截断、批内去重、`find_module_hit` 库内去重、双模式报告已够用（§01-3）。
2. **JSON 主格式 + 纯行 fallback**：主格式 `pmf-fragments v1`（`{format, formatVersion, dimensionKey, items:[{contentEn, displayName?}]}`）保证可解析；fallback 接受「一行一条英文」的极简输出（LLM 写不好 JSON 时的逃生舱）。Tagged（`[key] …`）不需要——单维度无 key 路由。
3. **随机示例取自 DB，不取 docs**：`modulesByDim[dim.id]` 随机采样 K 条（默认 5，可调 3–8，带种子显示与换一批按钮）；空维度回退内置 few-shot（pose/top 各 1 例，与翻译模板同源）。`docs/samplePrompt` 仅作为内置 few-shot 的离线语料参考，不打包进运行时。
4. **倾向文本直通 + 包裹 + 限长**：用户倾向（≤500 字）原样放入 `<user_preference>` 块，并附「不得覆盖 Output Format」约束；前端 sanitization 只做去首尾空、压空白、截断、剥离 ```` ``` ```` 围栏，不做语义改写（见 04）。
5. **零 Rust 变更**：所有新逻辑在前端；后端复用 `db_batch_create_modules(/_text)`。若将来需要服务端采样 `docs/samplePrompt`，另立需求，不在本期。

## 4. 非目标与边界

- 不做应用内 LLM 直连（无 API key 管理、无流式、无重试）。
- 不做跨维度一次生成（一次 Dialog 只服务右键所在的维度；多维度需求走 `SegmentImportDialog` 手工拼 raw）。
- 不做 `displayName` 自动翻译（生成时 LLM 可顺手给中文，入库时原样存；缺失则沿用 `contentEn` 前 20 字回退，与 `batch.rs:178` 一致）。
- 不做权重/NSFW 的生成约束（`weight` 默认 1.0，`isNsfw` 默认 false；Dialog 提供统一默认值选择器，作用于整批入库，不进入提示词约束）。
- 单次生成数量上限 50（提示词与解析侧双限），单次入库沿用后端 500 上限。

## 5. 状态与持久化

- Dialog 内状态：`tendency/count/exampleCount/seed/excludeExisting` 持久到 `localStorage`（键见 06），`activeStep` 同样持久（与翻译 `pmf:translate:activeStep` 对称，键为 `pmf:generate:*`）。
- 步骤可跳：Step1 ↔ Step2 ↔ Step3 顶部步骤条可直接切换；Step3 无解析结果时显示空态引导回 Step2。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| LLM 不按 JSON 返回 | fallback 纯行解析 + 解析侧兼容 fence/多余解释/扁平 map（§05 照抄 translationParse 策略） |
| 倾向注入破坏格式（如用户写 "ignore format"） | 包裹标签 + 「倾向不得覆盖格式」约束 + 长度上限；解析失败时 Step3 空态引导重试 |
| 生成与库内重复 | Step1 可选附「已有清单（前 N 条）」要求 LLM 避重 + Step3 前端预标库内重复 + 后端 `skip` 终局去重，三层防线 |
| 模板 fence 自矛盾重蹈 Need01 | 04 模板正文零 fence，约束行单列；单测断言模板不含 ```` ``` ```` |
