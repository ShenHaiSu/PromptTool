## 1 决策背景

### 1.1 为什么必须重构

当前主窗口为 `MainWindow(PanedWindow 32:28:40) = 左选材 | 中已选Listbox | 右(上预览+IR / 下批量+历史)`（见 `src/ui/main_window.py:84-128`, `src/ui/styles.py` 仅 22 行）。

用户实测反馈核心矛盾：

- **中 + 右上 = 48% 版面在重复展示同一份已选结果**：中栏 `Listbox` 手工排条目，右上 `preview_text(height=5)` + `ir_text(height=8)` 又把拼装结果抄一遍。
- **手工占比过高**：`上移/下移/Scale(0.5~2.0)拖拽/锁定/删除` 全挤在中栏，批量与历史被挤到 `Treeview(height=8)` 的半屏小窗。
- **视觉天花板**：`styles.py` 仅 `theme_use("clam") + 3 个字体配置`，色值硬编码散落在 `batch_cards.py/preview_panel.py/history_panel.py`（`#E8F5E9/#FFF2CC/#F8FAFC/#4CAF50` 等），无 Token、无暗色、无圆角阴影，第一眼即“内部工具感”。

> 结论：不动布局只换皮肤，手工占比问题无解；只动布局不换皮肤，观感仍停留在 2015。

### 1.2 为什么选方案B

| 方案 | 形态 | 手工占比 | 批量可视 | 预览常驻 | 改动成本 |
|---|---|---|---|---|---|
| A Sticky条 | 中栏吸顶预览 | 低 | 高 | 是（中栏内） | 1-2 天 |
| **B 顶部通栏** | **顶部 88-120px 全宽预览** | **低** | **最高** | **是（全宽）** | **1 天+1 天** |
| C 抽屉 | 右侧抽屉覆盖 | 最低 | 中 | 否（按需） | 2 天 |
| D Tab | 右侧大 Notebook | 低 | 高 | 否（Tab内） | 1 周 |

**选 B 的三条理由：**

1. **预览最符合心智**：提示词是最终产出物，应像 Figma 顶部工具栏一样全宽常驻，而非藏在右上角小窗。
2. **下部三栏等高，批量获完整高度**：预览抽离后，`左选材 | 中已选画布 | 右批量+历史` 三栏共享 `860-110px ≈ 750px` 高度，批量 Card 流一次可看 50 条无需滚动到底。
3. **改动最小、风险最低**：仅新增 `TopPreviewBar` + 瘦身 `PreviewPanel`，`MainWindow` 从“1 个 Paned”变为“TopBar + Paned”，不引入 `Notebook` Tab 切换的认知负担（D 方案留作 V2.1 可选演进）。

### 1.3 为什么引入 sv-ttk

- `tkinter` 原生 `clam/default/alt` 主题无论怎么调 `Style.configure` 都无法做出圆角、现代阴影、暗色。
- `sv-ttk`（Sun Valley ttk theme）是纯 Python、零编译、单文件主题，`pip install sv-ttk` + 一行 `sv_ttk.set_theme("light")` 即可获得 Win11 风格，且与现有 `ttk` 完全兼容。
- 对 `零依赖交付` 的破坏最小：仅 1 个运行时依赖，可做 `try: import sv_ttk except: fallback to clam` 优雅降级。
- 替代方案对比：`ttkbootstrap` 更重但组件更多、`CustomTkinter` 需重写所有 `ttk` 为 `CTk*`、`PySide6` 需 3-4 周重构 — 均不如 `sv-ttk` 性价比。

## 2 总体目标与原则

### 2.1 目标

- **降低手工占比 60%**：中栏从 `Listbox + 5 按钮 + Scale` 改为 `Chips 画布 + 拖拽 + 点击改权重`，操作路径从 3 步缩为 1 步。
- **消灭中+右上重复**：预览上移至顶部通栏，`IR` 默认折叠，`分隔符/括号/排序` 收进 `… 设置`，中栏专注“选词”。
- **视觉从 40 分到 80 分**：统一 Design Tokens，`sv-ttk` 换肤，一致的圆角/间距/色板，支持明/暗双主题。
- **零破坏存量数据**：DB schema 不动，仅 UI 层重构。

### 2.2 设计原则

1. **预览常驻、配置收敛**：高频看结果，低频改配置。
2. **选材加宽、画布居中、工厂全高**：信息密度向“选”和“批量”倾斜。
3. **Token 驱动**：所有色/字/距走 `styles.py`，禁止面板内硬编码。
4. **渐进增强**：无 `sv-ttk` 时回退 `clam`，功能不受影响。

### 2.3 非目标（本期不做）

- 云同步、多用户、服务端 API。
- MJ/Flux 负面提示词、Token 长度预估（留 P0-03/P1-04）。
- Canvas 虚拟化到 10k+ 条（本期上限 500，分页已够）。
- 拖拽跨维度（仅中栏内排序）。

## 4 术语表

| 术语 | 含义 |
|---|---|
| TopBar / 顶部通栏 | 全宽 88-120px 的预览条，含 prompt 全文、冲突 badge、IR 折叠、操作区 |
| AssemblyCanvas / 已选画布 | 取代 `Listbox` 的中栏 chips 流，支持拖拽、点击改权重、锁定 |
| BatchFactory / 批量工厂 | 右栏上半区，`ScrollableFrame + BatchCard` 流，现获完整高度 |
| AssetLibrary / 资产库 | 右栏下半区，`Notebook{历史/收藏/模板}` |
| Design Tokens | `colors/spacing/radius/typography` 的集中变量 |

## 5 影响面与兼容性

- **影响文件**：`src/ui/main_window.py`（大改）、`src/ui/styles.py`（重写）、`src/ui/preview_panel.py`（瘦身）、`src/ui/assembly_panel.py`（重写为 canvas）、`src/ui/batch_cards.py`（微调）、`src/config.py`（新增窗口 Tokens）、`requirements.txt`（新增 sv-ttk）、`README.md`（更新截图与依赖说明）。
- **不影响**：`src/engine/*`、`src/db/*`、`src/exporter.py`、所有测试（需增量补 UI 测试）。
- **兼容性**：`sv-ttk` 缺失时 `apply_style` 自动回退 `clam`，功能 100% 可用，仅视觉回退。
