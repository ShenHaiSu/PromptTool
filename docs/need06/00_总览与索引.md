> 阅读顺序：`01 → 02/03 → 04 → 05 → 07/06`。`02/03` 为格式嵌入细节，可按需单读。

## 1. 用户决策（已确认，施工中直接执行）

| # | 决策 | 落点 |
|---|---|---|
| 1 | **embed-only**：不再写同名 `.json` sidecar，元数据只进图片文件内部 | `04` §2：`download_and_persist` 删除 sidecar 写盘分支；`iq_remove` 的 sidecar 删除保留作历史兼容（文件不存在则忽略） |
| 2 | PNG/JPG 的 keyword/魔术头统一用 **`PromptTool:Meta`**（PNG `iTXt` keyword）/ **`PMF1\x00`**（JPG `COM` payload 魔术头） | `02` §2、`03` §2 |
| 3 | JPG 超长 JSON **分段接受**：按 `60000` 字节切片，多 `COM` 段 `index/total` 拼回 | `03` §3、`05` §2 |
| 4 | 需要一个**解析入口**：传入图片即可解析出生图参数 | `05`：纯函数 `extract_embedded_meta` + 新命令 `iq_read_image_meta` + 前端 `readImageMeta` |

## 4. 全局硬约束（本系列 Code Review 必查）

1. 文件第 0 字节魔数永不变：PNG `89 50 4E 47 0D 0A 1A 0A`，JPG `FF D8`；
2. 嵌入失败永远回退原图落盘，任务仍成功（不断流）；
3. 零新依赖：CRC32 手写，不给 `Cargo.toml` 加 crate；
4. `meta` 字段与旧 sidecar 字段一致（`prompt/irHash/size/ratio/model/imageUrl/elapsedMs/createdAt/taskId`），JSON 用紧凑 `to_string`；
5. Key/代理明文不进图片：`meta` 只含上述 8 字段。
