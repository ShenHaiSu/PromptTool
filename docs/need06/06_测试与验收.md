# 06 测试与验收

## 1. 后端单测（无 IO，随 `cargo test` 跑）

| 用例 | 断言 |
|---|---|
| `png_embed_keeps_magic` | 嵌入后前 8 字节仍为 PNG 签名；第二块 type=`iTXt` |
| `png_crc_valid` | 对 `type+data` 重算 CRC32，与块尾 `crc` 一致 |
| `png_roundtrip` | `embed_png → extract_embedded_meta` 还原 JSON（含中文 prompt） |
| `png_bad_input_falls_back` | 首块非 `IHDR` / 签名错误 → `Err`（调用方回退原图） |
| `jpg_embed_keeps_soi` | 前 2 字节仍为 `FF D8`；有 `APP0` 的 fixture 中 `APP0` 仍在 `COM` 之前 |
| `jpg_roundtrip_single` | 常规 JSON（< 60KB）单段拼回一致 |
| `jpg_roundtrip_multi` | 构造 `> 60000` 字节 JSON，多段 `index/total` 拼回一致 |
| `jpg_bad_input_falls_back` | 无 SOI / 段长度越界 → `Err` |
| `extract_none_for_plain` | 无嵌入的普通 PNG/JPG → `Ok(None)` |
| `extract_missing_segment` | JPG 缺片（fixture 删一段）→ `Err` 含“分段缺失” |
| `crc32_known_vector` | `"123456789"` → `0xCBF43926`（IEEE 标准向量，锁死手写表正确性） |

fixture：手写最小 PNG（签名+IHDR+IDAT+IEND，约 70 字节）与最小 JPG（SOI+APP0+DQT+SOF0+SOS+EOI 骨架）放 `#[cfg(test)]` 内联字节，不新增测试资源文件。

## 2. 兼容验收（手工，一次性）

- `pngcheck -v` 嵌入 PNG：无 warning/error；
- `magick identify` / `exiftool` 读嵌入 PNG/JPG：正常输出尺寸，无报错；
- Windows 照片查看器 + Chrome `<img>` + 微信/QQ 拖入：正常显示；
- 体积增量 ≈ JSON 大小（`ls` 对比）。

## 3. 回归验收

- `cargo test -p tauri-app --lib image_queue` 全绿；
- 端到端：并发 3×6 任务落盘，抽查图可打开 + `iq_read_image_meta` 读回 `prompt` 一致；
- 旧图（无嵌入）调 `iq_read_image_meta` → `Ok(None)`，前端 toast 正常；
- `iq_remove(deleteFile=true)` 对新图（无 sidecar）不报错；对历史图（有残留 sidecar）仍顺带删除。
